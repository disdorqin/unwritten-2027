# 部署流程合并建议 v1（对 GPT town-preview 流程的增量补丁）

- 出处：A4 第三轮 Y 路部署比对（`laneY-deployment.md` §9 的 M1–M7），A4 第四轮整理成文。
- 定位：**唯一部署路径仍是 GPT 的 town-preview 一套**（`tools/compose.town-preview.yaml` + `tools/Dockerfile.town-preview` + `docs/deployment.md` 首节）。本文档不另立第二套流程，只把 Muse 部署包中经验证更可靠的四个机制（SHA 标签纪律、旧镜像显式保留、`.deployed-sha` 记录、健康检查重试与精确比对、部署 SHA 人工比对步）以增量补丁形式并入，并附 M4–M7 的文件级小修。
- Muse 旧包（`Dockerfile.townsite` 等）按现存文本有 3 处 COPY 缺空格、从未通过 Docker 构建，**停用**，只留历史备份（`docs/交流区/Muse/部署包/`），不得再用于部署。
- 部署目录口径：`/opt/apps/unwritten-2027`（已与服务器交接对齐）。

## 一、合并后的完整命令序列（替换 `docs/deployment.md` 首节命令块）

设钉版完整 SHA 为 `<PIN>`（部署前由验收方给出，40 字符）。全程在服务器 `/opt/apps/unwritten-2027` 执行：

```bash
# 0. 检出钉版 + SHA 门禁（M3）：检出的不是验收版就停，绝不继续
git fetch origin
git checkout <PIN>
test "$(git rev-parse HEAD)" = "<PIN>" || { echo "SHA 门禁失败：检出与钉版不一致，停"; exit 1; }
export TOWN_RELEASE="$(git rev-parse HEAD)"
# TOWN_RELEASE 护栏（M3）：为空或为 local 时 healthz 只证明自洽、证明不了版本，必须停
[ -n "$TOWN_RELEASE" ] && [ "$TOWN_RELEASE" != "local" ] || { echo "TOWN_RELEASE 非法，停"; exit 1; }

# 1. 保留回滚点（M1）：记录当前在跑的镜像 SHA（首次部署无旧镜像时跳过本段）
docker image inspect "unwritten-town-preview:$(cat .deployed-sha 2>/dev/null)" >/dev/null 2>&1 \
  && cp .deployed-sha .deployed-sha.prev || true

# 2. 构建 + 启动（沿用 GPT 原流程：先校验配置，构建后不重构、不拉取）
docker compose -p unwritten-preview -f tools/compose.town-preview.yaml config --quiet
docker compose -p unwritten-preview -f tools/compose.town-preview.yaml build web
docker compose -p unwritten-preview -f tools/compose.town-preview.yaml up -d --no-build --pull never
docker compose -p unwritten-preview -f tools/compose.town-preview.yaml ps

# 3. 健康检查（带重试 + 精确比对）：重试只等服务起来，不掩盖版本错误
curl --fail --retry 10 --retry-all-errors --retry-delay 2 -s https://town.disdorqin.cn/healthz
curl -s https://town.disdorqin.cn/healthz | grep -qx "town-preview $TOWN_RELEASE" \
  || { echo "healthz 与钉版不一致，停（先做第 4 步人工比对再决定回滚）"; exit 1; }

# 4. 人工比对步（不可省）：操作员亲眼核对 healthz 返回的完整 40 字符 SHA
#    与验收方给出的 <PIN> 逐字符一致，并把实测输出原文记入部署回执。
#    返回 "town-preview local" = 构建漏传 TOWN_RELEASE，视为部署失败。

# 5. 落账（M1）：healthz 与人工比对都通过后才写 .deployed-sha
echo "$TOWN_RELEASE" > .deployed-sha
curl --fail -s -o /dev/null https://town.disdorqin.cn/ && echo "首页 200 OK"
```

## 二、回滚命令（完整版，替换 deployment.md 的回滚文字段；M2）

```bash
# 旧 SHA 取自 .deployed-sha.prev（上一次成功部署的记录）
OLD="$(cat .deployed-sha.prev)"
# 先确认旧镜像还在本地——一次 docker image prune 就可能让它消失，缺了就只能重构建旧版
docker image inspect "unwritten-town-preview:$OLD" >/dev/null || { echo "旧镜像不存在，改走重构建旧 SHA 路径"; exit 1; }
export TOWN_RELEASE="$OLD"
docker compose -p unwritten-preview -f tools/compose.town-preview.yaml up -d --no-build --pull never
curl --fail --retry 10 --retry-all-errors --retry-delay 2 -s https://town.disdorqin.cn/healthz | grep -qx "town-preview $OLD"
echo "$OLD" > .deployed-sha
```

要点：镜像按 SHA 打标签（GPT 原方案已有）＋部署前显式 inspect 保留（M1）＋`.deployed-sha`/`.deployed-sha.prev` 双文件落账，三者齐了回滚才不是口头承诺。**不要执行 `docker compose down -v`**（M6）：`-v` 会删掉证书卷，下次部署要重新签发证书。

## 四、部署回执必须包含（给执行部署的一方）

1. 实际部署的完整 SHA（40 字符）；
2. `/healthz` 实测输出原文（须为 `town-preview <完整 SHA>`，且与钉版逐字符一致——人工比对步的记录）；
3. 证书签发状态（新签/复用、有效期）；
4. 回滚点是否就位：`.deployed-sha` 与 `.deployed-sha.prev` 的内容、旧 SHA 镜像 inspect 是否存在；
5. 首页与小镇页面各一次 200 记录。

以上五项缺一，A–H 公网验收不以回执代替实测。
