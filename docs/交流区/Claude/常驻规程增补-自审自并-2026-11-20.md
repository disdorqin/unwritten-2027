## 一、完工 = 自并入主干，没并 = 没完工

领单循环原第 5 步（任务文件标已完工+提交号）之后、领下一件之前，必须先完成自并：

1. **自审三件**：①构建过（本件涉及的构建命令全绿）；②定向测试过；③挂载状态可证——新内容在玩家默认路径里有引用或入口（grep 主干能找到调用点；只建文件没接线的不算数）。
2. **自并**：把本件从自有 lane 并入 `town-blockout-integration`；并完在**合并结果**上再跑一遍构建，绿了才算并成。
3. **登记**：任务文件写明「已并入 integration + 合并提交号 + 挂载状态（已挂载/未挂载）」，队列行改标已完工。然后才许领续单链的下一件。

只落在 lane 上、没进 integration 的件，一律按**在建**计，不许标已完工。

## 二、接合文件例外（不变）

viewer.ts、town-blockout.html、服务端主干等公共大文件，不许在自并里直接改：照旧出公共批补丁 + 认领公共批锁，由持锁窗集中落。场景与系统的新文件本体可随自并直接进主干。

## 三、撞车与红灯

合并冲突、或合并后构建变红：**停**。把原因写进任务文件、报分区窗，不许强推、不许改别人的分支、不许把红着的合并留在主干上。分区窗抽查发现问题可回滚，回滚不算处罚、记账即可。

## 四、分区窗的核查义务

分区窗每小时核 integration 尖端与本区 lane 尖端：哪件标了已完工却查不到合并提交号，按未完工打回并催并；哪条 lane 完工未并超过一轮，记入当轮回执报总控。

## 五、边界

发布（town-release）仍归总控：自并只到 integration 为止，不许任何窗碰发布线。本增补与永不停机、续单链、落盘令并行，互不顶替。
