## 3. 列车网络（外环 + 中央干线，环绕并串联扩容后的整图）

### 3.1 现行系统事实（代码实测，改线必须在此系统内做）

- **导线**：`docs/p0-layout-draft.json` 的 `extension.coasterGuideLine`（33 点，首尾重复闭合），town-railway.ts 以 CatmullRomCurve3（centripetal、闭合）成环，按 ≈1.7 m 步长采样；轨距 gauge 1.66，chunkSize 64（p0-layout-draft）。
- **高程**：采样点高程 = 地形包络（轨面 ≥ 地形 +0.62，近站渐升至 +5.7 口径）+ 最大坡度 0.225 双向钳制 + 站台 railY 钳制；高架段自动出桥墩（pierDetails，隆起 ≥1.5 m 出墩）；站前路下穿预留净空（stationRoad 段轨面 ≥ 地面 +3.05）——**导线本质是高架导轨系统，下穿/跨越有现行机制**。
- **站点**：town-rail-stops.ts 6 站——过山车站/镇站 (478,224)、火车站前站 (477,320)、森林木屋站 (112,420)、湖南岸站 (350,27)、城堡南站 (496,20)、温泉站 (502,144)；各站带 platform halfLength、railY、speed（8.7–11）与接驳 trail。
- **时刻表**：town-rail-timetable.ts——纪元 Date.UTC(2026,0,1)，位置由各客户端以同一墙钟 `sample(now)` 本地算出，**天然全端一致、不走协议同步**；加速度 2.2、最高速 11、停站 12 s；周期 cycleSeconds 随站距与站数自动生成。
- **先例**：B8 城堡站接驳绕冰宫前场（stationTrail 绕 forecourt [460,39,508,53]）——改线绕既有地标有已验做法，照此办理。
- **机制边界（网络化设计的硬约束，代码实测）**：`buildTownRailRoute(grid)` 读的是模块级单例 `guide`（coasterGuideLine 展开 + guideReplacements）与模块级 `platforms` 全表，产出**一条** route（length/points/pointAt/keepClear/stops 按弧长排序）；viewer 侧列车状态是**单个** `phase` 对**一张** timetable 采样，上/下车判定（currentStop、movingRailExit）全部建立在「一列车沿一条闭环按站序循环」之上。系统内**没有**道岔、没有第二列车的冲突/会让逻辑、没有跨线换乘概念。据此裁定拓扑（§3.4 详述）：
  - **采用：单环 + 弦（中央干线并入同一闭环）**——导线仍是一条闭合样条，只是南腿中段改道向北穿入镇心再折回；站点仍是一个按弧长排序的循环序列；时刻表、上/下车、全端一致**零机制改动**，改的只有 guide 点列与 platforms 增补条目。
  - **否决：双环共用广场站**——须把 buildTownRailRoute 参数化（guide/platforms 入参）+ 第二列车实例与第二张 timetable + 共站段两车冲突判定 + keepClear/桥墩构建双路合并，是新机制而非改线；且共站轨道若重叠走行，高程钳制（双 platform 同点 railY 互斥）在现行算法下无解。
  - **否决：八字形（导线在广场自交叉）**——交叉点两遍轨面在现行包络算法下会被算成同一高程（无立交机制），且同一站台以两个弧长距离出现会击穿 timetable 的 arrival 按站 id 检索（legs 按 id 匹配、重复 id 取首遇）。

## 补条（Thomas 2026-11-19 13:40 裁定）：新景建筑功能优先

四景（北岭/镜湖/松林/灯市）新建建筑**以功能为目的，不再以好看为目的**，与老镇精修标准分开执行：

- 每栋新景建筑立项先答「玩家在这里做什么」——无功能答复不许建（纯装饰壳禁建）；功能须是可实走的玩法/服务（租赁、补给、休息回暖、加工、寄存、站点服务、玩法据点等），并在派工单里逐栋登记功能名。
