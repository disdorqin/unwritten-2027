# 时光信箱细化 v1

- 日期：2026-11-18
- 性质：《灵感池-v1》#24「时光信箱」的可直接施工细化；与邮局留言墙（《全镇交互覆盖规划-v1》邮局行、今晚二梯队已批）**同批施工、共用文本存储层**。
- 口径说明：信箱本体设在**邮局**（与灵感池 #24 一致）；覆盖规划第 13 行「纪念馆新区·时光信箱」作为**同一系统的分箱入口**（新区信箱可写信、可查封存状态，开箱读信回邮局主箱），两处共用同一存储层与同一开启时间，不另起一套。

---

## 1. 写信规则

- **入口**：邮局时光信箱（主箱）/ 纪念馆新区分箱，走近按 E（移动端点按）打开 DOM 写信面板（零 WebGL 绘制调用）。
- **收信人**（四选一，单选）：
  1. 跨年夜的朋友——自填称呼；
  2. 镇民——从现有 NPC 名单下拉选（罗大江、苏小满、顾长明、乔麦、柳三弦、钟铁生等在册 NPC）；
  3. 明年的自己；
  4. 小镇（公开信，开箱后挂邮局公开栏，谁都能读）。
- **字段与上限**：
  - 称呼（收信人称谓）：≤ **12 字**，非空；
  - 正文：≤ **200 字**（含标点），非空，输入框实时字数统计；
  - 落款：≤ **8 字**，可空，空缺时默认显示「一位镇民」；
  - 以上限值均为施工常量，写进配置一处，不散落硬编码。
- **封存规则**：
  - 每位玩家封存上限 **5 封**；达上限时提示先撤回一封再写。
  - 点「封存投递」即落锁：播放投递动画 + 落锁声（声音包），信件进入封存列表。
  - 封存后**不可编辑**；开启前可**撤回**（删除）重写，撤回不留痕。
  - 封存后玩家只能看到信封面（收信人 + 封存日期），**正文不可见**——包括写信人自己。
- **NPC 投信**：镇民也会往信箱投信（数量与名单施工时按语料批次定，建议 6 名常驻 NPC 各 1 封）。NPC 信件为版本内置数据常量，**不入 localStorage**；开箱时与玩家信件合并展示，字段以 `fromNpc` 区分。NPC 信件内容归 Muse 语料批次另行供稿，事实纪律照旧（只用已记录事实与已备语料，不虚构）。

## 2. 定时锁

- **开启时间**：**本地时间 2026-12-31 20:00**。实现为常量 `UNLOCK_AT = '2026-12-31T20:00:00'`，按玩家设备本地时区解析，不写死 epoch（避免跨时区玩家被误锁/误开）。
- **未到时间时的交互**：点击信箱/任一封存信，只显示状态面板——「未到开启时间」+ 封存计数 + 倒计时文案（「距开箱还有 X 天 X 小时」）。不开正文、不给任何正文片段或首字提示。
- **到点后的状态**：信箱挂红绸/发亮提示可开启；开启后信箱转为「已开启」常态，信件随时可重读，不再上锁。
- **单机口径（如实标注）**：单机版以设备本地时钟为准，玩家改系统时间提前开箱视为自愿剧透，**不做强校验**，也不因此判作弊；多人版改为服务器时间权威（见第 5 节）。

## 3. 开信仪式（与 P7 跨年仪式的衔接）

- **时序位置建议**：作为 P7 仪式的一个情感段落，放在**广场倒计时/零点烟花之前**（如 20:00 邮局开箱 → 读信 → 众人移步广场接主仪式）。具体时序由 P7 编排统一定，本细化只给衔接点，不抢编排权。
- **开箱环节**：20:00 到点，邮差苏小满在邮局门口主持开箱（NPC 到场走作息/仪式调度）；流程：落锁声 → 箱盖开启 → 信件列表浮现（DOM）。
- **读信**：自愿读，不强制、不计时；读信在邮局内/门口进行，与广场烟花、红包雨等**峰值特效错峰**（读信段落不叠加全镇粒子峰值，守仪式峰值预算）。
- **公开信**：收信人为「小镇」的信件，开箱后自动上邮局公开栏（与留言墙同面展示区，分栏呈现）。
- **仪式后**：信件保留在信箱中，活动后随时可回邮局重读；跨年夜之后新写的信不再封存（信箱转为普通信箱模式，直接可读——此条为建议，P7 编排时可再定）。

## 4. 共用文本存储层（与留言墙共用）

设计原则：一套记录结构、一套校验/过滤/渲染工具层，两个集合键分开存（留言墙有淘汰策略、信件不淘汰，分开存互不影响；任一键数据损坏只回退该集合为空，不连带崩另一边）。

- **键名**：
  - 留言墙：`unwritten.wall.v1` → `{version:1, items:[Message]}`
  - 时光信箱：`unwritten.timebox.v1` → `{version:1, items:[Letter]}`
- **共用基础字段**（Message 与 Letter 同构部分）：

```json
{
  "id": "时间戳ms+随机后缀",
  "kind": "wall | letter",
  "authorType": "player | npc",
  "authorName": "落款/留言者名",
  "body": "正文纯文本",
  "createdAt":  epoch毫秒
}
```

- **Message 专有**：`pinned`（bool，NPC 预置留言置顶且不参与淘汰）。
- **Letter 专有**：

```json
{
  "recipientType": "friend | npc | self | town",
  "recipientName": "称呼",
  "signature": "落款（可空）",
  "sealedAt": epoch毫秒,
  "openedAt": null（开启后写入）,
  "fromNpc": false
}
```

  （NPC 内置信件不入此键，合并展示时在内存里补齐同构字段，`fromNpc:true`、`id` 以 `npc-` 前缀。）
- **容量与淘汰**：留言墙本地上限 200 条，超出按时间淘汰最早的**玩家**留言（`pinned` 与 NPC 留言不淘汰）；信件不淘汰（有 5 封/人封存上限兜底）。
- **版本与迁移**：两键都带 `version` 字段；结构变更走迁移函数逐版升级；解析失败/结构非法时回退为空库并保留原始串备份键（`*.bak`），不向玩家抛错。
- **渲染纪律**：一律纯文本渲染（`textContent`），禁止把用户输入当 HTML 注入。

## 5. 校验（长度 + 敏感词）

- **长度校验**：输入端实时计数 + 提交端复检，双保险。留言墙正文 ≤60 字；信件按第 1 节上限（称呼 12 / 正文 200 / 落款 8）。纯空白、纯标点视为无效内容拦截。
- **敏感词**：本地简表过滤，命中即**拦截提交**并提示「这句话不太合适，换个说法吧」（不静默改字、不部分打码后放行）。词表分类维护：脏话辱骂类、广告引流类、**联系方式模式**（手机号样式、邮箱样式、常见社交账号引流写法——用模式匹配拦截，防玩家把真实联系方式写进公开文本）。
- **防刷**：相同正文重复提交拦截；提交冷却 3 秒。
- **多人版口径（预留标注）**：本地词表只是简表，**多人版必须以服务端复检为权威**，客户端校验仅作体验优化；公开信与留言墙在多人版上线前须过一遍服务端过滤方案再开放。

## 6. 多人预留事件形状

统一形状 `{type, actor, target, payload, t}`（与覆盖规划 1.2 一致）：

```json
{"type":"wall.post",    "actor":"player:local", "target":"postoffice.wall",    "payload":{"messageId":"…","body":"…"}, "t":  epoch毫秒}
{"type":"timebox.seal", "actor":"player:local", "target":"postoffice.timebox", "payload":{"letterId":"…","recipientType":"self","recipientName":"…","body":"…"}, "t": epoch毫秒}
{"type":"timebox.open", "actor":"player:local", "target":"postoffice.timebox", "payload":{"letterId":"…"}, "t": epoch毫秒}
```

多人化迁移点：存储由 localStorage 迁服务器（记录结构不变，直接搬运）；开启时间改服务器时间判定；`actor` 换真实玩家 id；NPC 信件仍为服务端内置数据。

## 7. 本项验收要点（对齐覆盖规划第 4 节六条，另加定时锁专项）

1. 双通道可触发：邮局主箱与新区分箱均可写信、查封存状态；
2. 定时锁边界：本地时间 2026-12-31 **19:59** 点击只显示「未到开启时间」+倒计时；**20:00** 后可开启并读信；开启前信封面不泄露正文任何片段；
3. 封存规则：达 5 封上限拦截；封存后不可编辑、开启前可撤回；撤回后名额释放；
4. 校验：超长、纯空白、敏感词、联系方式模式、重复提交、冷却期内连点，均按第 5 节拦截且有提示；
5. 存档留存：刷新/重进后封存信件、留言墙内容仍在；两键之一人为损坏时另一键不受影响；
6. 性能：写信/读信全程 DOM，本地视角 draws 增量 ≤+5（预期 ≈0），离开邮局地块后零常驻成本；
7. 回归：留言墙与信箱共用工具层改造后，留言墙原有功能（写/看/翻页）回归通过。
