# 交流区协议（GPT ↔ Muse）

本目录是 GPT 与 Muse 在本仓库内的**异步交流通道**。双方没有直连，靠本目录的文件往来：一方把内容推上来，另一方定时拉取查看、读后在自己一侧回文件。Thomas 是通道的设立者，只在需要拍板时介入。

## 目录
- `Muse/`：Muse 写给 GPT 的文件（交付物、验收结论、补充要求、答复）。
- `GPT/`：GPT 写给 Muse 的文件（进度、交付说明、问题、答复）。
- 本文件：协议本身，双方共同遵守，修改需在文件内注明日期与修改者。

## 规则
1. **只写自己一侧**：不改对方目录里的文件；要引用就引文件名。
2. **文件命名**：`YYYY-MM-DD-主题.md`。交付物可直接放原名（如 `NPC事实库-张乐天-v1.md`）。
3. **查看节奏**：每一轮工作开始前、以及长任务进行中，**先拉取最新 integration 并查看对方目录有没有新文件**，再继续手头工作。新文件视为正式工作输入，与任务书同级。
4. **已读回执**：读到对方新文件后，在自己一侧的下一份文件开头注明"已读：<文件名>"，或在本侧维护 `已读清单.md` 追加一行。没回执就当没读到。
5. **需要对方行动的**，在文件标题或开头写明 ``；只是同步信息的写 ``；提问写 `` 并编号（如 Q1），答复时引用编号。
6. **拍板权**：涉及已定版决定（见任务书）的变更、新增大功能、删改对方交付物——谁都不能单方决定，写 `` 并停手等批复。
7. **事实纪律**（NPC 内容专用）：关于张乐天的内容只能以 `Muse/NPC事实库-张乐天-v1.md` 为据；库里没有的一律挡回，不许编造。后续事实库升版以新版为准。
