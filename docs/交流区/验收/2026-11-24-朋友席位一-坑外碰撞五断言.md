## 三、③ 的机制（本轮定位，属建议性质，未改任何代码）

1. `town-crater-mouth-works.ts` 的 `hitBox()` 把**带旋转的盒退化成世界轴对齐 AABB**：`hx=(sx|cos yaw|+sz|sin yaw|)/2`。
2. 补给站台基是 7.9×6.1 @ 60°，退化后约 **9.2×9.9**，北缘 = 120.914 + 4.95 = **125.86**，跨过门线 123.34 达 2.5 m。
3. 台基顶面 g+0.75 高于 `stepHeight=0.43`，`supportAt()` 不会把脚抬上去，`obstructed()` 又对 `floors` 也生效 → 玩家在地面被台基"地板"挡住。
4. 唯一的坡道 AABB（北缘 124.7、e −85.69…−83.41）**整个落在被台基封死的区域里** → 从外面永远够不到坡道。
5. 结论：**门洞不是没开，是被自己的台基碰撞盒封住了**；室内板（7.4×5.6，北缘 125.5）又叠了一层。

### 最小修复方向（只提建议）

- 首选：`hitBox` 支持真旋转盒（OBB-AABB）相交，或对建筑台基改走"分区盒"。工作量中等，但一次修好所有旋转建筑。
- 次选（局部手术）：台基/室内板在门洞走廊 \|dx\|≤1.4 处切四块留出通道；坡道外延到台基 AABB 之外，并让坡顶在 AABB 边界处已达 g+0.91。
- 兜底：把 0.85 m 直坎改成与门同宽的台阶坡（多段 ramp），使 `supportAt` 在 AABB 边界处就能抬到台基顶。

## 四、快速前往单向性复核

`#jump` 的选项文本是「广场南侧」「山口」「星港坪」「陨石坑口」等；**旧稿写的「广场」是无效值**，`points.get()` 取不到会静默 `return false`（无位移、无提示）。本轮用正确 label 重测：

| 出发点 | 广场南侧 | 山口 | 星港坪 |
|---|---|---|---|
| 门外 (2,159) | (223.0,180.0) ✓ | (290.0,300.0) ✓ | (336.0,640.0) ✓ |
| 坑内 (-26.4,159.7) | (223.0,180.0) ✓ | (290.0,300.0) ✓ | (336.0,640.0) ✓ |

- **双向都正常，上轮"坑域内单向失败"本轮不复现**。判定为旧稿的复现条件问题（无效 label + `#jump` 传送后丢指针锁，导致后续按键失效，看起来像"没反应"）。
- 附带修正：`#jump` 传送后浏览器会丢 pointer lock，所有鼠标转向静默失效，人会觉得"传送后人自己往前跑"。真机上如果遇到同样现象，点一下画面重新锁鼠标即可。
