# BB5 · 赠予与手持展示就绪回执

基线：集成 `ae233311f03333954e2b5d8160a0b650246d1371`，分支 `416d747c09e1dc2b5cfa490d397f5b164fe440da`。可与 BB3/BB4 独立准备手持展示、递出与拒收的状态图，生产接同一权威物品和玩家身份。BB5 行为不限屋内场景，BB4 储物上线无需先于赠予。

**按 BB §5 执行。** 面对面递出经轻确认，接下才完成。拒收、超时或离开后物品仍归原持有人。手持展示不更改所有权，结束还原。还礼须由当前持有人发起一次新赠予。成品只留赠者名一行，矿物食物不留来历。不设交易界面、报价或以物易物入口。矿口镐和绑定收集物禁止转让。R3-43 准本侧按 CD1 与 U 批补遗写作引导，补遗属于世界档，赠予既不写入补遗，也不把它做成背包对象。

**开工顺序。** 定物品能力与展示字段，接现有面对面交互入口。递出时权威核验场域、身份、可转让状态；接下时重验本人身份、归属、容量并原子提交，单次请求只转一次。拒收、超时、离场、断线统一取消待接受动作，不改变所有权。成品来历只写当前这一次的赠者展示名字段。下一次还礼走同一入口，展示与赠予分别用可测状态。超时窗口、相对站位及长按值跟随已批准交互规格，未得来源前无需写死。

**验收证据预备。** 双客户端实际走查「接近 → 展示 → 递出 → 拒绝/重试 → 接下 → 重新当面还礼 → 离开」。记录双方物品计数与身份读回，绑定项和矿口镐成功转移数为零，展示转移零次，重复接受最多一次；另核断线、满格、背身/离场、来历字段及双方插画。覆盖 PC 与移动端交互，并核生产启动与 viewer DOM；对网络消息大小或频率的主张以后按实测回执登记。
