## 90 秒判定与手动禁亮

- 使用已有 `viewer.ts:2764` 动画循环的单调时间和移动结算后的 `x,n,ground`（:2982–2983）。移动阈值按任务书 `<2 m`，时窗达到 `90,000 ms` 才可自动亮。首晚阶段由 N2/N3 宿主提供；已接的 `viewer.ts:1258–1259` 使用 `presence.serverNow` 及演练时钟，供阶段来源对接。埋点应区分真实步行、回前台及换场；切场或重新入镇重建坐标采样，避免跳位被计作步行进度。
- `viewer.ts:2035–2078,2259–2283` 的 E 键和触屏「互动」共用 `interact()`，但 `town-activity.ts:4–12` 的 `TownActivitySpot.run(): void` 无成功回执。当前代码甚至在误按或上车失败时也走这条输入路径。把有效交互信号接在任务宿主实际受理或成功节点（例如对话面板确实打开、上车获准），拒绝、取消和空按不重置计时。有效交互目录以正式验收用例落款为准。自动判定只需读取本地成功时间。
- 自动补救与手动补救用同一条步行光点路。玩家关闭后，记录本时段的自动禁亮；即使再停 90 秒也保持关闭。护照按钮仍允许主动开一次路线，且不解除本时段自动禁亮。时间段 ID 由 N3 宿主供给。自由时段默认熄灯，玩家可从常驻入口主动补救；自动补救适用范围等阶段接口一并钉定。

## 无指针锁定首屏

`tools/voxel-tavern/town-blockout.html:9–21,36–55,98–105` 加载 `viewer.ts`，已有 `#env-banner`、`#help`、`#walk`、`#lock-look`、摇杆与互动键。现役 `viewer.ts:165` 已创建 WebGL，:2223–2224 才用缺 API 或 UA（微信/QQ）显示横幅，现役横幅不足以提供进镇前引导屏；:2104–2113 还在触屏时跳过普通的锁定提示更新。首屏接 YD4 共用入口，置于 3D 显示／入镇之前，避免在 N6 内再造一套页面门。

按 YD4 / MD3，识别内置浏览器后显示短引导、右上角菜单打开外部浏览器、复制链接、可见的重试入口，以及继续进镇的拖拽路径。微信／QQ 与未提供 API 的环境不调用指针锁定，首屏「重试」用于重试入镇或重新检测能力；继续后使用现役 `touch-look.ts`、`touch-walk.ts` 或 `desktop-look.ts:65–85` 相应拖拽实现，保留可关闭提示。只在能力支持的桌面环境使用 `desktop-look.ts:44–59,91–104` 的手势重试及 Promise 拒绝、`pointerlockerror` 路径。注意它的 1,500 ms 静默超时只清 pending，并未发 `onLockFailed`，需与 YD4 对齐失败可见信号，同时保留桌面正常锁定。外部浏览器同进度依赖 YD4／身份宿主，本稿不把本地护照存储当作跨浏览器续接。
