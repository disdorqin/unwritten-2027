# ZA-36 · 山口空气墙硬边界定位（窗 A → 总控裁定，2026-11-21）

窗 A / `town-blockout-lane-a`；基线 `town-blockout-integration@37856174`（复测代码当前至 `e87a3766`）。本件是**真实源码/高度采样诊断**，非浏览器实走完工证据。

## 确定的原因

1. `src/presence/protocol.ts::TOWN_BOUNDS` 经 `town-extension.ts::worldBounds` 传入 `terrain.ts::canEnter`；目前 `worldBounds.depth = 540`。`canEnter(x,n)` 的 `n > depth - 1` 必定返回 false。浏览器 `viewer.ts::outdoorWalkable/tryMove` 直接使用此守卫，所以人在 `N539` 后无法继续北走。**这是正式行走边界，不是单棵树或守卫 NPC 的碰撞**。
2. `src/shared/za22-mountain-domain.ts` 的山域协议原点 `mountainPresenceNorthOrigin = 540`，只收 `N540–800`；`viewer.ts::createZa22CloudRoute.enterOrExit` 只有缆车从山脚登车后抵达顶站/返程才切 `presence.setMountainDomain`。镇侧直接北走没有切域动作。
3. 同一 E/N 的两张地面并未对齐。用现役 `createTerrainGrid().heightAt` 对 `sampleNorthRidge350` 直接取样（米）：

| 坐标 | 镇域地面 | 前山真地形 | 高差 | 镇域可进 |
| --- | ---: | ---: | ---: | --- |
| E290 / N300 | 12.79 | 23.20 | 10.41 | 是 |
| E320 / N520 | 9.68 | 187.90 | 178.22 | 是 |
| E320 / N539 | 7.71 | 209.02 | 201.31 | 是 |
| E320 / N540 | 7.65 | 210.16 | 202.51 | 否 |
| E440 / N540 | 9.65 | 140.12 | 130.47 | 否 |
| E320 / N628 | 7.65（采样钳到边缘） | 347.00 | 339.35 | 否 |

4. 镇侧 `town-front-ridge-proxy.ts` 明确写「**纯视觉壳，不是地形**」：南趾 `N692`、冠位 `N758`，甚至南趾也在现镇 `N540` 边界之外；所以远景已挂不代表有玩家承面。前山老规格入口 `E290/N300` 处即有约 10.41m 台差，无坡道不能用简单单点切换冒充无缝连续步行。

## 必须由总控明确的两选一（ZA-36 原书禁止自行选）

**A. 真正连续步行（扩地图/合地形）**：扩镇域步行与服务端 presence 上限，并在 `E290/N300→山脚→N540` 设计 **可达的坡道剖面/之字路**，使 `grid.heightAt` 与 `sampleNorthRidge350` 平滑衔接。还需同步接缝、道路、地块掩膜、ZB-28 守卫时窗与 ZA-34 高度场；不能把 `TOWN_BOUNDS.depth` 改为 800 就算解决（现截面仍有约 202m 竖直断崖）。这是大改，需主干接合文件单写锁和跨窗联验。

**B. 叙事转场（正式山口/缆车下站）**：镇域脚位一直保留安全可走；在总控指定且真正可达的山口点加一次交互「醒」转场，切入山域的合法 feet 与 presence，不在设计关口之外切域。必须重新确认**入口锚**与**入域落脚/退域**：现在山域仅收 N≥540，旧前山山脚 E290/N300 在协议外；若直接从镇面 N539 传到山域 N540，同点落差约 200m，不是合格的山脚体验。必须配随山脚带观景与连通的实体路线。门禁由 ZB-28 守卫按人/夜窗决定，不能拿隐形墙代替。

**推荐先请总控选 A/B，未裁不得改 `viewer.ts` / `src/presence/protocol.ts` / `terrain.ts` / `town-front-ridge-proxy.ts`。** 坑内装扮与绘制合批不依赖此裁定，已独立在 `ZA-36` 第二步交付。
