# ZA-18 冰晶宫接线

本轮已读 Muse 新文件：《主窗口令-场景内容总表》`44aaf5f`、《任务总表》`d5a5ef2`、《设计-天空之城》`93db6fc8`、《设计-采集与合成》`fff3fd97`、《协作规程-任务认领协议》、任务文件 `ZA-18` 与 `ZB-22`、《任务书-冰宫本体玩法细化》及《任务书-节日与庙会系统元宵》。

## 可取件

场景提交 `b1c7364a` 与 `createIcePalaceRiteAuthority` 组成接线候选。场景西庭拨杆、北侧晶簇采晶、南庭安雪礼有共同的服务端与客户端脚位定义。冻影只作冰中陈设。三个动作从服务器接受的当前地面脚位取身份和位置，请求包含动作和唯一请求号。北庭新增霜封冷却残骸堆和单个拾取目标。宿主提交成功后，活动才显示对应结果。

## 宿主接线

| 接口 | 注入点与负责数据 |
| --- | --- |
| 服务端入口 | `src/presence/server.ts` 的 `createPresenceServer` 选项注入 `IcePalaceRiteAuthorityHost`。WS 与轮询共用 `receiveText`，沿 `summit-passport` 现有连接校验、限速与同一 peer 回执路径调用 `authority.request(peer.id, message)`。加入和重连发送 `authority.snapshot(peer.id)`。 |
| 可信脚位 | 由正式域宿主提供当前地面域已接纳的 `peer.record`。服务端按 presence 厘米单位读取，建筑原点沿用 `icePalaceBuildingOrigin=[484,72,12]`。共享屋、地下、太空档位对应的 peer 在此接口不提供地面脚位。 |
| 引寒与镜湖 | `iceWindow` 端口读全镇已确认冰期，拨杆端口提交权威操作。提交需按请求号去重。获准变更后广播一次同一份 `lake` 快照。客户端把它交给窗 B 的 `mirrorLake.setConfirmedConditions(snapshot.lake)`。窗 B 的冰上夺宝 `isIceOpen` 使用 `authority.isIceOpen`。镜湖现有的重建碰撞接缝跟随 `setConfirmedConditions` 的变化结果。 |
| 采晶 | `forgeInventory` 对接 D `BoosterForgeProfile.iceCrystalShards` 和窗 B 按 ZB-22 报备的同一布包计数。正式宿主提供稳定玩家键与批准的采晶规则。若调用锻造侧事务，保留 `stardustOre`、`boosterOwned`、`fuelSeconds`，记录请求号以安全重试。锻造继续用同一玩家键读并扣耗。 |
| 冬至事件 | `solstice` 端口从全镇节庆事件状态与此玩家参与回执读 `closed/ready/completed`。仅运行服务端确认中的合法冬至事件，提交后回传该玩家的结果。 |
| 玩家界面 | `tools/voxel-tavern/town-blockout/town-presence.ts` 采用 WS/轮询共用状态入口。初始与重连从服务端快照更新。客户端以随机请求号关联结果。从 `viewer.ts` 的 `registerIcePalaceActivities` 把 `rites: { read: () => snapshot.rites, request: submitRite }` 传给 `createIcePalaceLandmarkActivity`。 |
| 船件拾取 | 同一注册器接受 `fragmentPickup: { present, isTargeted, pickUpOne }`。目标 ID 为 `ice-palace-coil-fragment`，目标对象是场景中可射线命中的实际碎片模型。玩家走近再通过统一点按 E 拾一件，通用 ZB-22 背包确认成功后显示一条角落小字。采晶成功使用同一角落提示端口。 |

公共批合入口时统一接线。窗 B `7558f59` 的镜湖场景只消费 `setConfirmedConditions({frozen,showUnderIceGlow})`，夺宝房只消费 `isIceOpen()`，两者尚无冰晶宫冰期来源。窗 D `213a133` 的锻造服务接收并扣耗 `iceCrystalShards`，正式 presence 的玩家资料与物品事务接口尚未挂载。总控场景表明定冬至仪式点，现行节日稿只为冬至定「围」的方向，尚缺安雪礼在线时段、触发与参与回执的正式表。

## 实走目标

从真实出生点 E223/N180，经东南桥 N149、E319/N137、E324/N103、E350/N100、E374/N129、E445/N136、E446/N107、E447/N80 到冰宫西门 E461/N72。随后按正常移动和 E 操作。

| 正式交互脚位 | 取证 |
| --- | --- |
| 引寒机关 E471.00/N73.30/Y12.12 | 按 E 后的服务端响应与拨杆状态，第二个玩家客户端看到相同冰期，镜湖浮冰/碰撞或关闭状态与冰局许可一致。 |
| 采晶柱 E478.05/N77.43/Y12.12 | 捕捉冻影。玩家本人按 E，检查正式库存写入以及同账号重连。有资格的情况下再从锻造读取并按正式配方消费。重复请求只复用同一次回执。 |
| 安雪礼 E485.40/N65.03/Y12.12 | 使用批准的节庆窗口，逐一确认窗外拒绝、窗内 E 行礼、提交后仪式灯与参与回执。 |
| 船件拾取 E484.35/N77.47/Y12.12 | 准星对向地上的 E484.35/N78.47 碎片。点按 E 后查看布包只多一件及角落文字。以背对碎片、重复点按、布包拒绝回执作三项对照。 |

四处脚位均已核算现有西门到宫内的地面支撑和身体净空。完成状态以公共宿主接线、构建和同版起点实走为准。

### 场景验收入口

在安装仓根与 `tools/voxel-tavern` 既有依赖的待验工作树中运行：

```sh
node tools/verify-za22-local.mjs palace /tmp/za18-native-proof
```

现有入口构建并访问正式页面的回环预览。从出生点使用原生鼠标、W/S、Shift 与 E，经西门和 N72 宫内主廊到四处脚位。位置证据同时取画面 HUD 与真实 presence 客户端动作帧，脚高需落在 12.12 m 的 ±0.07 m 内。该档以四点到达、E 后脚位不动、交互未挂起及没有奖励提示为通过条件，产出 `za18-live-walk.json` 和四处截图。真实接线后走上表的正式回执验收。
