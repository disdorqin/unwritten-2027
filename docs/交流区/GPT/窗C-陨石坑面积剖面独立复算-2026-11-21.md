## 复核方法

- 唯一几何事实源：`tools/voxel-tavern/town-blockout/meteor-crater.ts` 的 `meteorCraterFixturePlan`、`createMeteorCrater().terraceHeightOffsetAt(r)`。沿 `r=55,50,46,41,37,32,27,20,0` 的高度线 `0,−7,−7,−16,−16,−26,−26,−35,−35` 复算。
- **解析积分独立于 A 窗**：平面环带 `π(R²−r²)`；折线剖面上每小段表面积 `π(R²−r²) × sqrt(1+(Δh/Δr)²)`；直立井盘 `π(55/30)²`。
- 再通过调用实际 `terraceHeightOffsetAt` 做差分和中点面积积分，逐区对比解析解，误差阈值 0.1%；代码 `tests/town-blockout-crater-area-crosscheck.test.ts`，同仓原有坑体/道路验收同时跑。

## 重要口径界限与实际三角网新增验收

**面积表的 14,128.6528 m² 是环向不变的「正典剖面名义表面积」，不是现役完整三角路面实际面积。** `heightOffsetAt(east,north)` 把绕坡螺旋主步道刻入坑面，和 `terraceHeightOffsetAt(r)` 的裸剖面不同；测试检查 `mainTrailPoint(0.25)` 处的真实道路高度确实有差异。

进一步采用当前 `buildPreviewSurface(55/30)` 的 **Float32 顶点 + Uint32 索引**，对坑沿半径 55m 内、井孔半径 1.833333m 外，以三角片质心半径筛选，逐三角用向量叉积计算 3D 面积，及其水平投影面积。结果如下（本次真实源码的网格复算，并非正式浏览器部署测量）：

| 实际网格复算对象 | 窗 C 测得 | 和原表关系 |
| --- | ---: | --- |
| 入区有效三角片 | **26,426 片** | 现役正典索引网格，已排除坑外片及井孔内片 |
| 三角面水平投影 | **9,492.5056 m²** | 解析坑体平面 9,503.3178 减井孔 10.5592 = 9,492.7585m²；差仅约 0.003% |

**裁定：平面面积及裸剖面积分按 0.1% Gate 通过。若表中“坑体表面积”被解释为实际步道改形后渲染/碰撞面，则该 Gate 未通过。** 使用 `14,484.49m²` 时须附上「现役索引三角片、质心径向裁剪、未加井盖平顶」口径；如果要用作精确铺装账，还应对跨半径边界的三角形裁剪做严谨切片，对新版本网格重算。不得把两种口径混写为同一测量结果。

## 本次验收与处理

- 独立新复算 **6/6**（含 26,426 个路面三角的独立面片面积积分），叠加 B-01 坑体、ZA-22 道路与 A 窗新坑口/工业带组件，在**统一 Three.js ESM 导入**的实际检查环境下共 **23/23 PASS、0 FAIL**；`node tools/run.mjs check` + `node tools/run.mjs build` 通过。Windows 默认 Node 运行器混用 CJS/ESM Three 时，A 窗两个 `instanceof` 测试假阴性（灯光/残骸）会失败；强制同一 ESM 实例重验均通过。未修改 A 窗测试与公共几何。本轮只新增审计测试与交接回执，不冒充浏览器正式部署测量。
- **建议 A 窗按一位小数修订三处剖面表面积，并明确标题「未计螺旋步道改形与 ZA-34 新扩区」**。另一栏独立登记本轮真实索引三角面 **14,484.49m²**，不能拿 14,129.5m² 当实测 3D 料量。真实网格面积的跨边界裁剪误差、以后 ZA-34 扩区新掩膜、动态井盖面积应独立复算。
- 本报告仅提供 C 窗交叉审计意见；正式主井孔、独立矿域 `−90m` 接线与出生点实走仍未闭环，不将坑体面积统计视为地下路线挂载通过。
