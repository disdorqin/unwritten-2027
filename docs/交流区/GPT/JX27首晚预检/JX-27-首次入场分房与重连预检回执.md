## 现役重连复验

固定 `75859a094757c5dcee8b874eef86ec37f4204907`，用 `createPresenceServer` 在本机回环起两种真实传输。WebSocket 第一次进入、同时使用相同昵称进入、关闭第一连接再用相同昵称进入，分别取得 `1 / 2 / 3`。两次同名轮询 join 取得 `4 / 5`、各自不同的 session。回执未保存 session 的值。

浏览器只持久化 `unwritten.presence.name.v1` 昵称。已核对发布源 `town-presence.ts` blob `27ac80e7617be99b332a291f107839641bd523eb`，WS 的 join 发 `{type:'join',name}`，轮询的 join 发 `{name}`。`server.ts` blob `d11570d95a28972fbbc49283c84e35c9e8f08a7e` 为每次连接重新分配 `nextId`，轮询会话断开时从当前表清除。同名双端与重连的原始输出在回归日志。

## 隔离分房候选

- [两文件补丁](jx27-first-night-home.patch) 新增分房分配器及定向测试。单一宿主应在正式认证和入场受理后传入已有稳定主体键。第一次入场取登记名单中第一个空位，同一主体再次入场直接读回原屋。登记达到容量后，多出的访客留空且不改存档。
- 分配先持久化完整记录再对本次返回房屋。保存失败不占位，重建分配器从同一落盘文件恢复。在单一世界权威内使用同步保存适配，候选没有增加网络消息或认证字段。
- 用已对版的 JX-6 现役 52 屋表验证，文件 SHA-256 `b22f7191f46d5ccef91ae606c268ffa26c26b64a38b7d2c5442c508a97e809c5`，旧表 Git blob `df3dec065ae186b190aa5f92a693052267f817e9`。模拟首次入场分配 52/52 唯一，读回 52/52 保持同屋，共 52 次写入。试验使用记录导出次序，正式宿主应供那一轮的登记名单。

**区块自洽**。首晚候选负责分路和保留对应的待认领屋。JX-28 的「挂上我的名牌」、正式所有权、同住与托管照原任务书。宿主正式身份、生产持久化接线、双端真实分房、本人光柱、绑床和门牌章待后续。现役连接序号、轮询会话和展示昵称均不能作为跨重连的屋主身份。
