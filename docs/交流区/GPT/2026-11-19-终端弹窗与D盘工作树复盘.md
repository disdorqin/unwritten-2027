## 本机执行约束

1. 开工查执行器返回的实际绝对路径。小镇工作树及自行写出的测试缓存、日志、构建和临时文件都落在用户指定的 D 盘项目目录或已约定的 D 盘验收目录。复用已存在的 D 盘检出。DevSpace 的托管路径仍落 C 时使用 D 盘普通检出或显式指定的 D 盘 Git worktree。
2. 同一桌面同时至多一项重验收。跨窗口错开全量回归、构建、Chrome 实走、性能采样和带载压测。一次性验收使用可取消的非交互入口，保存绝对工作路径、启动和结束时间、退出码及日志。验收不启用 `--watch`。重试前核对上一进程树已退出，避免启动互相重叠的副本。
3. 收工时先核对自己创建的工作树已保存回执和独有提交，确认进程退出和无未保存改动，再通过 `git worktree remove` 回收已结束的临时检出。历史 C 盘目录按工作树分别核对干净状态、远端覆盖或独有提交归档、活跃任务和未跟踪资料后处理，保留有待核实的工作树。
4. DevSpace 后续修改从实际启动配置设置 D 盘 `DEVSPACE_WORKTREE_ROOT`，临时目录单独设置并回读。验收入口需覆盖完整进程树的静默启动、取消和超时清理，取消后检查子进程。创建及清理按任务记录路径与 PID，验证托管任务结束后只回收已归档的干净工作树。这次已实际使用 D 盘检出交付规约。现役 DevSpace 配置与 C 盘历史树没有在本轮改动。
