# 装饰屋舍空间施工回执

## 现状审计

装饰房原先只建外立面和障碍，门无动作。西北木屋组已有一栋实体可进木屋，沿用原来的室内和通行。以集成头 `d3d4c2e` 构建实际地图后，共核对到 **90** 扇装饰房入口，原镇住宅 52、新区街巷 36、装饰木屋 2。

## 施工与实测

- 所有装饰入口使用同一套绿色门牌标识和「进入屋舍空间」动作。90 个外部站位均通过干地和碰撞扫线，其中 88 个可直走、2 个可斜向进入。
- 一间体素屋舍含壁炉、桌椅、床、书架和窗，3 个可坐点、烤火交互、留影点。首次进门才构建，之后复用原对象，室外隐藏。Chrome 146 实走原镇、新区、木屋各一门，室内对象 UUID 相同，返回误差低于 0.02 m，朝向恢复。模型从未重复创建。
- 屋内独占 scene layer。灯炉用现有灯光和自发光体素，进入壁炉范围走 `ceremonyFrost.setWarmth('fire-source', …)`。炉边就座实测冻纹透明度 0.75→0.70。相片实际下载为 `UNWRITTEN-2027-shared-home.png`。
- 两个独立 Chrome 客户端连接真实本机 presence，各从不同房门进入，双方同房各见 22 个访客部件；一人先离开，另一人的室内访客网格清零。两人独立返回各自门口。服务端回归同时验证同一水平格的室外访客与屋内分开。
- 单房 **2 draws／8,652 tris**（721 实例、1 套 BoxGeometry、0 纹理、0 新实时光源）。单人稳定 12 帧 GL hook 与 renderer.info 一致，零 Shader／GL／页面错。户外标识并入原批次，总计 450 个盒实例、5,400 个三角面，全镇几何账增量，额外 mesh/draw 为 0。
- 严格 TypeScript、town-preview 构建、全量 Node **126/126** 与服务端 **21/21** 通过。手机实机未覆盖。
