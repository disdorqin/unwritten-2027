# ZB-26 窗 A 挂载核验

底本 `town-release@b1cd43a2`，任务规格来自分区一 `c6913e9` 与 `e48ac98`。供窗 B 本体和分区一取件。

- 视角锁死的覆盖点在 `viewer.ts` 2190 行和 315 行。桌面与触屏输入共用 `turnView` 写 `yaw`，每个雪橇物理步又用 `alignPlayerWithSled` 把 `spot.yaw` 覆盖给 `yaw`（2966 行）。摄像机和 Presence 共同读取该变量。挂载时保留实际橇头给远端车身姿态和动画，第一人称另读骑乘看向；同一个桌面拖视和触控输入进看向，原有 W/S/A/D 进本体。取件时一并验证原地复骑、主动下橇和仪式携橇着地。
- 倒挡最先在空地就失效。`sled-motion.ts` 105/130/134/142 行把 S 当作制动并且正推力钳到 0，150 行回滚靠坡度。以发布树同 blob，平地 `grade=0`、`surface=0`、`deepSnow=false`、转向 0、60 Hz 执行 2 s，S 从静止位移 0 m、速度 0 m/s；静止相同条件按 W 前移 3.886 m、末速度 3.819 m/s。`sled-ride.ts` 181/192 行是实际路缘和硬障碍的另一层撞停，贴墙实走依然需要验。
- 点位表要区分预览场景与山域。`viewer.ts` 253/1092 行的原地点表同时驱动镇域绘制与 `activitySpots`。云海台和山门经 2058/2060 行优先取 `cloudRoute.action`，再由 2870 行提前走只渲染 `cloudRoute.scene` 的分支；只向镇域点表增加这两个坐标无法出现在山域视野或提供上车入口。窗 B 点位表需带域及地面高度，窗 A 与分区一接到实际补片后一起验挂载分支。

复算最小命令（在上述发布树执行）

```sh
node --import tsx --input-type=module -e 'import {createSledMotion} from "./tools/voxel-tavern/town-blockout/sled-motion.ts"; for (const forward of [-1,0,1]) {const motion=createSledMotion(); let meters=0; for(let i=0;i<120;i++) meters+=motion.step(1/60,{forward,turn:0},{grade:0,surface:0,deepSnow:false}).north/60; console.log({forward,meters,speed:motion.state.speed});}'
```

本件为挂载接缝与空地诊断。ZB-26 的正式施工、端上倒挡及逐点验收状态以对应任务卡为准。
