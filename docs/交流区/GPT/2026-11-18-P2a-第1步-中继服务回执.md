# P2a 第 1 步 · 位置中继与服务端回归

- 新增 `src/presence/`，可通过 `npm run start:presence` 启动已编译的 Node + ws 服务。仅在内存中管理会话、昵称与最后位置。监听位置由 `PRESENCE_HOST` 和 `PRESENCE_PORT` 配置，WebSocket 路径为 `/presence`。
- 会话总上限 64，包含握手完成但未 join 的连接。进出用 join／leave JSON，其余为 12 B state 与 `1 + 12 × 人数` 字节的快照。位置字段是厘米定点，包内玩家 ID 以服务端会话为准。
- 扩展镇界为 640 × 512 米。用 32 米格筛选，同层和跨层均按水平 80 米半径，取最近 48 人，空可见集变化也会及时清除。服务端校验格式、坐标边界与发包率，保留合法传送。
- T0 为 80 米、10 Hz。T1/T2 支持按在线人数由 `PRESENCE_TIERS` 配置，已实测升档和降档。开工拉取时 Muse 原稿未入库，生产阈值待按原稿填入。本地测试参数仅作验证。客户端来包仍按 10 Hz 窗口，档位收敛的是快照速率和订阅半径。
- 连接空闲时用 WebSocket 心跳维持会话。固定位置仅在可见集或者其他玩家状态变化时收到新快照，慢连接跳过积压的快照。

## 实测

- 服务端 Node 回归 **20/20**，其中真实 WebSocket 专项 **7/7**。覆盖会话 ID、昵称、进出、限速和异常帧、米到厘米边界、合法传送、80 米边缘、T0/T1/T2 双向切换、64 会话上限与 48 条快照上限。
- `tsconfig.server.json` 编译与专项严格 TypeScript 通过。根目录全量编译包含基线已有的镇景测试扩展名与 Three.js 双版本类型冲突，本批以服务端项目及专项严格编译核验。
- Windows 本机 48 个 WebSocket 客户端在近距离持续移动。3.006 秒内 1,296 个快照，每帧 47 条远端记录，平均 9.0 帧/秒/客户端，出口合计 243,587 B/s，每客户端 5,075 B/s。统计是应用层有效载荷，公网 TLS 及正式带宽峰值留待第四步。
