## P0 性能架构（非单纯降画质）
已证最后联合核显测试：坑口朝镇794 draws/2247048 tris、47.89–57.23 FPS/p95 21–25ms；B单项配对宽合批曾816→710/p95 29.1→16.8ms，后续盒面裁剪朝镇703 draws/2177224 tris。硬件Intel UHD D3D11，不能外推用户拯救者的GPU/真实FPS；B独立圆柱优化尚缺硬件AB。现有每帧各优化器预热/裁剪/恢复、terrain移动时遍历tile和动态索引上传、同步生成地形等是待测CPU/上传/长帧瓶颈，并非已经测定的根因。
- Phase1真实硬件基线：固定设备、显卡、分辨率、DPR、画质，坑口朝坑/朝镇、坑底、山脚、后坡、雪橇高速往返；采CPU各段、GPU timer（可用时）、帧时p50/p95/p99/长帧、draws/tris、GPU资源及加载队列。检查Edge实际使用独显/核显，不假定高性能电源模式会切GPU。隔离地形裁剪/宽合批/天空/天气/物理等单变量，不以禁用核心内容当正式修复。
- Phase2世界地形流送：全覆盖常驻低模，按64m空间块组织，近/中/远1/2-4/8-16m作为起始参数，按屏幕空间误差选LOD；混合所有权边界与保护区保持精确边界，LOD邻接缝合、近块就绪才替换远块、失败保留旧有效网格，碰撞始终取固定正典高程。优先玩家速度向量、视野及安全距离预加载；Worker离线/异步建网格，主线程统一上传时间预算，缓存与LRU释放；不一次为全域预分配巨型重复顶点缓冲，属性兼容处使用索引网格，保留硬边/材质边界。避免每帧重建/上传索引；优先稳定块剔除。
- Phase3对象与物理：按区块/材质构建稳定静态批次，森林远处简化或impostor、纪念馆远距建筑壳、轨道远LOD、地下非活动域停止视觉更新、透明天气/灯光预算；近景保留细节；碰撞只查询局部空间哈希/BVH，固定物理步长、渲染插值，联机权威独立；低频非必要更新，不停必要任务。统一所有优化器的CPU/GPU提交预算，避免多种裁剪层重复遍历。
- Phase4验收：游戏裸链接、普通玩法和雪橇、同设备AB及跨区图证，确保可见地面无洞、无巨型幕墙、无悬空/穿模、近远切换不闪烁。目标PC 60FPS/16.7ms帧预算、中端手机30FPS/33.3ms，常用视角<=300 draws、<=150万tris并关注p95/长帧，坑区相对广场>=80%；这些为目标非承诺。优先减少真实提交与长帧，而不是追逐单个微基准。验收须区分模拟视口和真机。
推荐顺序：先P0可见地形与远景错位修复，同时采集性能基线；再统一地形流送与渲染预算；最后后山连接与联合验收。仅作后续规划，不因本文件自动领取旧任务。
