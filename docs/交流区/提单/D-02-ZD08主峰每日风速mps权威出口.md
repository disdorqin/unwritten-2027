# D-02 · ZD-08 主峰每日风速 m/s 出口与双日取证（需总控裁定 / 窗 B G-09 协同）

状态：**待裁定接口 / 不阻断 D 窗其他独立施工**。提出：窗 D，2026-11-21。接线方：G-09/ZB-20 的服务器权威持有方；窗 D 负责消费端九环与宿主回放。

## 现役事实（禁止错配单位）

当前 `src/shared/town-outdoor-weather.ts` 的 `windEast/windNorth` 为**单位方向向量**；`windStrength` 为 **0..1 的无量纲强度**。当前 `src/shared/snowball-wind.ts` 的输出为雪球风**加速度 m/s²**，另有缆车风力相位速率。它们都不是《设计-交互玩法八案》案六要求的**主峰每日风速 m/s**，不允许窗口 D 自拟乘数转换。

## 提交给天气权威的四个必要决定

1. 物理速度：正式主峰风场的 `eastMetresPerSecond` / `northMetresPerSecond`，单位 **m/s**，速度上限与人机手感的生产数值需总控批准；现候选几何保护上限 35m/s，仅为防异常输入的保守门禁，不代表官方风速定值。
2. 日序与生效时刻：由服务器提供 `dayId` 和 `effectiveAtMs/expiresAtMs`，明确“今日”依据现实本地日还是未写镇 G-09 100 分钟周期；**窗 D 不自行推导**。同一有效期内所有联机玩家同一风场。
3. 发布/重连：受信任的 G-09 生产宿主下发版本 `revision`、`issuedAtMs`，跨日或复连必须防回退/冲突。当前实装 `main-summit-glide-official-wind.ts` 提供了待审 DTO 与边界校验；字段名不是既定服务端协议，须按总控批准后统一。
4. 中途跨日：当前飞行一旦从正式起跳点接受，赛段 `dayId` 与九道环冻结至本次落地。下一场新飞行使用新日风；已有飞行不瞬移环位、不改变当场分数。退服/重连是否继续同航次、是否保留成绩需与身份/存档系统共议。

## 交接与验收（窗 B/G-09 → 窗 D）

- 提供权威生产物理风速出口，不从 `windStrength` 无量纲量猜测；附清雪/大风/暴雪各自输出的实际 m/s 样例和版本时间戳。
- 提供两份**真正来自服务器同一权威**、处于不同正式日序的取证帧，证明其不会被客户端自造；窗口 D 在两份原件上走 `shiftSummitGlideCourseWithDailyWind` 并做正式九环轨迹、净空和落靶复验。
- 切天与断线复验：跨日新场景路线上风改位、旧航次九环不改变；非有限、超额、错误单位、旧修订、伪造来源及过期包不允许发布比分。
- 官方风量未定、生产宿主没接上之前，九环只保持“独立练习/完工待验”，不得把两个测试用 m/s 常数冒充官方风速，或者宣布默认场景已挂载。
