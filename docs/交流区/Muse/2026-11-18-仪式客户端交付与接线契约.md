## 2. town-ceremony.ts 做了什么

- **时钟提供者**（设计 §5 的 CeremonyClock 接口）：
  - `createLocalCeremonyClock()`——单人版，设备本地时间，与时光信箱 UNLOCK_AT 的本地口径同源；本批已接线使用。
  - `createServerCeremonyClock()`——多人版预留：`calibrate(serverEpochMs)` 存偏移、`now() = 本地 + 偏移`，偏移数学已实现并有单测；**presence 传输/校准调用未实现**（GPT 份额，契约 §4-1）。
- **时间轴纯函数**（设备本地时间，12-31 当晚）：`ceremonyStateAt(now)` 给出阶段（standby/mailbox/evening/converge/approach/countdown/climax/afterglow/ordinary）、`snowIntensityAt`（雪势 1–4 档连续曲线：档间以边界为中心 10 分钟线性过渡；零点后 10 分钟 4→2、01:00 回 1；与设计 §3.1/§3.2 对齐）、`frostBaselineAt`（L0–L3，零点后 +20/+40/+60 s 逐级快速消退）、`dimLevelAt`（23:50 起 0.6、最后 10 秒 0.3、零点回 1）。
- **cue 表**（设计 §3.4）：`ceremonyCuesBetween(from, to)` 纯函数枚举窗口内 cue——20:00 `mailbox-open`；21/22/23 时 `hourly-chime`（3 小敲）；23:50 `lights-dim .6`、23:59:50 `lights-dim .3`、T+0 `lights-dim 1`；T−10…T−1 每秒 `countdown-tick`；T+0 `new-year`；大敲 `grand-strike` 12 下（T+(i−1)×2.02 s，第 12 下在 T+22.22 s，设计口径「约 T+24 s」内）；`bloom-band` 4 带（T+0/+0.6/+1.2/+1.8 s）；`fireworks-main` T+1 s、`fireworks-far` T+8 s、`fireworks-finale` T+14 s（在设计 T+8~16 s 窗口内取点，可调）；`climax-end` T+30 s。
- **编排器** `createCeremonyDirector(clock, hooks)`：每帧 `update()` 推进 cue 并回报状态；**迟入/重连不补放已错过的 cue**（设计 §5），但状态（阶段/雪势/冻纹/渐暗）立即正确。hooks：`onCue`、`onSnowIntensity`（连续值，供 GPT 的 snowfall uniform 消费）、`onFrostBaseline`、`onDim`。
- **DOM 叠层** `createCeremonyOverlay`：最后 60 秒 DOM 大字倒数（≤10 秒切 `.final` 大字样式）、渐暗黑幕（opacity = (1−dimLevel)×0.72 近似）、T+0「新年快乐！」横幅（9 s 后自动收，减动效时 12 s）。全部 DOM、零 WebGL；`dimOverlay:false` 选项供 GPT 接真实灯光渐暗后关闭黑幕近似、只留信号（契约 §4-3）。

## 3. town-frost.ts 做了什么

- `frostLevelStyles`：L1 角霜（opacity .25/霜带 6%）、L2 边带（.5/12% + 冷色片 .08）、L3（.75/22% + 冷色片 .14 + 呼吸雾），逐项对设计 §4.1。
- `createFrostTracker`（纯逻辑）：个人等级浮点跟踪——首次 update 直接对齐目标（迟入状态补齐，设计 §5）；之后升/降均按 **1 级/20 秒**平滑；身处任一回暖点时目标 = 基线 −2（设计 §4.2「−1~2 级」取上限，地板 0），离开后同速率回基线。
- `createCeremonyFrost`（DOM）：`#ceremony-frost` 内 `.frost-edges`（复用 `snowball-impact-frost.png` 平铺 + CSS 径向 mask 只露边缘，mask 比例按 `data-level` 切换）、`.frost-tint`、`.frost-breath`（L3 且非减动效时显示，纯 CSS 动画）。只在等级变化时写样式，静止零成本；与雪球命中的 `#snowball-frost` 是两个独立叠层（z 序 3 vs 2，同帧不冲突）。`setEnabled(false)` 整体隐藏（设置开关接口，设计 §4.1 可关）。
- **红线落实**：寒冷等级只写该 DOM 叠层，不写任何玩法状态——不掉血、不减速、不锁交互（设计 §4.3）。
- **回暖判定接线现状**：已接两个现成可判定的——`interior` ← 帧循环既有的 `sheltered`（与 snowfall 共用同一判定；注意该判定在本基线只覆盖纪念馆室内足迹，是既有限制，扩大室内判定属 GPT 后续）；`onsen` ← `hotSpringSoak.active()`。未接的留事件接口 `setWarmth(source, active)`：`hot-drink`（酒馆饮品/热饮摊的饮用事件尚无现成信号）、`fire-source`（广场篝火尚未建，属广场充实批）。

## 4. 与 GPT 侧的契约点（接线契约，合并/联调时按此对接）

1. **服务端仪式时钟**：presence 侧下发服务端 epoch（连接时 + 周期校准）→ 客户端改用 `createServerCeremonyClock()` 并在校准时调用 `calibrate(serverEpochMs)`；director 与 cue 表不改。仪式事件（手动敲钟、大敲、绽放）若走服务端时间戳广播，接收端用同一 clock 换算本地触发点；迟入者不补放、只同步状态（director 已按此语义实现）。
2. **cue 消费**：`createCeremonyDirector` 的 `onCue` 是唯一 cue 出口。GPT 侧消费：`hourly-chime`/`grand-strike`/`countdown-tick` → tower-chime 播放（小敲/大敲两档参数在 GPT 侧定档）；`fireworks-main/far/ finale` → festival 参数化编排的三个发射点；`bloom-band`（4 带×0.6 s）+ `lights-dim` → town-lights 仪式覆盖层（不写玩家点灯进度，设计 §3.5）；`mailbox-open` → 时光信箱开启提示/引导（信箱本体在 GPT 侧）；`new-year` 本批已接横幅，GPT 如需同时触发树/钟楼全亮走 `bloom-band` band 0 同刻。
3. **渐暗双轨**：本批黑幕叠层是近似实现；GPT 若以真实灯光实现渐暗，初始化时传 `dimOverlay: false`，改由 `onDim` hook / `lights-dim` cue 驱动真实灯光，避免双重变暗。
4. **雪势强度**：director 的 `onSnowIntensity(value)`（1–4 连续值）是 snowfall 强度 uniform 的数据源；GPT 给 snowfall 加 uniform 时订阅此 hook 即可，曲线不在 snowfall 内另写（设计 §4.4 一个数据源两处表现）。
5. **冻纹回暖事件源**：`ceremonyFrost.setWarmth('hot-drink' | 'fire-source', active)` 已留接口；热饮饮用事件与篝火区建成后由 GPT 在事件点调用。室内判定若扩围，`sheltered` 的新判定结果继续走现有 `setWarmth('interior', …)` 一行接线。
6. **DOM id 占用**：`ceremony-frost`、`ceremony-dim`、`ceremony-countdown`、`ceremony-banner` 四个 id 由本批新增，GPT 侧勿重名。
