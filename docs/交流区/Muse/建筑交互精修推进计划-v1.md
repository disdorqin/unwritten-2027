## 1. 标杆拆解：未写酒馆为什么好

酒馆是全镇唯一走完「结构样件→外观细化→室内陈设→第一人称实玩修正」全程的建筑（仓库 AGENTS.md 既定迭代法，酒馆为已认可样件）。拆开看，它的好由五组可复制要素构成：

### 1.1 陈设密度基准

| 要素 | 酒馆实况（出处） | 可复制基准 |
|---|---|---|
| 可用空间 | 两层全可用：1F 大厅+吧台+壁炉区、2F 阅览回廊，楼梯带栏杆实走（`landmark-tavern.ts` 体素模型 + floors/colliders 全登记） | 主要建筑至少一层完整可用内饰；有二层的必须实走可达，不做假楼梯 |
| 功能区成套 | 吧台（柜台+酒架）、餐桌区、壁炉区（光源位 [4,3.5,-3.2]）、阅览区（2F 光源位 [-3,10.75,-.5]）、门廊，四区家具成套而非单件点缀（`landmark-tavern.ts` lightSources 与模型目录） | 每栋至少 2 个功能区，家具按区成套（桌+椅+该区标志物），禁止「一张桌子算陈设」 |
| 织物与小件 | 地毯（runner + 包边）、桌布+金饰条、楼梯踏步木件逐级、屋顶积雪逐片（`buildParts()` 后半段程序化补件） | 每栋至少 3 类软/小件：织物、桌面物、墙面物各一 |
| 灯具成组 | 灯笼 8 盏（门廊 4 + 厅内 4，统一 `lantern()` 造型：灯罩分层+灯焰+金件） | 灯具成组出现（≥3 同族），造型全镇可复用 |
| 标识与字 | 招牌「未写酒馆」四字逐字 CanvasTexture 进材质（`makeMaterial` sign0–3） | 每栋有名字：招牌/名牌必备（扩展审计第 1 项同此判） |

### 1.2 交互数量与类型

酒馆现有 **4 类交互**，是全镇单体最密：

1. **调酒**（吧台触发点）：选基底×配料→2.2 秒调制，吧台 3D 道具实时注液变色（`tavern-mix-props.ts`）→端起随身→任意处「喝一口」；成果记入护照戳册（`tavern-activity.ts`、`tavern-mix-book.ts`）。
2. **就座 ×2**：1F 餐桌旁、2F 阅览长凳（`tavern-activity.ts` seats，走全镇 sit 框架）。
3. **可开窗**：两层共 12+ 扇窗登记为活动点，带各自落位 approach（`landmark-tavern.ts` tavernWindows + `addTownWindow`）。
4. **NPC 对话**：老板罗大江驻店，熟络分层台词（NPC 语料 v2）。

**基准线：T1 建筑 ≥3 类交互（其中至少 1 类是「动手型」——制作/操作/留存成果，纯对话与纯就座不算达标）；T2 ≥2 类；民居轻量档 ≥1 类。**

### 1.3 NPC 与氛围

- **有人**：罗大江常驻吧台后，建筑有「主人」——这是酒馆与空壳建筑的第一区别。基准：T1 建筑至少 1 名驻点 NPC 或固定巡游停靠点。
- **烘焙光影**：6 个手写光源位（壁炉/吧台/中厅/阅览层×2/门廊）把暖光烘进顶点色（`landmark-tavern.ts` lightSources），室内 .19 基础亮度 + 光源衰减叠加——**零真实光源、零逐帧成本**，得到全镇最暖的室内。基准：室内氛围一律走烘焙/emissive，禁止为精修新加常开 PointLight（邮局 2 盏旧账为反面教材）。
- **像素材质**：每种材质一张 16×16 程序纹理（木纹/石纹/屋面各有图案规则，`makeMaterial`），近看有颗粒、远看成色块。基准：新陈设不许纯色平涂盒，必须进既有材质/图集体系。

### 1.4 性能姿态（标杆的另一面）

酒馆内容最密，成本却在中游：1F 145 calls / 619,860 tris、2F 122 / 547,582（画像实测），且几何开镇时已就位、进门仅 +10 buffer（全镇最小，无「进门长出来」感）。原因：全模型按材质合并成批、纹理是程序生成的共享 CanvasTexture。**基准：内容密度与成本脱钩——靠合并与共享，不靠删减。**

### 3.3 民居轻量档（不逐栋重做）

- **模板化**：只做 2–3 套「可进样板间」模板（木屋/砖房/现代各一），每套 = 开门可进 + 4–6 件陈设（床/桌/炉/柜/挂画，走该栋既有批次）+ 1 个轻交互。
- **轻交互只选一**：#21 信箱明信片（逐户翻看，内容走 NPC 语料纪律）为全民居统一项；样板间内可加「留一盏灯」（开关窗灯 emissive）二选一，不叠加。
- **铺开方式**：模板在原镇主题住宅先落 3–5 栋、扩展四片区各落 1–2 栋，其余住宅维持实心但补门廊小件（灯笼/柴垛/信箱本体）消除「假门贴面」感。逐栋全精修明确不做——36+ 栋的边际体验收益最低、性能账最难收。

## 4. 性能把控（硬纪律，Thomas 最在意的一节）

### 4.1 总账不动

全镇预算不变：任一标准视角 **calls ≤300、tris ≤150 万**（现行口径）。精修是「在预算内把空房子填满」，不是「申请加预算」。D6 与既有整改争回的余量优先归还欠账（博物馆 2F、市集街区），不许被新陈设抢占。

### 4.2 单栋增量上限（开工前定死，验后对账）

定法：**上限 = min（纪律封顶， 该栋实测视角剩余预算的一半）**；纪律封顶为 **calls +5 / tris +5 万**（与覆盖规划「单处交互本地 ≤+5 draws」同源，扩展到整栋精修）；**已超标栋上限为 0**——先做减法还账、回到预算内，才按公式解锁增量；**未测栋先补测基线**，补测前只许按暂定上限（calls +5 / tris +3 万）施工且不得超。

| 建筑 | 基线（calls/tris） | 增量上限（calls/tris） | 前置条件 |

### 4.3 过程纪律（每栋、每批都执行）

1. **先报后做**：每栋精修开工前，施工方在回执/任务单里写明本栋增量预算（对照 §4.2 上限）；没有预算数字不开工。
2. **验后对账**：完工后同机位、同视角 GL-hook + renderer.info 双路实测，与基线对比入验收单；**实测超上限即回退该栋新增项**（按项倒序撤），不许「先上车后补票」，不许挤占别栋余量转嫁。
3. **靠近才活**：交互逻辑与陈设动画只在玩家进入该栋/进入地块加载半径时激活；**空室内休眠**——无玩家在内时不跑更新循环、不刷粒子、不轮询触发点（温泉蒸汽「50 m 内才更新」、NPC「60 m 外冻结」为既有先例，全栋推广）。
4. **只许并批**：新增陈设一律并入该栋既有材质批次或 InstancedMesh，**禁止逐件独立 Mesh**；新贴图进共享图集（博物馆标签图集机制），禁止一物一纹理；发光一律 emissive/烘焙，**禁止新增常开光源**。
5. **远处零成本**：地块卸载后 draws、纹理、缓冲区计数回基线（覆盖规划验收第 4 条），精修批次验收时逐栋抽查。
6. **总账复核**：每批精修落地后重测四标准视角（广场/纪念馆/冰湖/酒馆室内）+ 本批涉及栋的本地视角；任一超标，冻结下一批精修、先还账。

## 5. 排期衔接

### 5.1 启动门槛

本计划在 **多人 P2a（互见）上线并稳住、P2b（雪球/姿态同步）落地后**启动。理由：精修会动 viewer 触发点与各栋批次，与多人改造同文件冲突面大；且 Thomas 的优先级序列已定（多人 → 多人负载优化 → 建筑精修）。P2 期间只做不碰代码的准备：陈设清单定稿、文案备料、本计划 §4.2 的未测栋基线补测排期。

### 5.3 批次序

1. **批一（急救+样板）**：博物馆还账（图集化/按翼分批）、市集街区按格分批——两笔纯减法先行；同时长殿点灯接力（余量最大、最容易出效果）作精修样板批，跑通「报预算→施工→对账」全流程。
2. **批二（T1 主体）**：钟楼、邮局、温泉、火车站、纪念馆新区，按 §5.2 合并单逐栋推进，一栋一验。

4. **批四（民居轻量档）**：模板定稿后批量套用，最后收口。

每批结束出对账小结（各栋预算 vs 实测），Thomas 过目后再开下一批——精修是长期工程，节奏服从「不卡」这一条总纲。
