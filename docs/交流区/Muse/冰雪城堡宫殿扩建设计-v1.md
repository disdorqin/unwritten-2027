# 冰雪城堡宫殿扩建设计 v1（Muse，2026-11-18）

Thomas 指示链：14:06「冰雪城堡可以做大一些，像一个宫殿一样」→ 追加「**玩法第一，没玩法就没意思**」→ 点名宫殿寻宝、迷宫、密室探索与机关 → 裁定「**机关不用双人，一个人也行**」→ 质量加码「更详细、玩法更多样、性能账要硬」。

与《冰雪城堡精修设计-v1》分工：精修稿管材质/光影/细部（17 项继续有效，GPT 已建首批 f1ffd1e 与外观/画廊/王座反馈 ec4ff10）；本稿管**玩法系统、体量格局、扩建边界与总成本账**。两稿冲突处以本稿的格局与玩法为准，精修的材质口径（fresnel 冰缘光、发光本色、冰凌带、母题变体要求）全部继承。

**叙述顺序即优先级：先定玩什么（§1），再定多大（§3–§4），最后算账（§5）。**

## 0. 总则（五条，施工与验收都按此裁）

1. **单人总则（Thomas 14:11 裁定）**：宫殿全部机关、迷宫、密室必须**单人可解、单人可通**，不许任何双人门控。双人配合至多是可选捷径（更快/更省事），且每个机关必须在 §1.6 逐个写明单人正解。验收时以单人全程通关为硬线。
2. **玩法先于体量**：任何一处新体量必须对应 §1 的一个玩法落点；没有玩法对应的纯装饰扩建不立项（前庭、后园的观景/拍照点除外，那是地标本分）。
3. **机关只许热点状态机级**：全部机关用 town-activity 热点 + 本地状态机 + 既有系统（钟声 WebAudio、P2b 事件、frost 回暖）实现；不许新物理系统、不许新协议字段（P2b 姿态枚举扩一位除外，见 §1.2）。
4. **并批与零常开**：新几何一律并入既有 wing 批次或新增 wing 的 opaque/luminous 合并；动态件（门板/冰镜/推雪块）逐件点名计数，不许泛滥；无人时零新增常开开销（机关状态机只在玩家进入城堡地块后启用）。
5. **已建不浪费**：f1ffd1e/ec4ff10 已建的精修件（冰凌带、塔冠尖刺环、雪花纹章、王座背屏、双鹿、冰雕展廊 4 件、吊灯、登基反馈、许愿晶）全部保留，扩建只在其上叠加与扩容，不推倒。

## 1. 玩法主线（先定玩什么）

### 1.1 玩法全景与多样性对照

| 玩法类 | 宫殿落点 | § |
|---|---|---|
| 探索 | 冰宫迷宫 + 密室链（王座后→画廊→塔楼梯下→宝物间） | 1.4 / 1.5 |
| 解谜 | 机关谱六件（压力板/拉杆序列/敲钟顺序/冰镜光束/限时门/冰钥匙） | 1.6 |
| 竞速 | 主塔登塔竞速（计时+成绩牌） | 1.7 |
| 争夺 | 王座「冰雪之主」限时据点争夺 | 1.2 |
| 收集 | 生肖挂件城堡节点 + 宫殿专属宝物（冰冠/权杖）轮换藏点 + 冰钥匙 | 1.3 |
| 社交 | 大厅长桌宴席（就座/举杯/宴席回暖）+ 前庭雪仗据点 + 王座全镇广播 | 1.8 / 1.9 / 1.2 |

六类全占。设计时刻意不设的：宫殿内 NPC 对话树（礼仪官只做职能播报与提示，台词由内容线供，见 §1.10）、宫殿专属货币（宝物只做收集与展示，不进任何经济系统，沿用全镇无货币口径）。

### 1.2 王座争夺「冰雪之主」（候选①，采用）

现有王座就座/拍照/登基反馈之上，升格为限时据点玩法：

| 参数 | 口径 |
|---|---|
| 成为冰雪之主 | 在王座就座连续 3 s（现有 seat 点位，冰冠标记升起 + 登基反馈全套：塔晶呼吸加速、厅光渐亮） |
| 任期 | 5 min 封顶；离座超过 10 s 视为退位；被雪球命中 3 次（P2b hit 事件计数）被「拉下王座」（退位 + 一行广播文案，不惩罚） |
| 全镇广播 | 就位/退位各一条 announce 全镇广播（复用 presence announce 通道）：「XX 登临冰雪王座」/「冰雪之主退位，王座空悬」 |
| 头顶标记 | 冰冠标记：P2b 姿态枚举扩 1 位「戴冠」（粘性状态，变化才发，零新协议）；单人/离线时本地同样显示（DOM 标记，零 GL） |
| 成绩 | 王座台侧成绩牌（canvas 牌，并入铭牌图集口径）：今日累计在位时长榜（localStorage 本地口径先行；多人榜待 P2b 事件层顺带，不单独开系统） |
| 单人情形 | 无人争夺时就座即得称号与全套反馈，5 min 后自动退位可再坐——单人也有完整体验，不做假争夺 |
| 奖励 | 在位期间王座拍照点自动加冰冠构图框（现有拍照框架的相框变体）；仪式夜：在位者即「守冠人」，零点 cue 时王座厅光效由其触发（仪式稿衔接点，先登记不实现） |

与 P2b 衔接：命中计数走 P2b 被击者权威判定（设计稿 §1 口径），宫殿侧只订阅 hit 事件累计，不自判。

### 1.3 探索线总览：寻宝就是路线本体（候选②，采用）

宫殿寻宝不是另挂一个系统——**迷宫与密室链就是寻宝的路线本体**，宝物与挂件落在路线深处：

```
西门/南门入宫 → 庭院（许愿晶、礼仪官给第一条线索）
├─ 前庭冰宫迷宫 → 迷宫之心石窟：+ 生肖挂件·城堡节点
├─ 大厅拉杆序列 → 画廊密室（冰镜光束）→
├─ 王座后密室（冰钥匙开）→ 密室链中段
└─ 主塔敲钟顺序 → 塔楼梯下密室 → 宝物间（终点）：+ 冰冠陈列
```

| 收集物 | 位置 | 口径 |
|---|---|---|
| 生肖挂件·城堡节点 | 迷宫之心石窟 | 以《生肖寻宝藏点规划-v1》城堡区条目为准，本稿只定它落在迷宫深处而非庭院随手可得 |
| 冰钥匙 | 迷宫之心石窟（压力板机关后） | 道具 flag（localStorage + DOM 道具片显示），全宫共用一把，不消耗；是密室链后半的门禁 |
| 宫殿宝物（冰冠/权杖，二选一轮换） | 藏点 A（画廊密室）/ 藏点 B（宝物间）周轮换 | 取得后在王座台侧陈列位亮起对应宝物（全镇可见的「已集齐」展示）；轮换与重置口径走现有寻宝的周口径，不新开计时系统 |
| 冰冠（终点陈列） | 宝物间 | 不可带走，是密室链通关凭证：陈列前拍照点 = 宫殿探索线的毕业照点 |

### 1.4 冰宫迷宫（Thomas 点名立项）

位置：前庭东半（南扩带内，露天冰墙迷宫——冰雪节式的露天冰迷宫，从大殿观景层可俯瞰全貌，俯瞰本身就是提示手段）。

| 参数 | 口径 |
|---|---|
| 占地 | 24 × 12 m（前庭东半，E 局部口径见 §3.5） |
| 格网 | 格距 1.5 m，16 × 8 格；墙体为冰块墙，高 2.2 m（跳跃 1.25–1.30 m 跳不过，防翻墙作弊）、厚 0.4 m |
| 主线 | 入口（西端）→ 迷宫之心石窟，主线长约 60 m（约 40 格），步行约 50–70 s |
| 支线 | 死胡同 6 条（其中 2 条尽头放小奖励：许愿晶碎片文案牌/拍照点），环路 2 处（防单路背板无聊） |
| 石窟 | 迷宫中心偏东 3 × 3 m 冰窟：冰钥匙台 + 生肖挂件点 + 一盏灯（luminous 并批） |
| 可变路径口径 | **不做动态墙系统**。可变性由 3 块可推雪块承担：雪块可推入/推出 2 个岔口凹位，堵一条近路或开一条近路——同时是压力板机关的配重来源（§1.6-1）。地图本体固定，验收可复现 |
| 防卡死 | 任意点到出口的通路不依赖雪块位置（雪块只影响近路与机关，不堵主线）；石窟内设「离开石窟」热点（原路返回口径，不做传送） |
| 成本形态 | 墙体全 box 并入前庭 wing 一次合并（§5）；雪块 3 件为独立动态 mesh（点名计数） |

### 1.5 密室链（Thomas 点名立项，逐间）

四间一线，顺序即探索线后半。暗门开启方式各不相同（对应机关谱），全部单人可开：

| # | 密室 | 位置 | 开启方式（机关） | 室内内容 | 单人解法步骤 |
|---|---|---|---|---|---|
| 1 | 王座后密室 | 王座背屏后（现背屏 solid 处改活板门） | **冰钥匙**（§1.6-6）：持钥匙在背屏前用开门热点 | 狭室：密室链图谱牌（画出四间密室的相对位置，给后续探索降难度）+ 宝物轮换藏点 A 的线索牌 | ①先通迷宫取得冰钥匙 → ②回王座厅，背屏东侧热点「以冰钥匙开启」→ ③活板门滑开（状态机动画 0.6 s），入内读图谱 |
| 2 | 画廊密室 | 北翼画廊中段展墙后 | **拉杆序列**开外门 + **冰镜光束**开内龛（§1.6-2/-4） | 宝物轮换藏点 A + 冰雕小品 1 件 + 敲钟顺序的乐谱线索（低-高-中音高提示画） | ①按画廊展品铭牌顺序拉 3 拉杆 → ②展墙移开 → ③转两面冰镜使光束落靶晶 → ④内龛开，取宝物/读乐谱 |
| 3 | 塔楼梯下密室 | 主塔楼梯第一跑下方 | **敲钟顺序**（§1.6-3）：塔顶三钟按乐谱顺序敲响，梯下门应声开 | 限时门机关的控制杆 + 宝物间前厅 | ①登塔（竞速路线同路）→ ②按乐谱敲三钟 → ③下楼，梯下门已开（保持 10 min，不搞二次竞速惩罚） |
| 4 | 宝物间（终点） | 大殿王座台地座内（由密室 3 前厅经限时门入） | **限时门**（§1.6-5）+ 入门后冰钥匙二次验（防跳关直入） | 冰冠陈列 + 毕业照拍照点 + 宝物轮换藏点 B + 成绩牌（探索线完走记录） | ①在密室 3 拉控制杆 → ②限时门开 20 s，前厅至宝物间 12 m 单人步行 ≤10 s（留一倍余量）→ ③门内冰钥匙热点验钥 → ④达终点 |

密室共性口径：室内照明靠 luminous 冰灯（并批，零真光源新增）；门状态为本地状态机 + 进度 flag 落 localStorage（`unwritten.ice-palace.v1` 一个键存全部机关/密室/收集进度，沿用时光信箱的单键口径）；多人时密室进度**各玩各的**（presence 不带机关状态，与 NPC 本地口径一致，不做全镇同步门——避免先到者替后到者开完所有门）。

### 1.6 机关谱（逐个参数与单人解法）

全部热点状态机级。判定半径默认沿用 town-activity spot 的 range 口径（0.85–1.2 m），下表逐个标注。

**机关 1 · 压力板（迷宫石窟门 + 宝物间前厅备用）**

| 参数 | 口径 |
|---|---|
| 尺寸/判定 | 板 0.9 × 0.9 m；站上板面（玩家 y 在板顶 ±0.45 m 且水平距中心 ≤0.55 m）即触发 |
| 行为 | 压住期间石窟门开；离板 1.5 s 后门合 |
| **单人正解** | 把迷宫内可推雪块（1.2 m 见方，推行速度 = 步行 ×0.8）推上压力板配重——雪块在板上即恒压，单人从容过门 |
| 双人捷径（可选） | 同伴站板压住，另一人直接过（更快，非必需） |
| 奖励 | 门后即冰钥匙台 |
| 实现 | 板与门各 1 个动态 mesh（点名）；推雪块复用迷宫 3 块之一；状态机三态（闲置/压住/延时合门） |

**机关 2 · 拉杆序列（画廊密室外门）**

| 参数 | 口径 |
|---|---|
| 构成 | 画廊 3 展品旁各 1 拉杆（杆距 ≤6 m，单人往返无压力）；正确序 = 展品铭牌编号序（雪松→帆船→冰灯塔，铭牌即题面） |
| 判定/冷却 | 拉错即全复位 + 一声低鸣（WebAudio 合成，复用钟声合成器低音色）；无惩罚冷却，可立即重试 |
| **单人正解** | 拉杆为自锁式（拉下保持），单人依次拉完即开门——本机关天然单人 |
| 奖励 | 画廊密室外门开（展墙滑动 0.8 s） |
| 实现 | 拉杆 3 件并入画廊 wing 静态几何 + 各 1 个小动态杆头（点名 3 件）；序列状态机 |

**机关 3 · 敲钟顺序（主塔塔顶 → 塔楼梯下密室）**

| 参数 | 口径 |
|---|---|
| 构成 | 塔顶 3 口小冰钟（大/中/小，音高低/中/高），复用 `tower-chime.ts` WebAudio 合成钟声（改音高参数，不新造音频系统） |
| 题面 | 画廊密室乐谱画（低-高-中）+ 礼仪官可重复索要提示（§1.10） |
| 判定/时限 | 每次敲钟间隔不限时（单人不赶时间）；错序在第三声落下时判错、清零重来；全对 → 梯下密室门开，保持 10 min |
| **单人正解** | 一人敲完全部三钟即成——天然单人 |
| 奖励 | 塔楼梯下密室（密室 3）开启 |
| 实现 | 钟体并入主塔 wing；敲钟热点 3 个；与钟楼敲钟分工：钟楼管仪式与聆听、主塔管解谜与竞速（§1.7），两套钟声合成共用、场景分开 |

**机关 4 · 冰镜反射光束（画廊密室内龛）**

| 参数 | 口径 |
|---|---|
| 构成 | 光源晶（恒亮）+ 冰镜 2 面（各 4 个朝向档位，热点点击循环切换 45°）+ 靶晶；光束为预烘焙的 luminous 细长盒段（每镜 4 档 × 2 镜 = 16 种组合的光路几何预先算好、按状态显隐，全在画廊 wing 的 luminous 合并内，零动态 mesh） |
| 判定 | 仅正确组合（镜 A 档 2、镜 B 档 4，出厂定版）使末段光束落靶 → 靶晶亮起、内龛开 |
| **单人正解** | 冰镜档位保持式（转好不复位），单人逐面调即可——天然单人 |
| 奖励 | 内龛：宝物轮换藏点 A |
| 实现 | 纯状态机 + 显隐切换，是六机关里最便宜的一件（+0 动态件） |

**机关 5 · 限时门（宝物间）**

| 参数 | 口径 |
|---|---|
| 时限 | 控制杆拉下 → 门开 **20 s**；门至宝物间内门 12 m，单人步行约 8–10 s，**时限留一倍余量**（Thomas 单人总则的量化落点） |

| 双人捷径（可选） | 同伴守杆可反复续开（省往返，非必需） |
| 实现 | 门 1 动态 mesh + 杆（并入密室 3 静态）；倒计时走 DOM 提示行（town-activity-status 通道），零 GL |

**机关 6 · 冰钥匙（道具门禁，王座后密室 + 宝物间验钥）**

| 参数 | 口径 |
|---|---|

| 使用 | 门前热点「以冰钥匙开启」，判定半径 1.2 m；不消耗、可重复开 |

### 5.3 与 D6 峰值机位的关系（必须对账的一笔）

- 第五轮实测的全镇峰值机位（缩放第 31 步一带）：**285 calls / 1,496,832 tris**；按旧线（300/150 万）余量仅 **3,168 tris**；按 Thomas 14:12 新 PC 线（450/220 万）余量为 **165 calls / 约 70.3 万 tris**。
- 宫殿是否入该峰值帧：峰值帧为全细节广角帧，城堡位于地图东缘——**须以真机在第 31 步机位复测城堡入帧范围后定对账口径**，本稿先给最坏情形：若宫殿全量入帧，该帧 tris 增量 = 宫殿外部可见部分 ≈ **+1.6 万**（密室/画廊内装在广角帧同样被渲染，无遮挡剔除，按全量保守计）。
- 对账结论：旧线下最坏情形超约 1.3 万 tris——按 12:13 裁定这不构成回滚事由、只触发真机裁决；新 PC 线下最坏情形仍在余量内（1,496,832 + 16,000 ≈ 151.3 万 < 220 万），**结论：新线下无账面压力，旧线下记一笔真机裁决项**。
- 真机复测点（写进 §7）：①第 31 步峰值机位（城堡入帧与否 + 帧时）②前庭南缘望宫殿全景（宫殿自身最重机位：主殿+双翼+主塔+迷宫同框）③大殿内王座机位（内装最重）。三点帧时以真机为准，SwiftShader 数不作数（沿用既有口径）。

### 5.4 远处零成本与实例化口径（逐部）

- 城堡本体走 viewer 的 landmark 懒加载（现行口径不变）：未接近不加载、离开不驻留新增常开销。
- 机关状态机、王座计时、竞速计时：玩家进入城堡地块 bounds 才 tick，离开即停（零常开）。
- 迷宫雪块、机关门：静止时就是普通 mesh，无逐帧更新；仅交互帧有状态迁移。
- 光束、宴烛、石窟灯：luminous 顶点色发光（L1 口径），零真光源新增——宫殿全量**不新增 PointLight**（精修 L3 的 2 盏池化灯仍是全宫上限）。

## 7. 验收点

**远景地标感**
1. 广场徽心、湖对岸两机位望宫殿：塔群读作「二大二小一主」、主塔 26 m 压得住画面；夜间窗框亮边 + 前庭冰灯柱成串，宫殿是东缘第一亮点。
2. 火车行经城堡南站路段望北：前庭 + 迷宫 + 宫殿全貌的第一眼构图成立（接驳轴线不挡视线）。

**近景与内部**
3. 双翼廊屋不穿帮：借墙面无缝、展品铭牌可读；主殿挑高后吊灯对位、冰毯中轴不断。
4. 母题变体抽查：主塔八角塔身与四方塔可辨；南门雪花纹章与西门为同母题不同图样（六角 vs 现图样）。

**玩法（硬线）**
5. **单人全程通关**：一名测试者单人按 §1.3 路线走完——迷宫取钥匙 → 王座后密室 → 画廊双机关 → 登塔敲钟 → 限时门 → 宝物间，全程无双人协助、无作弊指令；逐机关对照 §1.6 参数表核时限/半径/冷却。
6. 王座争夺：就位广播、3 命中退位、5 min 任期、离座 10 s 退位四项逐项触发验证（多人项用双客户端，单人项单客户端）。
7. 竞速：起/终点板判定、计时行、个人最佳落盘；宴席：开席举杯 + 回暖 flag 生效。

**回归与账**
8. badWalk：地块新边界（48×52）全域 + 接驳轴线走廊复测 = 0；既有互动全回归（就座/双拍照/许愿晶/铭牌/展廊）。
9. 性能对账：renderer.info 在 §5.3 三个复测点实测，城堡组 calls/tris 与 §5.2 账面偏差 >20% 须在回执中归因；动态件点名清点 = 10 件（雪块 3 + 门 3 + 杆头 3 + 压力板 1），多一件即不通过。
10. tests 全套通过（基线口径不回退）。
