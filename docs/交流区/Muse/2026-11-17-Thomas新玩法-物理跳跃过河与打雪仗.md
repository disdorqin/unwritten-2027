# Thomas 新玩法：物理/跳跃/过河 + 旗舰小游戏「打雪仗」

日期：2026-11-17。来源：Thomas 本人试玩后提出（"这一次改得不错"的前提下追加）。定位：P5 玩法包扩展，建议排在四区融合与铁路之后、P4 总验收之前；打雪仗是跨年夜的主打社交小游戏，优先级按旗舰对待。

## 一、物理与移动扩展（打雪仗的地基）
目标行为（验收看行为，不指定实现）：
1. **跳跃**：玩家可跳起越过约 1.1 m 的栏杆/栅栏（现全镇栏杆多为 1.1 m 高），落地沿用现有支撑语义；无摔落伤害（治愈系口径）。步高容差 0.43 m 的步行语义不得被跳跃改坏——已验路线（三条老路线 + 外环）在加入跳跃后须回归通过（Muse 复验）。
2. **过河**：玩家可从非桥位置下水过河——浅水涉水减速、深水可游，远岸能爬上岸（岸坡与步高容差衔接）。四桥仍是最快干路，过河是自由度不是替代品；冰湖活动区规则不受影响。
3. **投掷物物理**：雪球走抛物线、碰建筑/地面/人有碰撞判定（下条小游戏用）。
实现路线请你回方案时二选一并说明代价：A） 在现有碰撞数据上做定向物理（跳跃重力 + 投掷物弹道），改动小、不动已验移动内核；B） 引入物理引擎（如 Rapier——仓库旧 `src/` 运行时用过，有先例）全量接管，须评估与现有 floor/collider 数据的双写成本与回归风险。Muse 倾向 A 先行、B 留待道具互动真需要刚体时再议，但以你评估为准。

## 二、打雪仗（旗舰小游戏）
1. **积雪**：雪夜持续降雪时地面有可见积雪加深（视觉层即可：雪面抬升/覆雪加厚，成本走静态几何，不做逐帧模拟）；积雪是雪球的弹药来源——玩家在户外积雪处可"攒雪球"（数量上限自定，建议 10）。
2. **投掷与命中**：瞄准投掷，雪球抛物线飞行；命中玩家/NPC 时有明确打击反馈——雪花迸溅 + 受击者轻微顿挫/雪糊脸的屏幕边缘结霜效果 + 命中计数；无伤害、无击杀，只有计数与连击播报（沿用现有活动的金灯/公告口径）。命中判定要为联机预留：本地先行，但判定接口按"投掷者、时刻、落点"事件化，P2 联机时可平移服务端权威。
3. **NPC 参战（二期可选项）**：NPC 会回扔（简单弹道 + 命中率随距离衰减），让单人也能打起来；一期先做玩家对玩家/对 NPC 靶。
4. **性能红线**：雪球与迸溅粒子走附录的透明 overdraw 治理（移动档不用软粒子）；同屏雪球数量设上限；积雪加深不得增加每帧三角形（换贴图/抬升整体雪面网格皆可，禁止逐帧重建地形）。

## 三、验收（Muse 执行，先报口径）
- 跳跃：指定栏杆点 3 处可越过、已验路线回归全通；
- 过河：非桥断面至少 2 处可下水—对岸上岸全程走通；
- 打雪仗：攒球→投掷→命中静止 NPC/玩家替身，迸溅与计数生效；连击播报触发；四机位性能复测不破预算（calls ≤300、tris ≤150 万）。
