## 逐项落实（对诊断 §5）

### §5.1 失败可见化 + 一键重试 —— 已落实
- `desktop-look.ts`：新增可选第 4 参 `callbacks: DesktopLookCallbacks`。三条失败路径统一回调 `onLockFailed(reason)`，reason 为 `'unsupported'`（API 缺失）/`'rejected'`（Promise 拒绝或同步抛错）/`'error'`（`pointerlockerror` 事件）；锁定状态变化回调 `onLockChange(locked)`（在 `pointerlockchange` 里按状态翻转触发，不重复报）。请求逻辑抽成 `engage()` 并导出（供按钮与「第一人称」按钮复用），画布 `pointerdown` 的拖拽登记与原行为不变。
- `viewer.ts`：准心下方新增可点击 DOM 浮层按钮 `#lock-look`「点击锁定鼠标视角」（HTML +2 行；样式在 style.css 尾部追加块，`position: fixed` 于准心下方 26px、金色底与 `#world-action` 同色系、z-index 5；纯 DOM、零 GL）。显隐由 `refreshLockHint()` 统一管理：行走中且未锁定且非触屏时显示，锁定成功（`onLockChange(true)`）即隐藏，切回俯瞰隐藏。点击即 `desktopLook.engage()` 重试（按钮 click 是合法手势）。
- 帮助文案对齐：行走模式下只要未锁定，`#help` 不再写与状态矛盾的「点击画面后移动鼠标转向」，而是按状态切换——已锁定→原鼠标文案（抽为常量 `walkMouseHelp`，`mode()` 改为引用，文本逐字不变）；未锁定→`walkDragHelp`「当前为拖拽视角：按住左键拖动转向……点准心下方按钮可锁定鼠标视角。」；不支持→提示拖拽 + 建议改用 Chrome/Edge。

### §5.2 requestPending 防闩锁 —— 已落实
- `engage()` 发请求时同时设 1.5 s 定时器自动 `clearRequest()`；`clearRequest()` 一并清定时器，`pointerlockchange`/拒绝/错误任一先到都无副作用。无 Promise 返回且内核静默忽略请求的浏览器不再整场锁死。

### §5.3 Esc 冷却文案兜底 —— 已落实
- `viewer.ts` 用 `onLockChange(false)` 记录 `lastUnlockAt`；失败回调时若距上次退出锁定 <1.5 s，帮助文案改为「刚退出鼠标锁定，请稍等一秒再点画面；这段时间可按住左键拖动转向，WASD 行走。」。按诊断要求**不做无手势自动重试**，靠下一次点击（画布 pointerdown 或锁定按钮）重试。

### §5.4 切第一人称顺带锁定 —— 已落实
- `walk.onclick` 改为在真实 click 事件链内先 `mode(true)` 再 `desktopLook.engage()`，保住 transient activation；失败自动走 §5.1 提示。`selector.onchange`（选目的地进第一人称）未动：进入后点一下画面或点锁定按钮即可，文案此时已是拖拽口径，不再误导。

### §5.5 环境前置横幅 —— 已落实（按任务书口径）
- 面板 `<aside class="panel">` 顶部（h1 之后、复用面板既有结构，未新造框架）新增 `<p id="env-banner" hidden>`：「当前浏览器可能不支持鼠标视角锁定，建议复制链接到电脑上的 Chrome 或 Edge 打开。」

## 测试与检查（基线 → 改后）

- 新增单测（最小 fake DOM：FakeDocument/FakeCanvas 事件桩，`as unknown as HTMLCanvasElement` 注入，与 tests/ 既有风格一致）：
  1. API 缺失 → `onLockFailed('unsupported')` 且可重复尝试；
  2. Promise 拒绝 → `'rejected'` 且 pending 清除、再次点击重新发请求；
  3. `pointerlockerror` → `'error'` 且 pending 清除、可再 engage；
  4. 静默浏览器（请求返回 undefined、无任何事件）→ 1.5 s 后闩锁自动清零、再次点击重新发请求（实测等待 1.65 s）；
  5. 锁定/退出 → `onLockChange(true/false)`，锁定中 engage 为 no-op；
  6. `engage()` 待定时重复调用只发一次请求。
  结果：**6/6 通过**。
- 全量回归：Node 客户端套件 **98/98 → 104/104**；server 套件 **13/13 → 13/13**，零回退。
- tsc：根配置全量 72 → 73 个错误，唯一新增是新测试文件自己 import 行的 TS5097——与仓内全部既有测试文件同类的既有噪声（根 tsconfig 未开 `allowImportingTsExtensions` 而 tests/ 统一用 `.ts` 后缀导入）；**出厂源码文件零新增错误**。viewer.ts 依赖图定向 tsc（`--allowImportingTsExtensions` 口径）改前改后均为同 1 个既有错误（`landmark-tower.ts` 未用 `@ts-expect-error`，与本批无关），逐字一致。
- 打包：esbuild 直接 bundle viewer.ts 在基线与改后同样卡在既有 `.png` loader 缺失（CSS 引用的 snowball-impact-frost.png，真实构建由 vite 处理，非本批引入）；补 `--loader:.png=dataurl` 后改后图 bundle 成功（exit 0）。
