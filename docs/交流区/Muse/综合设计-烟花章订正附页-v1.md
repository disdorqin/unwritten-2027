## 附页正文（读作 §3.3 补 · 服务端校验裁决口径）

### 原口径

§3.3 原文：「放烟花者客户端发 `{type:'event', kind:'fireworks', seed, theme, startAt}`，**服务端原样转发（不模拟、不存状态）**，其余客户端在 `startAt`（服务端时间轴）按同一种子生成同一张表本地开演。」

### 现口径

服务端在转发前先做**准入裁决**，通过才广播；`startAt` 不再由放烟花者客户端给出，改由**服务端生成**。广播帧为 `{from, seed, theme, startAt}`（实现中 `startAt = Date.now() + 250`，服务端时间轴）。

**校验什么（准入层，共 6 项）**：

1. **站位**：申请人最近的位姿记录距任一烟花燃放点 ≤ **2.7 m**（server.ts:98-101；燃放点表在 `src/presence/firework-sites.ts`），超距拒绝——防异地刷放。
2. **全镇单场锁**：服务端维护 `fireworksOccupiedUntil`，一场未完时新申请拒绝（与客户端 `showActive` 锁构成双层，原稿 §3.3 的「全镇同时只许一场」由双层共同保证）。
3. **个人冷却**：服务端维护个人 **90 s** 冷却（server.ts:65、103-110），冷却内申请拒绝——原稿的 90 s 本地计时升级为服务端计时，本地计时与「烟花师傅在装填」文案保留作即时反馈。
4. **种子/主题格式**：`seed`、`theme` 在客户端与服务端两侧都过 `isFireworksSeed` / `isFireworksTheme` 校验，非法值不予广播。
5. **事件一致性**：同一事件只广播一次（去重），保证各端收到的是同一份 `{seed, theme, startAt}`。
6. **拒绝通道与能力标志**：拒绝时回 `fireworks-rejected` 消息（新增消息类型），客户端据此给文案（如站位拒绝的「请靠近烟花燃放点再试」）；`join` 应答带 `fireworks: true` 能力标志（server.ts:152），客户端据此知道服务端支持烟花事件。

**不校验什么（内容层，共 4 项，仍按原稿）**：

1. **不模拟粒子、不生成演出表**：服务端永远看不到 bursts；演出表由各客户端按 (seed, theme) 本地生成。
2. **不核对演出表内容**：服务端不验证任何一端的生成结果与种子是否吻合——一致性由纯函数构造保证（见下），不由服务端裁决。
3. **不存演出状态/历史**：服务端只在内存中保留锁与冷却的时间戳窗口，无落盘、无历史记录；进程重启即清（与 presence 全局「不存数据库、不写磁盘」纪律一致）。
4. **不管迟入与断联**：迟入者错过不补放（`launch()` 对 age ≥ duration 的场次拒绝）、presence 断开时退化为本地自放 + 本地冷却——均按原稿 §3.3 口径，未因裁决升级而改变。

### 与种子纯函数 / 广播一致的关系

- **确定性前提不变**：同一 (seed, theme) → 同一张表，由客户端纯函数 `makePlayerFireworksTable(seed, theme)` 保证（festival.ts:110-131，LCG 种子 RNG）。裁决层只决定「这一场准不准开始」，不碰「这一场长什么样」。
- **广播一致反而加强**：原口径的 `startAt` 由放烟花者客户端自报，各端时钟差直接变成开演差；现口径由服务端在广播时统一盖 `startAt`，全镇共用一个服务端时间戳，开演一致性不再依赖申请人客户端的时钟。
- **对接口径警示**：自本附页起，烟花事件通道的服务端是「校验裁决」而非「哑中继」。后续施工（P2b 事件层及任何复用此通道的设计）**不得再按「服务端原样转发」的假设对接**；新增事件类型若需要服务端准入规则（站位/锁/冷却类），按本附页的模式在服务端登记，若只需转发则在设计中明写「不裁决」以免默认套用。
