# 多窗分工总则（2026-11-18，Thomas 提议、Muse 定版）

> 一个仓库、一条集成线、**只有一个窗口能合、能部署**。其余窗口在自己的分支上造候选，造好送审，主窗口逐个合入并滚动。第 5/6 轮双线岔开的教训就是反面教材：谁都不许直接往集成线推施工提交，更不许自行部署。

## 角色与车道

**主窗口（集成官）**——现有窗口继续担任：
- 唯一写 `town-blockout-integration`、唯一部署、唯一维护发布台账。
- 独占文件：`viewer.ts` 总装接线、presence 服务端与协议、`layout.json` 登记、烟花/雪球等已验数值的改动。
- 自留批次：B1 收尾（服主跟随，已在飞）、B13 百门通（接线重，主窗口自建）。
- 职责：候选到一个验一个——合并 → 全量测试 → healthz 逐字核对 → 部署 → 回执；冲突按「协议从现役、内容从候选」裁。

**A 窗口（建筑线）**，分支 `lane-a-buildings`：
- 队列：B2a 广场一二期 → B2b 戏台融合 → B4 冰晶宫殿 → B9 精修收尾（含集市三摊与 NPC 驻位）→ B6 生肖余件。
- 只动建筑/地形/点位类文件；需要总装接线时在回执里写「接线申请」，主窗口接。

**B 窗口（系统线）**，分支 `lane-b-systems`：
- 队列：B3 雪橇（含翻滚）→ B5 寒意（含蹚河速冻与冻霜表现）→ 跌落反馈（全镇）→ B10 天气大雪 → B14 集市爆竹。
- 以新模块文件为主；动既有系统数值前在回执里先声明，主窗口核准后才合。

**C 窗口（仪式与内容线）**，分支 `lane-c-ceremony`：
- 队列：C1 零点传送 → C2 烟花大秀接线 → C3/C4 → B7 镇志三呈现 → B8 全图锚点 → B11 烟花扩充+酒馆二期（含喝酒细化）→ B12 皮肤。
- 仪式批的隔离纪律沿 C0 先例：测试服专用开关、正式构建 grep 证明。

## 铁律（所有窗口）

1. 开工先钉基线：回执第一行写明本批基于的集成头 SHA；基线过期（主窗口已滚新版）先变基再继续，不许在旧基线上堆活。
2. 只推自己的车道分支；**不许部署、不许碰集成线、不许改独占文件**（见上）。
3. 每批独立回执：基线、改动文件清单、接线申请、测试数、性能账（PC 线 450 draws / 2.2M tris）。
4. 卡住就跳过并标注（keep-going），不许死等；拿不准的冲突写进回执留给主窗口裁，不许自行合并他线。
5. 主窗口合并顺序按送审先后，急件由 Muse 在交流区点名插队。
