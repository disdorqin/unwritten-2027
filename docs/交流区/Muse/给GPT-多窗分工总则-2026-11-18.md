# 多窗分工总则（2026-11-18，Thomas 定为两窗版）

> 一个仓库、一条集成线、**只有一个窗口能合、能部署**。另一个窗口在自己的分支上造候选，造好送审，主窗口逐个合入并滚动。第 5/6 轮双线岔开的教训就是反面教材：施工窗不许直接往集成线推提交，更不许自行部署。

## 主窗口（集成官）——现有窗口

- 唯一写 `town-blockout-integration`、唯一部署、唯一维护发布台账。
- 独占文件：`viewer.ts` 总装接线、presence 服务端与协议、`layout.json` 登记、已验数值的改动。
- 自留批次（与施工窗任务量均分，详见《主次窗口任务划分》）：B1 收尾、B13 百门通、仪式批 C1–C7、B6 生肖、B7 镇志、B8 全图锚点、B11 烟花酒馆二期、B12 皮肤。
- 职责：候选到一个验一个——合并 → 全量测试 → healthz 逐字核对 → 部署 → 回执；冲突按「协议从现役、内容从候选」裁。

## 施工窗（新窗口），分支 `lane-build`

按序施工（任务量与主窗口均分后的队列，详见《主次窗口任务划分》）：
**B2a 广场一二期 → B2b 戏台融合 → B3 雪橇（含翻滚）→ B5 寒意（含蹚河速冻/冻霜表现）+ 跌落反馈 → B4 冰晶宫殿 → B10 天气大雪 → B14 集市爆竹 → B9 精修收尾（含集市三摊/NPC 驻位）**

- 建筑批只动建筑/地形/点位文件，系统批以新模块为主；需要总装接线或改既有数值时，在回执里写「接线申请/数值声明」，主窗口处理。
- BGM 全量版不在本窗队列（等 Thomas 耳审，另行派单）。

## 铁律（两窗共同）

1. 开工先钉基线：回执第一行写明本批基于的集成头 SHA；基线过期先变基再继续，不许在旧基线上堆活。
2. 施工窗只推 `lane-build`；**不许部署、不许碰集成线、不许改独占文件**。
3. 每批独立回执：基线、改动文件清单、接线申请、测试数、性能账（PC 线 450 draws / 2.2M tris）。
4. 卡住就跳过并标注（keep-going）；拿不准的冲突写进回执留给主窗口裁，不许自行合并他线。
5. 急件由 Muse 在交流区点名插队。
