## 1. 形象施工规格

### 1.1 设计依据（Muse 形象描述，原文存档）

> 「小未：体素方块风小羊。奶白色卷毛——用错落小方块堆出蓬松感，不要光滑球面；一对小金角，螺旋向后弯；脖子系一条红围巾，围巾角垂到胸前，挂一枚金色小铃铛；四只黑色小蹄子；短尾巴上翘；圆眼睛、嘴角上扬的开心脸；整体身高约 0.6 m（到玩家膝盖上下），头身比约 1:1.2，圆润敦实。识别点排序：金角 > 红围巾铃铛 > 奶白卷毛。」

识别点排序是施工优先级：远距离（>15 m）只剩金角与红围巾可辨，故金角的金色饱和度与围巾的红色面积不得为省件数削减；卷毛是近距离质感，件数可在 §1.3 的区间内浮动。

坐标口径：原点在四蹄落地面中心，+Y 向上，总高 ≈0.60 m。与 NPC 体素人同管线：逻辑件合并进几何、整体进 town-npc 单批次（主题稿 §6.1 口径：单批次内 +1 个体，draws +0）。

### 1.3 成本账

- **tris**：合并几何后目标 **1.2k–2.2k tris**（卷毛小方块只留外露面，内贴面在合并时剔除——与全镇体素合并同口径）。主题稿 §6.1 给小未本体 + 常驻角落的估算 ≈+600 tris 是平滑低模口径；本稿的卷毛错落堆法必然更贵，**以本稿区间为准并在形象验收时实测回填**，超出 2.2k 先减卷毛件数（从身体侧面下沿减起），不动金角/围巾/铃铛。
- **draws**：**+0**。小未与 NPC 同批渲染；跟随状态下也走同一批次（它是一个被网络状态驱动的特殊 NPC 个体，不是新渲染通道）。
- **常开开销**：动画为部件偏移预设（§1.4），每帧仅在小未可见且状态变化时重算其部件矩阵——照 P2b §3.3 脏标记口径，静止待机时零重算。

### 1.4 动画集（全程序化，无骨骼；部件偏移预设，数学照 town-npc `pose()` 先例）

## 2. 跟随机制

### 2.1 跟随对象认定

跟随对象 = **服主会话**，不是某个名字、不是某个客户端存档。认定链：服主在自己的客户端完成 §3.2 的口令验证 → 服务端在内存中把该会话标 `owner=true` → 跟随系统只认这个标记。服主换设备/换浏览器，只要重新验证即重新认定；服主会话断线，跟随即终止（§2.5）。名字可自选可冒名，与认定无关——这是红线，不许任何实现以名字符串判服主。

### 2.2 同步裁定（本节核心）

**裁定：跟随仿真放在服主客户端本地跑，小未的位置经 presence 同级通道以「虚拟演员」状态流广播，各端用既有插值管线渲染；不走主题稿的纯函数本地推演。**

理由（与主题稿 §6.2 不矛盾，分工不同）：

- 纯函数推演成立的前提是行为**只依赖共享时钟**（巡游时刻表、日期种子躲藏点）。跟随行为依赖服主的实时位置、寻路绕障、被雪球砸、上下车——全是交互反馈，纯函数推不出来；若各端各推一份，小未会在不同客户端差出数米（绕一栋房子就分叉），朋友间「小未在你脚边/在我这儿还在街口」的谈资就对不上。
- 服主客户端是唯一天然知道服主全部本地状态（地形采样、姿态、载具）的节点，由它跑跟随仿真（与玩家移动同一套可达面采样，§2.3），把结果当作一个额外演员的状态上报。服务端**不跑仿真**，只按兴趣集转发（与转发玩家状态同一段代码路径）。

实现口径：

- 小未占一个**保留演员 id**（`0xFFFE`，玩家 id 空间之外），状态记录沿用 12 B 二进制记录格式（东/北/高/yaw/seq），10 Hz、变更才发，与玩家状态同节拍同插值（120 ms 延迟 / 250 ms 外推，P2a 既有管线零改动复用）。
- 上行：服主客户端在自己的连接上多发一份小未状态（帧格式以「演员 id = 保留值」区分，服务端校验**只有 owner 会话可发保留 id 的状态**，他人伪造直接丢弃）。
- 花名册：join/welcome 的 roster 中小未以保留 id + 固定名「小未」出现，老客户端把它当普通演员渲染成默认小人——可接受的降级（老客户端本就不是发布目标）；新客户端按 id 识别并渲染羊模型。
- **带宽账**：小未 = 一个额外玩家的 presence 流量。上行 ≈12 B×10 Hz + 帧开销 ≈ 0.2 KB/s；下行扇出按兴趣集（80 m 内可见者，测试期 ≤8 人）≈ 1.6 KB/s 量级——在 P2b 负载方案 L3 总账（≈320 KB/s）里占 <1%，结论不变。
- 服主单人/presence 降级时（P2a 的静默单人模式）：跟随仿真本来就在本地，小未照常跟，只是没人看——零特殊处理。

### 2.3 跟随行为

- **跟随点**：服主身后侧方 1.6 m（偏左后 30°，随服主 yaw 转动并平滑趋近）；可接受距离带 1.2–2.5 m，带内停步待机。
- **速度**：步行跟随与服主同速（≤5.6 m/s 档内线性跟随）；间距 >8 m 切小跑，上限 **7.5 m/s**；间距 >30 m 或连续 4 s 无可达路径 → **重定位**：在服主 2 m 内可达点落位，配跳跃动画 + 雪沫（既有粒子池，+0 draws）；重定位落点须在任一旁观者 15 m 外或有遮挡时优先直落，不满足时也直落但加 0.3 s 雪沫遮掩——测试期朋友局不为此上复杂隐身逻辑。
- **寻路口径**：不引入导航网格。小未与玩家移动共用 `grid.surfaces` 1 m 可达面采样 + 墙体滑动（NPC 漫游的现行做法）：只走可达面（道路/广场/室内地面/冰面/浅雪），不进深水、不上屋顶、台阶容差与玩家同（0.43 m）。半径 0.18 m（比玩家 0.27 m 小，能过玩家能过的全部缝隙还富余）。
- **载具与特殊状态**（逐一口径）：
  - **乘火车（pose 5）**：小未随服主上车——服主 boarding 成立时，小未重定位到同车厢的宠物位（车厢内靠门固定偏移点），坐下姿态；下车时回到跟随点。不许出现小未在轨道上追火车。
  - **乘雪橇（pose 7）**：雪橇极速 17 m/s，小未跑不过——**骑乘**：服主上橇时小未跳进橇前筐位（橇体附着偏移），坐姿 + 围巾飘动件摆幅加大；下橇恢复跟随。
  - **滑冰（pose 3）**：小未上冰跟随，速度上限降为 4 m/s 并带滑步预设（腿少摆、身体惯性滑移），出冰恢复。
  - **游泳/深水**：小未不下水，停在岸边最近可达点坐等，服主回到 30 m 内恢复跟随（超距重定位只落在岸边可达点，不落水）。
  - **进屋舍室内（口袋坐标）**：presence 在口袋内原样工作（综合设计 §1.5），跟随不间断：服主过门后，小未延迟 ≈1 s 在室内门内侧落位（模拟它自己钻进来），出门同理。跟随仿真在服主客户端跑，坐标系随服主切换，无服务端补件。
  - **服主就座/泡汤**：小未在座位/池边 1.2 m 内停留，>5 s 坐下（§1.4）。
- **不挡动线**：跟随点偏移避开服主正前方与交互朝向；小未无碰撞体（玩家可穿过，与 NPC 同口径），不触发任何热点。

### 2.4 与主题稿行为的共存（状态机）

小未全局状态四选一，优先级从高到低：

1. **跟随**（服主在线 && 验证通过 && 跟随开关开）：本节 §2.3。
2. **找领头羊·躲藏**（当日躲藏未被找到 && 非跟随）：主题稿 §4.1，日期种子选点，纯函数。
3. **巡游**（整点出发的环线，纯函数时刻表）：主题稿 §1.1。
4. **常驻待机**（其余时间）：许愿树下常驻点，吃草/打盹。

共存细则：

- **找领头羊与跟随不互斥**：被找到的判定改为**距离制**——玩家与小未当前实际位置 ≤2 m 即触发「找到啦」（任何状态下成立）。跟随日就是「小未陪着镇长」的易找日：公告板「今日」格文案随状态切换（「小未今天陪着镇长散步」级，文案归内容线）。这样跟随永不毁掉当日打卡，躲藏只在服主缺席时才是真躲藏。
- 状态切换全由各端按同一规则本地判定（跟随状态由 presence 中小未演员在/不在场 + §3 的模式广播决定，其余由共享时钟/日期种子决定）——除跟随流本身外不新增同步。
- 跨年夜 23:50 见证位（主题稿 §3.1）：若当晚服主开着跟随，小未以跟随优先，见证位由「它在服主身边」自然替代——仪式 cue 表不为此改（它在场即可，站位不进 cue 判定）。

### 2.5 服主离线/关跟随

- 服主断线：服务端停止转发保留 id 状态，各端在小未样本过期（沿用 250 ms 外推上限 + 2 s 宽限）后，把小未切回本地纯函数行为：就地淡出不可取——口径为小未**小跑向最近的巡游线/常驻点方向并在离开所有客户端视野或 20 s 后**交还本地推演。简化实现可先做「2 s 后原地雪沫重定位到常驻点」，验收时按双端一致性判定（两端同一时刻起本地推演同一函数，结果一致即可，过程不做硬性要求）。
- 服主关跟随（§3.3 a 项）：小未执行同样的交还流程，回主题稿行为。

## 3. 服主权限体系

### 3.1 总原则

- 权限只挂在**服务端内存里的会话标记**上，连接断开即消失，不落盘、不跨会话（每次进镇重新验证，一次输入、本地保存凭据，见 §3.2——玩家无感）。
- 全部服主指令走一条新 JSON 消息型 `owner`（P2b E1 事件层的 JSON 家族同通道），服务端逐条校验 `session.owner`，非服主发送直接丢弃并计数（防探测：不给差异化报错）。
- 每项权限给冷却（§3.3），防手滑与防刷屏优先于功能丰富度。

### 3.2 验证方式（裁定）

**裁定：服务端环境变量 `OWNER_KEY` 存服主口令原文（仅服务端）；客户端在控制面板输入一次，口令只存服主自己设备的 localStorage（键 `unwritten.presence.owner.v1`），进镇 join 后服务端先发一次性随机数挑战，客户端回传 `sha256(口令 + 随机数)`，服务端以同样方式算出比对，通过则标记本会话。口令明文永不上行、永不广播、永不出现在任何日志与花名册里；其他客户端只知道「该会话是服主」这一个布尔（用于 §3.3 d 的呈现）。**

- 为什么不用名字：名字自选、可冒名（今晚测试已实证名字只是 localStorage 自填），以名认人等于无验证。
- 为什么哈希证明够用：朋友测试服的威胁模型是「朋友手滑/好奇试错」，不是密码学攻击；一次性随机数使录包重放无效。口令强度要求 ≥10 字符（面板提示），`OWNER_KEY` 只出现在服务器 compose 环境里——与既有部署纪律一致（朋友的服务器、GPT 经手部署，口令由 Thomas 经 GPT 部署通道注入，不进仓库、不进交流区文档）。
- 失败口径：证明不对 = 普通游客会话，无提示差异（面板仅在服主自己一侧显示「未验证」小字）；连续 5 次失败，该连接 10 分钟内不再受理挑战（防在线试口令）。

### 4.5 不撞款纪律（NPC 优先）

- NPC 的皮肤是**角色身份证**（玩家靠服装认人：罗大江、苏小满……及后续新增六人、集市摊主、宫殿礼仪官）。玩家目录**永不**复刻任何 NPC 的（主色 + 标志件）组合；新 NPC 上线时若与玩家某款相近，改玩家款（玩家款是目录数据，改成本低）——此为长期纪律，写进目录维护口径。
- 玩家之间的共同识别靠星徽围巾 + 名字牌（P2a 设计 §6 原口径），不靠服色唯一性：两人同款合法，靠名字区分。
- 小未的（金角 + 红围巾 + 金铃铛）组合是吉祥物身份证：玩家金羊款的角形/铃铛做**缩小版**且服色奶白无卷毛件——同框时一眼分清「羊」和「穿羊装的人」。

### 4.6 面板与存档键

- **选肤 UI**：进镇面板（现有昵称框同面板）在昵称行下加皮肤格：8+4+（服主 1）格色块横排，点选即换；未解锁格显示灰态 + 条件小字（「集齐 12 生肖」级一句话）。进镇前可选，进镇后在控制面板改**即时生效**（走 §4.7 的 style 消息，不用重连）。
- **localStorage 键规划**（沿现行点分命名，与 `unwritten.presence.name.v1` 同族）：
  - `unwritten.presence.skin.v1`：当前皮肤 id（数字）
  - `unwritten.presence.owner.v1`：服主口令（仅服主设备，§3.2）
  - 解锁标记键见 §4.3 两行；金羊/冰晶冠不落新键（读寻宝/宫殿存档推知，避免双账）
  - 头饰件（羊角头箍等 gear）沿主题稿 §5/§6 的 gear 粘性字段口径，不并入 skin id——skin 管服色与围巾，gear 管头上戴什么，两轴正交（主题稿 §4.2 已定头箍与 palette 正交，本稿沿用）。

### 4.7 presence 同步与兼容

- **join 附带**：join JSON 恢复 P2a 原始设计的 skin 字段——`{name, skin}`（skin u8 语义装在 JSON 里，**12 B 二进制状态记录一字节不动**）；服务端存 `peer.skin`，随 roster/join 转发（与 pose 的 join 附带同一机制，P2b §3.1 先例）。
- **中途换肤**：粘性 JSON 状态消息 `{type:'style', skin}`（与 pose 同族：变化时发、服务端存、新人 join 时随 roster 带出）；接收端换着色表即可，**不重建化身**（部件几何不变，只换材质槽颜色 + 头饰件显隐——脏标记重算一次该化身矩阵与着色）。
- **字节账**：join +≈10 B 一次性；style 消息 ≈40 B/次，换肤是分钟级低频——带宽可忽略，不进负载方案修订。
- **兼容**：老客户端不发 skin → 服务端默认 0 号（雪原白），与现行 id%4 观感不同但不报错；老客户端收到 roster 里的 skin 字段按未知字段忽略（P2b 已立的兼容先例），其眼中所有人 = 它自己的默认渲染。服务端不做版本门控。

### 5.3 验收清单（双客户端实测为纲）

1. **吉祥物一致性**：双客户端同屏看跟随中的小未，任意时刻位置差 ≤0.5 m（与化身同步 RMS 同口径）；服主绕一栋建筑急转，两端小未走同一侧，不分叉。
2. **跟随全状态**：服主依次步行/疾跑/上火车/上雪橇/滑冰/进屋舍/泡汤——小未逐项按 §2.3 口径在位；服主断线，另一端小未按 §2.5 交还本地行为且两端（含重连后的服主端）位置语义一致。
3. **服主验证**：错口令进镇 = 普通游客（面板无镇长区、发 owner 指令被静默丢弃）；对口令 = 镇长区展开；抓包检查全程无口令明文（只有哈希与随机数）。
4. **权限逐项**：a 召唤 10 s 内二次点无副作用；b 广播金色置顶两端同显、30 s 内第二条被限频；c 烟花两端同种子同启、10 min 内不可再点；e 踢人后目标可重新进镇、禁言期间其聊天两端均不可见而位置可见；f 召集令光柱两端同位、无人被传送；g 彩排 cue 带「彩排」标、bell 两端同响。
5. **冒名防线**：普通玩家改名与服主同名——无金名牌、无头衔、owner 指令无效，三项全过才算 d 项达标。
6. **皮肤互见**：A 依次换 8 基础款 + 已解锁款，B 端逐款对应（延迟 ≤1 s）；A 中途换肤 B 端不闪烁重建；B 中途入镇，首见 A 即为当前款（roster 带出）；老构建客户端进同一服：不报错、其眼中全员默认款、新客户端眼中它为 0 号款。
7. **不撞款目视**：六名 NPC + 集市摊主与 13 款玩家皮肤同屏截图逐一对照，无（主色+标志件）全同组合。
