# 酒馆饮酒特效设计 v1（Muse，2026-11-18）

Thomas 点名：调酒要喝出效果——喝完有眩晕感，酒馆的椅子能坐。排在多人 P2a 上线之后实施，不插队。

## 一、饮酒流程衔接

- 现有调酒活动（tavern-activity）产出饮品后，玩家可「饮用」：举杯动作（沿用活动姿态）→ 杯空状态 → 触发饮酒计数与眩晕。
- 每杯下肚记 1 个「酒意」单位；酒意随时间衰减（建议 1 单位/45 秒），喝热水/温泉泡汤可加速消退（与现有系统联动，不新造道具）。

## 二、眩晕效果（纯本地表现）

分级（按当前酒意）：
- **1 杯 · 微醺**：镜头极轻微摆动（正弦 roll ±0.4°，周期 ~2.4 s），无其他变化。
- **2 杯 · 上头**：摆动加重（roll ±0.9° + 轻微 yaw 漂移），屏幕边缘 DOM 暗角叠层淡入，走路时摆动幅度 ×1.5。
- **3 杯及以上 · 封顶**：摆动封顶不再加重（roll ±1.3°），暗角加深，偶发 0.3 s 轻微 FOV 呼吸感；不再往上叠，避免晕动症与不可玩。

实现纪律（硬性）：
- 只用相机变换 + DOM 叠层实现，**零新增 WebGL 绘制、零新粒子系统**；每帧成本 ≤0.05 ms（仅几个三角函数）。
- 与雪球命中的雪糊+震屏明确区分：命中是短促外力反馈（0.4–0.6 s），眩晕是持续状态效果，两套参数不共用。
- 设置里可一键关闭眩晕（无障碍）；关闭后只保留暗角提示酒意等级。

## 三、酒馆座椅可坐

- **复用现有长椅 sit/stand 框架**（扩展精修已落地 51 条长椅的坐/站），不新造系统：GPT 按酒馆家具清单把吧凳、酒馆椅逐件登记为可坐点（坐高、朝向吧台/桌面）。
- 坐下时可正常饮酒、与 NPC 对话；站起恢复行走。坐姿与座椅碰撞沿用长椅同款口径。
- 落位清单由 GPT 从酒馆实际家具生成，回执里报数量与坐标，Muse 抽验。

## 四、与多人的关系

- 眩晕纯本地：别人看不见你的镜头效果。
- 「醉步摇晃走姿」与坐姿同步属 P2b 姿态同步范围，本期不做，P2b 设计时一并纳入（喝了酒走路发飘让朋友看见才好玩，但不在本单内）。

## 五、验收标准

1. 连喝 3 杯：眩晕分级与封顶如设计，衰减后完全恢复，无残留摆动。
2. 帧成本实测 ≤0.05 ms/帧，draw calls 增量 0。
3. 酒馆全部吧凳/椅可坐可站，坐下饮酒、对话不穿模、不卡位。
4. 关闭眩晕设置后无任何镜头摆动。
5. 与雪球命中同帧触发时两者不互相污染（命中反馈照常、眩晕计时不被重置）。
