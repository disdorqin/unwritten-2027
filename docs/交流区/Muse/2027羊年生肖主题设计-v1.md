# 2027 羊年生肖主题设计 v1（Muse，2026-11-18）

Thomas 定调：2027×生肖的结合是**重中之重**。本稿定主题层——概念、吉祥物、视觉母题、与寻宝/仪式/集市/装扮的结合口径、三段时间线与成本施工。逐件藏点以《生肖寻宝落地设计-v1》（在写）为准，人设台词归内容线，施工以仓库实时头为准。

## 0. 核心事实与概念论证（先把巧合说透）

**三个「未」在 2027 年相遇，这是本主题的全部根基：**

1. **镇名之「未」**：小镇名「未写镇」（UNWRITTEN），站名「未写镇站」已定版（《站牌文案-v1》，常量 `TOWN_STATION_NAME`）。「未写」= 尚未写完的故事。
2. **年份之「未」**：2027 年是农历**丁未年**，地支「未」对应生肖**羊**。丁未羊年自 **2027-02-06（正月初一）** 起，至 2028 年春节止。
3. **开镇之时**：小镇 **2026-12-31 20:00 开镇**，跨入公历 2027 年；此后有春节扩展期（灯谜节日组已核日期：除夕 2027-02-05、春节 02-06、元宵 02-20 等）。

**关键口径（日历诚实，不许含糊）**：跨年零点（01-01 00:00）按农历仍在丙午马年内（仪式稿已据此把广场主冰雕定为骏马）。所以本主题的时间叙事是**「迎未」而非「已是羊年」**：

- 12-31 零点 = 公历 2027 到来，小镇**迎**它的本命年——金羊在这一刻揭幕，是预告、是彩头；
- 01-01 ~ 02-05 = 「迎未期」，羊年元素渐次铺开；
- 02-05 除夕夜 = **送马迎羊**的正式切换点，广场主冰雕由骏马换金羊，羊年主题全量转正；
- 02-06 起 = 丁未羊年本体，主题进入春节形态。

一句话概念：**「未写镇等了一年，等到了未年。」** 镇名里的「未」不是巧合事故，是这座镇子生来要过的第一个本命年——所有主题文案、仪式节点、寻宝压轴都挂在这句话上（文案终稿归内容线，本稿只定概念与落点）。

### 1.2 视觉母题：羊角纹 + 未字纹

两个母题，全镇共用一套画法，进**共享标签图集/既有批次**，不新开绘制管线：

|---|---|---|
| **羊角纹**（盘羊角螺旋卷纹，方角化处理以适配体素与图集像素） | 一对镜像螺旋 + 中轴短竖，单色线纹；图集内一个母题格，各载体按格取用 | ①广场灯笼柱阵的柱身纹带（仪式稿既有柱阵，加纹带变体）②旗幡/幌子的**下缘边纹**（仅羊年限定摊与节日旗，见下）③站牌纹样（见下）④护照印章（见 §1.2 末） |
| **未字纹**（「未」字本身作纹样，楷体，与 town-new-year.ts 春联同字体口径） | 单字入圆/入方两种框式 | ①灯笼面字（灯笼标签变体：红灯笼印金「未」字，春节期限定批）②集市限定摊幌子主字旁的小字印记 ③许愿树许愿卡的落款印（DOM/纸卡纹理变体） |

**与既有文案体系的不冲突规则（硬性）**：

- **站牌**：《站牌文案-v1》定版文案**一字不改**。羊角纹只以「牌框角花」形式出现在站房大字牌与进站口牌的纹理边框上——这是图集纹理变体，不是文案变更；施工时在回执登记为纹理变体，若内容线否决角花则整项撤除、站牌保持原样（已列为冲突项 C4，§2.4 同表登记）。
- **集市幌子**：《集市幌子文案-v1》9 摊种的主字/副文一字不改；羊角纹边只加在**羊年限定摊自己的幌子**上（§4.2），既有 9 摊幌子不加纹、不换色。
- **旗幡**：镇内既有旗幡不追改；只有春节期新挂的节日旗（广场灯带圈与集市灯笼街）用带羊角纹边的变体。

**护照页**：`town-passport.ts` 既有「扩展收集页」加一枚**「未年」主题印**：护照封面页（进度页）右下角一枚羊角纹环绕「未」字的印章图样，集齐生肖后印章由灰转金（§2.3）。实现走护照既有 DOM/seal 渲染（`.passport-seal` 现行样式族），零 GL。

### 1.3 色彩纪律：金羊点缀，别俗

- **金色只出现在五处**（定版清单）：①金羊挂件本体（§2）②跨年树顶金羊（§3.1）③小未的金铃铛 ④羊年限定摊幌子的边纹与小字印记 ⑤护照「领头羊」印章的转金态。清单外任何元素不得用金色——尤其不许金色大面积铺底、不许建筑描金、不许灯光改金色调。
- **金色的做法**：沿用既有 luminous 顶点色发光口径的**单一暖金色值**（施工时与冰雪城堡 L1 发光本色同批定值登记），不用渐变金、不用金属质感贴图——体素小镇的金是「一点亮晶晶」，不是「金碧辉煌」。
- **用量感口径**：任一标准视角内金色元素应为「一眼能数完的几个点」。验收时以广场、集市、城堡三机位目视核查，超标即回滚到清单内。
- 其余色彩不动：全镇既有红（灯笼/春联/幌子）、白（雪）、冰蓝（城堡/冰雕）三色体系保持，羊年主题是往这套体系里**加一个点**，不是换一套。

## 2. 寻宝结合：压轴金羊

### 2.1 羊件升格：从普通件到压轴件

《生肖寻宝藏点规划-v1》里羊件是 12 件中的普通一件（藏于北坡坡顶，线索「一只白羊卧雪坡，爬到坡顶才见它」）。本稿将其升格为**全寻宝的压轴件「金羊」**：

- **本体**：羊挂件的金色变体（同挂件图集/实例批次，贴图换金羊变体 + luminous 微光口径，仍是一实例批次内的一件，不涨 draws）；
- **位置**：**冰雪城堡宫殿宝物间**——冰冠陈列旁的专属展座（宫殿稿 §1.5 密室 4 宝物间：冰冠陈列 + 毕业照点 + 宝物轮换藏点 B）。金羊与冰冠同室：一个是宫殿探索线的终点凭证，一个是全镇寻宝的终点件，两条线的终点在同一间屋子里相遇——这是有意的收束设计，不是巧合堆叠；
- **与宫殿宝物轮换的关系**：宝物间原有「宝物轮换藏点 B」（冰冠/权杖周轮换，宫殿稿 §1.3）与金羊**并存不互替**：轮换宝物是宫殿内部收集，金羊是生肖收集，两个展座、两套进度（金羊走护照生肖页，轮换宝物走 `unwritten.ice-palace.v1`），互不门控。

### 2.2 门控口径（双层，都单人可达）

| 层 | 口径 |
|---|---|
| **线索门控（主题层，本稿定）** | 护照生肖页中羊格自始即**封印态**：格内是羊角纹环绕的「未」字印 + 一行「未年压轴 · 集齐其余十一件后开启」。线索页签里羊的线索**不显示**（其余 11 件照常）。集齐其余 **11 件**的瞬间：封印解开（生肖页一次解封动画/DOM 表现即可）+ 全镇公告一行（announce 通道：「十一件已齐，金羊现身——」级文案，终稿归内容线）+ 羊的正式线索揭示。正式线索指向宫殿而非北坡（谜面终稿归内容线，方向口径：冰宫深处、王座之侧） |
| **到达门控（宫殿线，既有）** | 宝物间本身要走完宫殿密室链（迷宫取冰钥匙 → 王座后密室 → 画廊双机关 → 塔楼梯下敲钟 → 限时门 + 二次验钥，宫殿稿 §1.5/§1.6，全单人可解）。金羊不另加门：能进宝物间的人，就能拿金羊。两层门控叠加的效果：**集齐 11 件是「知道去哪」，走通宫殿是「到得了」**，缺一不可，但都不需要第二个人 |
| **小未的角色** | 解封后，小未的对话多一段「金羊提示」（给方向感：往东、冰宫、王座旁——不给坐标，沿用寻宝线索纪律）；未解封时问它只摇头（内容线供俏皮话，不剧透） |

## 3. 仪式结合

### 3.1 零点揭幕：推荐「跨年树顶金羊点亮」

仪式稿 §3.4 cue 表 T+0 的第一光是**跨年树树顶星**全亮。本稿在二选一（树顶金羊点亮 / 广场金羊冰雕）中**推荐树顶金羊**，理由四条：

1. **改动最小、位置最正**：cue 表 T+0 第一光的载体已经存在（树顶星，[208,198] 跨年树顶）。把树顶饰件由「星」换为「星托金羊」（金羊立于星芒之上的一件 luminous 小件，并入跨年树批次），T+0 第一亮的语义就从「星亮了」变成「未年金羊亮了」——cue 表其余时序（大敲、波纹、烟花）一字不动。
2. **历法诚实**：零点仍在马年内，地面主冰雕必须是马（C5）；树顶的金羊是高处的一个**预告信号**（迎未），体量小、位置高、语义是「来了」而不是「已到」——与 §0 的迎未叙事严丝合缝。若在地面立金羊主雕，则与马雕双主并立，叙事打架。
3. **暗场可见性**：T−10 ~ T+0 全场渐暗至 3 成、只留跨年树与钟楼轮廓——全镇唯一的光源高点就是树顶。金羊在那里亮起，是全镇任何角落抬头都能看见的一眼，冰雕在地面做不到。
4. **金羊冰雕不浪费**：它不在零点出场，而在春节切换点接棒广场主展位（§3.2）——有自己的高光时刻，不与零点抢。

**cue 表增补（只加一行，其余不动）**：

| 时刻 | 增补 |
|---|---|
| T−10 s ~ T−1 s | 跨年树顶金羊为暗影轮廓（未亮），小未在树旁见证位（§1.1） |
| **T+0** | **树顶金羊先亮**（暖金单色，luminous 全亮）→ 树身灯串随既有 cue 全亮（金羊比灯串早约半拍，即 cue 表「树顶星先亮」的原口径换载体） |
| T+30 s 后余韵 | 金羊保持常亮至仪式结束；此后至春节期，树顶金羊每晚亮灯时随树亮（迎未期的日常形态） |

单人版同 cue 表本地时钟走（仪式稿 §5 既有口径），金羊亮起不依赖服务端。

## 4. 玩法结合

### 4.1 日常小事件：「找领头羊」

- **玩法**：小未每天躲一处（不在常驻点时即在躲藏点）。玩家在镇里找到它（走近触发热点「找到啦！」）→ 当日打卡成功，护照扩展页「找领头羊」格盖当日印（DOM 印章，一日一格，样式为小羊蹄印/羊角纹小印，走护照既有 seal 渲染）。
- **躲藏点**：候选点清单制——12 个候选点（与全图锚点咬合：各区锚点旁的安全角落，如集市北巷口、钟楼下、温泉石灯旁、城堡南门、湖畔、站台一角等；逐点由落地/全图批施工时按可站立与不挡动线口径核定登记）。**当日躲藏点由日期种子确定性选出**（日期字符串哈希 → 候选序号），全员同一天同一处（§6.2），先找到的人可以在聊天里给朋友报信——这是给联机日常留的天然话题。
- **提示**：公告板「今日」格多一行小未状态（「小未今天不在家」级提示文案，归内容线）；问镇上 NPC 可得方向性提示（远近口径：「往水边去了」级，不给坐标）；小未被找到后回常驻点，当日不再躲（状态由日期+本地 flag 决定，不需服务端）。
- **收集口径**：印是**个人进度**（localStorage，沿用护照/寻宝的个人进度原则——多人各盖各的，不抢）。集满 **7 枚**当日印 → 护照「找领头羊」页满格纪念（页面转金边 + 一段小未专属对话解锁，内容线供稿）；不设实物奖励、不设货币——它的定位是每天进镇的一个小理由。
- **与巡游的关系**：躲藏日小未不巡游（巡游表按「当日是否已躲藏」分支，仍是纯函数）；被找到后当日恢复常驻+巡游。

### 4.2 集市羊年限定摊

- **摊种定版**：新增限定摊种**「未未手作」**（第 10 种，限定种，不进 9 摊种常设表）——卖（无货币口径：以互动领取/小游戏换取）羊毛毡小羊、未字挂饰、**羊角头箍**（§4.3 的获取主路径在此）。摊主 NPC 留位（人设台词归内容线，与集市三摊主同规格留位登记）。
- **吃食口径**：限定摊兼一个吃食位——「羊汤暖锅」（热饮/吃食类的羊年变体：到摊互动得一碗热羊汤，接 frost 的 hot-drink 回暖通道，与温泉茶点、酒馆热饮同口径）。吃食只做这一样，不扩菜单。
- **落位**：集市扩建 v2 的**前广场特色摊区**预留一摊位（与春联年画西角、套圈东角同排，扩建稿批 2 成街时一并落位）；跨年夜当晚，它以**广场东缘限定摊**形态在广场开张一夜（仪式稿 §1.2 东缘限定摊位 2–3 摊的第三摊：热饮、糖葫芦之外的主题摊），初一起回集市落位转春节正式形态（§3.2 第 4 项）。
- **限定期**：跨年夜（12-31 晚）预览开张 → 迎未期（01-01 ~ 02-04）只在周末开（牌面写明，机制上按日期门控热点）→ 春节期（02-05 ~ 元宵 02-20）全量开 → 元宵后收摊，摊位几何保留作集市常设空摊/换季摊（不拆除，下一季复用）。
- **幌子**：主字「未未手作」、副文归内容线按《集市幌子文案》体例供稿；这是全镇唯一允许带羊角纹边的幌子（§1.2）。

### 4.3 玩家装扮：羊角头箍

- **物件**：一对小弯羊角的头箍（体素低模：发箍弧 + 双角螺旋简化体），玩家化身头部的**附加部件**。
- **获取**：主路径 = 集市限定摊「未未手作」互动领取（限定期内，一人一份，flag 落本地存档）；备选路径 = 「找领头羊」集满 7 印后找小未领取（错过限定摊窗口的人有补票口径）。两条路都无货币、无门槛竞争。
- **呈现与同步**：化身渲染 `town-presence-avatars.ts` 为单 InstancedMesh、22 部件/人（P2b 稿实测）——头箍作**第 23 部件（头部附件槽）**，只对已装备的化身实例化该部件（实例数按在场装备者数，不装备不占）。同步走 P2b 姿态的**粘性 JSON 通道同法**：新增 `gear` 粘性字段（join 时服务端存、向新人补发、变化才发），**不改 12 B 二进制记录**（P2b 稿已定记录占满、无空闲字节——本稿不挑战此口径）。单人/第一人称下本人不可见自己头箍（现状视角口径），拍照点/第三人称呈现与他人视角正常——这是它的主要秀场，设计上接受。
- **与外观体系的关系**：头箍与 P2a 的游客配色（4 种 palette）正交，任意配色可戴；NPC 不戴（小未戴的是金铃铛，玩家戴的是羊角——识别不混）。

### 6.2 吉祥物巡游的同步论证（NPC 本地原则是否适用）

**结论：适用，且不需要为小未开任何同步例外。** 论证三层：

1. **NPC 本地原则的现状**：全镇 NPC 状态不进 presence、各客户端本地演算（P2a 既定，宫殿礼仪官、酒馆诸人皆然），其隐含前提是「NPC 在哪儿」不影响他人玩法判定。
2. **小未的特殊性**：巡游与躲藏是**可被玩家间谈论的位置信息**（「小未今天在湖边」），若各客户端各算各的，朋友间的信息就对不上——这是它与普通 NPC 的唯一区别。
3. **解法是确定性而非同步**：小未的位置做成**共享时钟的纯函数**——巡游时刻表（几点在哪段路上）与躲藏点（日期种子选点）都只依赖全员一致的时间源（多人走服务端仪式时钟通道、单人走本地时钟，与列车班车制、仪式时钟同一先例）。每个客户端独立算出同一位置，**零协议、零服务端状态、零新增带宽**，且断线/迟入天然一致（列车已验此口径）。玩家侧的进度（找到没找到、盖印）是个人本地状态，与位置函数无关。
   - 边界：纯函数要求巡游不依赖玩家交互反馈（不能「被围观就停下」这类状态机）——小未的停顿点写进时刻表本身（到点停、到点走），交互只触发本地对话，不改路线。此条为施工红线。
