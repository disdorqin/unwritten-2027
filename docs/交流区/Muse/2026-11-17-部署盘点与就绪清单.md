## 2. 构建验证（本地实测，2026-11-17）

环境：本地工作副本 `~/workspace/unwritten-7a252f8/voxel-tavern`（Node v24.22.1），
命令与仓库口径一致：`node build-tavern.mjs` → `npm run build`（vite 6.4.1 生产构建）。

- 构建成功（16.7 s，201 modules）；产物哈希与 A4 第二轮 F 路独立构建**逐一相同**
  （townBlockout-DSB-u3r3.js 等），构建可复现。
- `dist/` 总计 **2.8 MB**，文件构成：2 个 HTML + 10 个 assets（JS/CSS/worker），自包含、无外部资源引用。
- 入口确认：`dist/town-blockout.html`（3.88 kB）存在，引用
  `/assets/townBlockout-DSB-u3r3.js`（486.81 kB / gzip 225.86 kB）、
  `/assets/three.module-Dz5I0p9O.js`（599.23 kB / gzip 153.18 kB）、CSS 10.60 kB（gzip 3.10 kB）。
  镇页首屏下载约 **gzip 384 kB**（不含按需 worker：mesh 381 kB、light 104 kB，运行时异步加载）。
  酒馆样板 chunk（tavern-*.js 1,189 kB）只被 index.html 引用，**镇页不加载**。
- 静态托管冒烟实测：本地静态服务器托管 dist，`/`、`/town-blockout.html`、主 JS、CSS 均 200。
  注意资源为 `/assets/` **绝对路径**，必须托管在站点根，不能挂子路径——部署包 Caddyfile 按根托管，
  且把 `/` 重写到 `/town-blockout.html`（否则访客先落到酒馆样板 index.html）。
- **构建上下文坑（必须知道）**：`town-blockout/town-railway.ts` 以相对路径
  `../../../docs/p0-layout-draft.json` 引用仓库根 `docs/` 的文件；只打包 tools/voxel-tavern 子树
  构建必失败（F 路首跑实测报错）。部署包 Dockerfile 因此以**仓库根为构建上下文**并显式拷入该文件。
- 本地无 Docker，`Dockerfile.townsite` 未做镜像级实 build；其构建命令与上述已验证命令逐条等价
  （npm ci --ignore-scripts → build-tavern.mjs → vite build，参数取自仓库 README 口径），
  镜像级验证留待服务器首次执行 deploy.sh 时由健康检查兜底——此点如实标注，不算已验证。

## 3. 部署包与既有预备的差异（以既有为准的例外及理由）

| 项 | 既有预备 | 部署包 | 理由 |
| --- | --- | --- | --- |
| 托管对象 | 根 Node 应用（旧运行时） | 新小镇静态 dist | 本次"拉人"看的是新镇；既有对象是旧入口（PLAN 42 行自认针对旧方式） |
| Caddy 行为 | reverse_proxy town:3000 | file_server 静态托管 + 根路径重写到镇页 | 静态镇无后端进程；旧反代配置原文保留（Caddyfile.nodeapp） |
| 健康检查 | GET /healthz（Node 判别端点） | HTTPS 200（/ 与 /town-blockout.html）+ 公网验收清单 | 静态站没有 /healthz，强行用它会误判（deployment.md 自述 CDN/静态下 /healthz 为 404 属正常） |
| 数据卷 | letters（信件）等三卷 | 仅 certificates + caddy_config 两卷 | 静态预览无服务端信件；证书卷命名与既有版一致，切换回 Node 方案时证书可复用 |
| 构建位置 | 服务器上 docker build | 默认服务器构建（静态构建较轻，实测 17 s 级），并注明备选 | PLAN §6 主张构建环境编译后上传产物——见第 5 节备选路径，上线赶时间时可切换 |

## 5. 备选路径（主路径受阻时）

- **服务器拉不动私有仓库**（无凭据）：按 PLAN §6 口径，本地/构建环境跑生产构建，
  只把 `dist/`（2.8 MB）打包上传到服务器，用 caddy:2-alpine 镜像 + 部署包 Caddyfile 直接托管
  （compose 去掉 build、改为挂载 dist 目录）。产物与主路径逐字节相同（构建可复现已验证）。
- **服务器构建内存吃紧**（2 GB）：同上，改走上传产物路径；静态托管本身内存占用极小。
- **443 迟迟未放行**：可先用 80 上线 HTTP 预览验证内容，但**不得作为拉人正式链接**
  （无 HTTPS 时浏览器对麦克风等能力有限制且观感差），仅作临时自查。

## 7. 服务器容量口径（2 核 / 2 GB / 50 GB / 4 Mbps / 300 GB·月）

- 静态站本体 2.8 MB，磁盘无压力；Caddy 托管内存占用小，2 GB 足够。
- 带宽是主要约束：4 Mbps 下单个访客首屏（gzip ≈384 kB + worker 约 485 kB）约 2–4 秒级；
  多人同时首屏会互相挤占——拉人初期小规模无碍，若同时涌入多则首屏变慢（非故障）。
  300 GB/月流量包对静态站很宽裕（约数十万次首屏量级）。
- 本次为单人预览，无服务端并发压力；多人联机（P2）上线前需另行容量评估，不在本清单范围。
