# 拉取式部署 · 一次性安装单（2026-11-19，Muse 出）

## 为什么装这个

Muse 本机出口对 SSH 的拦截已三次实测（2026-11-19 00:10 / 00:21 / 07:40，均在密钥交换阶段被出口代理重置、密码未及验证）。只要部署靠「某人 SSH 进服务器敲命令」，Muse 就永远上不了线。装完本件后：**部署 = 把验收过的代码推到 `town-release` 分支**，服务器自己拉取重建，Muse 独立可部署，不再卡任何人的窗口。

## 安装四步（有服务器权限者执行一次，约 10 分钟）

1. **建 release 分支**：从集成线当前头建分支 `town-release` 并推送（本批目标头 `3de70b1`）：
   `git branch town-release 3de70b1 && git push origin town-release`
   此后只有推到这个分支才触发部署，集成线随便推不影响线上。
2. **放脚本**：把仓库 `tools/pull-deploy/pull-deploy.sh` 复制到服务器仓库检出目录内（随检出走即可，不用挪系统目录），`chmod +x`；打开脚本顶部核对 `REPO_DIR` 是服务器上那份带 Deploy Key 的检出路径（默认 `/home/ubuntu/unwritten-2027`，不对就改）。
3. **装定时器**：`crontab -e` 加一行（每 2 分钟轮询一次）：
   `*/2 * * * * REPO_DIR=/home/ubuntu/unwritten-2027 /home/ubuntu/unwritten-2027/tools/pull-deploy/pull-deploy.sh`
   （REPO_DIR 按第 2 步的实际路径填。）
4. **首跑验证**：手动跑一次脚本，应把线上从 `799b571` 切到 `3de70b1`；回执写明 healthz 实测值与脚本日志尾 5 行。状态文件在检出目录 `.pull-deploy/`（deployed-sha / prev-sha / pull-deploy.log）。

## 脚本行为（先读再装）

- 轮询 `origin/town-release` 头 SHA，与 `.pull-deploy/deployed-sha` 相同就静默退出；不同才动。
- 部署走现行 town-preview 流程：检出目标 SHA → 以 `TOWN_RELEASE=<完整SHA>` 构建双镜像 → compose 切换 → **healthz 必须精确等于 `town-preview <SHA>`（最多等 90 秒）**才记成功。
- 失败自动回滚到上一个已部署 SHA 并重建；回滚也失败只记日志报警，不乱动。
- flock 防并发；日志在 `.pull-deploy/pull-deploy.log`。

## 装完之后的分工

- Muse 发版：验收过的批次推 `town-release`（与推集成线同一机制），2 分钟内自动上线，Muse 以 healthz 精确匹配验收。
- 任何人仍可照旧手动部署（脚本只在 release 分支头变化时动作，不冲突）；手动部署后请把 `.pull-deploy/deployed-sha` 同步为实际线上 SHA，避免脚本误判。
