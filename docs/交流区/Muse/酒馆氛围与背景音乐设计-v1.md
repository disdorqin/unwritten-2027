## 1. BGM 全设计（生成式、全合成、零采样资产；基调：喜庆而舒缓的过年味）

### 1.1 总架构：一条管线、一个音乐总线

- 复用 `festival.ts` 的共享 `AudioContext`（懒建、首次手势后 resume），BGM 挂在其下新增的 **music bus**（GainNode → DynamicsCompressor → destination，与钟声 SFX 并列过同一压缩器防爆音）。模块形态：`town-music.ts`，对外只暴露 `setScene(scene)` / `setIntensity(...)` / `duck(seconds, depth)` / 设置接口，编排逻辑全在模块内。
- 五层编制（急件三层为骨）：**低音垫（pad）+ 扬琴层（琶音 / 拨弦）+ 笛子主旋律（lead）+ 轻打击（木鱼 / 小锣 / 堂鼓）+ 风雪噪声（wind）**。急件的「衬底」在 M1 定型为低音垫、「五声拨弦」定型为扬琴层，**急件不返工**（§1.12）。全合成手段沿用镇页已验证的合成词汇：振荡器 + 增益包络 + BiquadFilter；拨弦与钟声同族（分音列 + 指数衰减），不引入采样、不引入外部音频文件（仓库零音频资产的现状不变，包体不长）。

### 1.2 曲式与编制：原创年味旋律（版权纪律先行）

- **版权纪律（硬性）**：《恭喜恭喜》《贺新年》一脉只取 **idiom**——五声调式、喜庆句式感（上行级进的开门感、短句呼应的对称、落音回主的圆满感）——**主题旋律必须原创，不直接引用、不改编、不近似复刻任何现有歌曲的旋律线**；验收时若试听者能说出「这是某某歌」即为不合格（§1.13 第 8 条）。
- **主题旋律（原创，音级骨架）**：D 宫调五声（D E F# A B，音级记作 1 2 3 5 6；与钟声音高同属一个明亮的五声音场），一段 8 小节主题（每小节 4 s，与和弦槽对齐）：`5 6 1' 6 | 5 3 2 3 | 5 6 1' 2' | 1' 6 5 - | 3 5 6 5 | 3 2 1 2 | 3 2 1 6, | 1 - - -`（`1'` = 高八度主音、`6,` = 低八度 6、`-` = 延留）。句式是过年的：高音开门、四小节一呼一应、末句落主收圆。施工时此骨架是**常量表**（音级 + 时值），不是生成结果——喜庆辨识度靠它立住，生成只在骨架上做变奏（§1.3），不另起旋律。
- **和弦进行**（每和弦 8 s、2 s 交叉淡化，一轮 32 s = 主题一遍）：**D5 → Bm7 → Gadd9 → Asus**（和弦音全取五声集合：D-A / B-D-F#-A / G-B-D / A-B-E）。
- **编制（新加坡华人过年声景，全部合成）**：
  - **笛子主旋律**：正弦基音 + 弱 2/3 分音 + 气声（带通噪声贴基音频带、−18 dB）+ 延迟颤音（起音 0.25 s 后介入、5 Hz、深度 ±0.6%）——合成出竹笛的亮与气，只奏主题与变奏，是全曲的脸。
  - **扬琴层**：亮拨弦（分音 1/2/3/4.2 + 起始 8 ms 噪声 tick），招牌手法是**快速重复音滚奏与琶音**：长音处同音十六分轻滚、和弦交界处一组上行琶音扫过——过年声景里辨识度最高的质感。
  - **低音垫**：每和弦根 + 五度两声部（三角 + 正弦），慢攻击 1.5 s、低通 700 Hz、总增益低（峰值 ≈0.05），只托底不抢脸（原「和声垫」降为纯低音垫，旋律让给笛子）；换和弦时声部逐个滑入（portamento 0.3 s），进行是环、无起止接缝。
  - **轻打击**：**木鱼**（1.9 kHz 正弦 burst + 极短噪声、衰减 60 ms，「笃笃」的点）；**小锣**（非谐分音 1 / 2.76 / 5.4、低增益、衰减 1.2 s，只落乐句分句尾与主题末音）；**堂鼓**（120 Hz 正弦下坠 + 噪声 snap，只在节庆档小节首）。音量纪律：**打击是点缀不是主角**——默认比旋律低 10 dB 以上，日常档近乎只剩木鱼（两档参数见 §1.5）。

### 1.3 生成规则：主题骨架 + 受控变奏（不是随机游走）

年味旋律要「听得住、记得住」，纯随机游走出不了这个效果——生成只做三件事：**变奏、织体、打击**，主题本身是常量（§1.2）。

- **笛子层**：每轮（32 s）完整奏一遍主题骨架；变奏规则（由时间锚种子决定，见本节末）：①装饰——长音前加一个上方邻音倚音（占时不抢拍）；②八度置换——呼应句（第 5–8 小节）允许整句高八度或低八度重奏；③留白——日常档每轮留 1–2 小节笛子休息（只剩扬琴与垫），节庆档不留白。四轮里至少一轮**素奏**（零变奏），让主题原样立住。
- **扬琴层**：按当前和弦音生成琶音织体——在八分 / 十六分网格上以档位密度（§1.5）填充和弦音琶音（上行 / 下行 / 波浪三型轮换）；主题重音拍（每小节首音）与笛子同音级呼应；滚奏只出现在主题长音（≥2 s）处。同时发声 ≤4 个 voice，超限偷最旧（与雪球池 drop-oldest 同哲学）。
- **打击层**：木鱼按档位落点（日常档：每 2 小节 1 点、只落乐句呼吸处；节庆档：每小节 2–4 点，固定型 `x . x x` 的变体）；小锣只落主题末音与节庆档的分句尾；堂鼓只在节庆档、每 2 小节首一记（−14 dB）。
- **时间锚定（关键裁决）**：一切生成种子由**绝对时间**导出——小节序号 = ⌊epoch / 4 s⌋，变奏与织体由 `mulberry32(seed = 序号)` 决定。于是全镇每个客户端在同一时刻听到**同一首**（同一小节、同一变奏），晚进镇的人落在乐句中间而不是从头播；与列车 / 仪式的「共享时钟纯函数」是同一设计哲学，零同步字节、零服务端参与。单人版用设备本地时钟同理成立。个人歌单播放时生成层让位（§1.10）。

### 1.4 风雪噪声层

- 1 s 噪声缓冲循环 → 低通（截止随雪势 400–900 Hz）→ 增益由雪势档（0–4，仪式/寒意同口径）驱动：0.015（无雪）→ 0.08（4 档大雪）；叠加慢速随机阵风（增益 LFO 周期 7–13 s 随机、深度 ±40%）。
- 室内时风声自动退到 0.01 以下（隔墙感），只留 §1.7 的室内层。

### 1.6 场景变体 A：室外底轨

§1.2–1.5 的原样即室外轨。进出任何室内（酒馆/屋舍/建筑室内判定沿用现有 interior 口径）时 1 s 交叉淡化切换变体，不停播、不重启乐句（时间锚定保证乐句连续）。

### 1.7 场景变体 B：酒馆室内（热闹的诚实合成法）

**先说清边界**：真人声鼎沸无法用合成凭空造出，本稿只用以下四种可行手段叠出「热闹的房间感」，全部低音量衬底，验收标准是「像隔着门听见的热闹」，不是「听见有人说话」：

1. **扬琴入室（主手法）**：酒馆有琴（琴椅/琴边桌在座）——室内时扬琴层加一条**合成小房间混响**（ConvolverNode，IR 为运行时生成的 0.7 s 指数衰减噪声，不采真样）、衰减拉长；笛子退到 −6 dB 作「门外传来的旋律」；打击层（锣 / 鼓 / 木鱼）**全部关停**——室内不敲锣打鼓是常识。叙事自洽：屋里有人弹琴、屋外年味隐隐，进门像推开一扇隔音门；旋律与室外同源（同一时间锚），乐句不中断。
2. **人声底噪（murmur）**：噪声 → 带通 500–1200 Hz → 振幅被随机「音节门」调制（80–200 ms 开 / 60–300 ms 关的随机包络）+ 慢 LFO，听感是**含混的人声涌动**，无任何可辨字音；音量随馆内在座人数（NPC 坐客 + 在座玩家数）线性缩放，空馆自动趋零——热闹程度由真实人数决定，不造假。
3. **杯盏声**：稀疏高频正弦 ping（2.8–4.2 kHz、60 ms 衰减）+ 微噪声 tick，泊松过程平均 1 次 / 7 s，仅在馆内有人时出现；点单/上酒事件发生时由事件直接触发一次（与 §2 的服务动作对位）。
4. **炉火噼啪**：随机脉冲（2–8 ms 噪声 burst 过 1.8 kHz 带通），泊松 ~3 次/s，按听者与炉子的距离衰减（沿 `playTowerBell` 的距离增益 + 低通公式），只在一楼炉边数米内可闻。

室内垫与风声：垫保持（低通降到 650 Hz 作「墙外传来的底」），风声退到 §1.4 的室内量。

### 1.8 仪式夜变体（与钟声/烟花的关系）

BGM 在仪式里是**配角中的配角**，让位纪律写死（钩子挂仪式时钟阶段，cue 表本身一字不改）：

| 阶段 | BGM 行为 |
|---|---|
| 23:00 起 | 切**节庆档**预热（§1.5）：锣鼓木鱼渐入，年味先浓起来 |
| 23:50–23:59:50（期待段） | 笛子、扬琴、打击全停，只剩低音垫 + 风声，垫增益 −3 dB——全镇屏息感 |
| T−10 s 起 | 2 s 内淡出到**全静音**（倒数与小敲独占声场；个人歌单同受此纪律，§1.10） |
| T+0 – T+30 s | 保持静音：大敲 12 下与烟花是唯一声源（烟花音效不在本稿范围，本稿只负责不抢） |
| T+30 s – T+10 min（余韵庆典） | **节庆档全开**：主题素奏一遍打头（零变奏，让全镇听清这支曲子），随后锣鼓木鱼齐上、扬琴加密——零点过后正是年味最浓的十分钟；与「镇志添篇」cue（T+300 s）不冲突 |
| T+10 min 后 | 3 min 内缓降回日常档夜里常态 |
| 日常手动敲钟 | 钟声触发 `duck(钟声衰减时长, −6 dB)`：音乐自动低头让钟声过，衰减完自动回位 |

### 1.9 音量、静音与自动播放

- **默认量**：music bus 峰值比钟声/命中等 SFX 低约 12 dB——音乐永远在事件声音之下。设置项：音乐音量滑杆（0–100，默认 55）、音乐开关、**M 键静音切换**；存 `unwritten.town-music.v1`（音量 + 开关），与既有设置同盘。
- **自动播放策略**：浏览器策略要求手势——镇页本来就要点击进第一人称/锁定视角，BGM 在**首次指针手势**时随共享 `AudioContext.resume()` 一起启动，不弹任何额外授权框；标签页切走时挂起（visibilitychange → 暂停调度、context 保持），切回续播（时间锚定保证续上的还是当前乐句）。
- **不抢语音**：朋友们用外部语音聊天——音乐频段集中在中低频且无突发峰值（压缩器兜底），默认量下不掩蔽人声；验收含通话实测（§1.13）。

### 1.10 个人歌单接口（服主专属，只做系统层口径）

Thomas 的个人心愿接口——曲目内容是他自己的事，本稿只定系统层：

- **入口**：设置面板「我的歌单」（**仅服主会话可见**，会话判定沿吉祥物稿的 OWNER_KEY 口令口径）——文件选择器多选音频文件（浏览器可解码格式），或拖放入口；播放节点接入 music bus，与生成音乐共用音量 / 静音 / 压缩器纪律。
- **播放关系**：歌单播放时，生成层（笛子 / 扬琴 / 打击 / 垫）淡出让位，只保留风雪噪声层垫底（可在设置里关）；歌单播完或手动切回后，生成层按时间锚从**当前乐句**淡入续上。歌单与生成音乐是二选一主声道，**不叠奏**。
- **纯本地、不广播**：文件是服主的个人音频——不上传、不经 presence 同步、其他玩家听不到（版权与隐私双口径）；镇上其他人听到的仍是生成 BGM。
- **持久化诚实边界**：浏览器不能无授权长期持有本地文件——v1 口径为**每会话选择一次**（File 对象会话内有效）；支持 File System Access 的浏览器可存目录句柄跨会话（句柄存 IndexedDB、每次使用仍过浏览器授权），接口预留句柄位、v1 不强求落地。播放顺序 / 循环模式存 `unwritten.town-music.v1` 同盘。
- **仪式让位不豁免**：歌单同样服从 §1.8 让位纪律（T−10 静音、零点让钟与烟花）——个人歌单不例外。

### 1.11 CPU / 内存账

- 稳态节点：低音垫 2 osc + 笛子 1 voice（+ 气声噪声 1 源）+ 扬琴 ≤4 voice（短命）+ 打击 ≤2 voice（短命）+ 风声 1 源 + 滤波/增益 ~12 节点 + 室内附加（convolver 1、murmur 链 3、ping/crackle 按事件建拆）——全镇任一时刻 ≤30 个音频节点，全在音频线程，**主线程每帧成本 ≈0**（调度器 250 ms 定时器 + 0.6 s 前视排程）。
- 内存：噪声缓冲 1 s（≈176 KB）+ IR 0.7 s（≈124 KB）+ 代码常量，合计 <0.5 MB；零下载资产。
- draw calls / 三角增量 **+0**（纯音频）。

### 1.12 与急件最小形态的衔接（增补清单）

急件已含：三层骨架（衬底 / 拨弦 / 风声）、室外固定编配、共享 AudioContext、首次手势启动。急件的「衬底」在 M1 定型为低音垫、「拨弦」定型为扬琴层——**急件不返工**。**本稿增补**（M1 批）：① 原创主题旋律常量表 + 笛子层（年味的脸）；② 扬琴琶音 / 滚奏织体 + 轻打击层（木鱼 / 小锣 / 堂鼓）；③ 时间锚定种子（全镇同曲）；④ 情绪两档 × 时段 × 雪势调制；⑤ 酒馆室内变体四手法 + 合成 IR；⑥ 仪式让位与节庆档升格 + 敲钟 duck；⑦ 设置三件（滑杆 / 开关 / M 键）与持久化；⑧ murmur 随在座人数缩放；⑨ 个人歌单接口（§1.10）。急件代码结构（music bus + 层函数）即 M1 的扩展点，不重写。

### 1.13 验收（真机听感清单，含情感项）

1. 连续听 10 分钟：主题每轮回归但变奏不重样、无机械循环感；换和弦处不「咔哒」。
2. 两台设备同时进镇：同一时刻乐句一致（对表录屏验 30 s，笛子落点对齐 ≤0.5 s）。
3. 推门进出酒馆：1 s 内音色切换完成、无爆音；室内能听见带混响的扬琴声 + 若有若无的人声底噪 + 偶发杯盏声、锣鼓木鱼全无，**听不出任何字**。
4. 雪势 0→4 档切换：风声与闷感随档变化，无突变跳档。
5. 仪式预演：T−10 前音乐已静音、零点只有钟与烟花、T+30 节庆档以主题素奏打头准时起、10 分钟后回落常态。
6. 手机外放：垫不糊（低通有效）、扬琴与笛子可辨；与朋友语音通话同开：默认音量下说话不费劲。
7. 设置：音量/开关/M 键静音即时生效、刷新后保留；切标签页回来音乐续上且乐句对位。
8. **喜庆辨识度（情感项）**：给不知情的试听者放日常档 10 s，能说出「像过年」；再放主题旋律——**不能**说出任何一首现有年歌的名字（说得出 = 引用了现成旋律，不合格，退回重写主题）。
9. **锣鼓不过吵（情感项）**：节庆档全开时与朋友语音通话 1 分钟，锣 / 鼓 / 木鱼不掩蔽人声、不引起「太闹了」的反馈；把打击层单独 solo 出来听，音量应明显只是点缀。
10. **夜里独听（情感项，总问）**：深夜档、一个人戴耳机听 5 分钟——舒缓、不闹、不瘆人，笛子与扬琴像「远远传来的年味」；问试听者「像不像过年回家」，应答「像」且不犹豫。
11. 个人歌单：服主选入自己的音频文件能播、与生成音乐切换无爆音、仪式预演时歌单同样在 T−10 静音；以非服主身份打开设置，无「我的歌单」入口。

## 3. 小游戏：骰子先行（划拳立项不施工）

### 3.1 二选一裁决：先骰子

| | 骰子（摇盅比大小） | 划拳（喊数对拳） |
|---|---|---|
| 呈现 | 3D 体素骰子落在桌面上，天生适配：6 颗骰 ≈72 tris、复用桌面批次 +1 draw；点数一眼可读，观战者也看得懂 | 手势数字靠方块手臂摆不出来，只能靠 DOM 面板出数，「拳」的肉身感丢失大半 |
| 公平机制 | commit-reveal 两段即可（§3.3） | 同样要 commit-reveal，且双方同时揭晓的时序更苛刻 |
| 与氛围的咬合 | 递盅、摇盅、开盅全是小二/老板的现成戏份 | 喊拳声是吆喝的天然延伸——但依赖台词量产，且 DOM 出数打断临场感 |
| 对 NPC | NPC 本地掷骰即可，无差别 | 同左 |

**裁决：骰子先行施工；划拳列为二期立项**（待气泡/吆喝系统跑顺、台词产能有余时再议，届时喊拳声正好接 §2.4 的气泡通道）。

### 3.2 规则（摇盅比大小）

- 双方各 **3 颗骰**，摇盅 0.9 s 后同开，比总点；大者胜。
- 平点：原地重摇（不另开局），连平 3 次判和局（无彩头，罗大江吆喝圆场）。
- 局制：一局定胜负（快局，酒桌节奏）；连玩由双方再邀，不做 BO3 强制。
- 参与资格：双方同桌对坐（中央桌/西桌/吧凳相邻位/暖棚游戏桌），或一方站着对坐着的 NPC——站坐可局，距离 ≤2.5 m。

### 3.3 双人对局流程（走 P2b 事件层）

消息走 P2b 的 JSON 通道（E1 已落地的转发形态），**点对点**：服务端按目标会话 id 只转发给对局双方（在既有兴趣扇出之外加一条「指定收件人」小径，不广播全镇）：

1. `game.invite {game:'dice', to}` —— 发起方对目标按互动键（目标占座时热点文案「邀玩骰子」）；对方收到 DOM 邀请条（10 s 应答窗，可拒可超时）。
2. `game.accept` / `game.decline` —— 应战成立，双方起立/坐正朝向彼此（姿态由本地来源切换，不新增姿态值）。
3. **commit 段**（防后手作弊）：双方客户端在摇盅动画开始时各自生成点数与随机 nonce，先发 `game.commit {hash}`（点数+nonce 的哈希），骰子在桌面上翻滚呈现（点数面朝下/盅盖状态，不露点）。
4. **reveal 段**：0.9 s 后双方发 `game.reveal {dice:[a,b,c], nonce}`，各端验哈希对得上才认账；验不过 → 本局作废 + 提示「盅底有诈？」（走个玩笑口径，不做惩罚系统——朋友局，防的是手滑与时序，不是防贼）。
5. 结算：各端本地同算胜负（同输入必同结果，无需服务端裁决）；结果 DOM 横幅 + 胜方举杯（pose 4）+ 罗大江/小二报点吆喝（§2.4）。
6. 异常：任一段超时（commit/reveal 3 s 未达）判对方弃局；中途离座/走远（>4 m）自动散局；断线重连不恢复局（快局，重开即可）。

### 3.4 彩头与饮酒特效联动（无货币）

- **负方罚酒一杯**：走已落地的饮酒管线——负方酒意 +1 单位（眩晕分级照 `tavern-drink-effects` 原口径，封顶 3 不变）；没有现成酒时，小二端一杯过来（§2.2 服务动作）再罚——服务即彩头的一部分。
- 已达酒意封顶者不罚酒，改罚**表演**：举杯向全桌致意（pose 4 拉长到 4 s）+ 一句自嘲吆喝位（内容线句池）。
- 胜方：举杯庆祝（pose 4）+ 连胜计数只在本桌结果横幅显示（不落榜、不全镇广播——酒桌的输赢是酒桌的事；要全镇荣誉有冰雪之主和领头羊在）。
- 全程**不涉及雪花币或任何货币**（D7 未定案，本稿不预设）。

### 3.5 单人对 NPC

- 可邀对象：在座坐客、小二（巡堂空档时）、罗大江（吧台局，玩家坐吧凳时）。
- NPC 侧全本地模拟：同一套 commit/reveal 剧场在本机内走完（NPC 的「哈希」只是走个形式，时序与双人局完全一致，玩家无感差别）；NPC 点数真随机，不放水不针对（罗大江赢了照样吆喝着给玩家倒罚酒）。
- NPC 应答性格：坐客总是应战；小二忙时（正端着酒）会回「这盅就来，等我把酒送到」延后一局；罗大江只接吧台局。——性格差异由应答文案承载（内容线），机制只给 accept / defer / decline 三态。

### 3.6 观战呈现

同桌/邻座玩家能看见桌面骰子的翻滚与开盅点数（3D 呈现的红利）；结果横幅只给对局双方与同桌 2.5 m 内的人（DOM 近场口径），不吵全馆。

## 4. 酒馆空间：扩容三案与推荐

现状约束：地块 22×18 m、两层，**酒馆是全镇唯一被 Thomas 完全认可的标杆建筑**——扩容的第一原则是**不动标杆的内脏**。

| 案 | 做法 | 利 | 弊 / 成本 |
|---|---|---|---|

## 6. 验收清单（氛围 / 游戏 / 空间；BGM 听感与情感项见 §1.13）

**氛围**

1. 进门 3 s 内听见迎客吆喝（气泡可见、40 m 外不可见）；同一玩家连进连出不重复刷。
2. 傍晚坐客轮值 2–3 人在座，举杯 / 闲聊气泡自然发生；中央桌始终空着留给玩家。
3. 小二巡堂一圈路线完整（吧台 → 西桌 → 中央桌 → 琴边 → 吧台）；玩家点单后小二送酒到座，杯盏声与动作对位。
4. 整点吆喝每时段只响一次；两名 NPC 的气泡永不重叠（8 s 不应期生效）。
5. 深夜坐客撤场、只剩罗大江与小二收尾；玩家与坐客对话 / 邀局时坐客不离座。

**游戏**

6. 双人全流程走通：邀局 → 应战 → commit → reveal → 结算；验哈希不过时本局作废且有提示；平点重摇、连平 3 次判和局。
7. 罚酒生效：负方酒意 +1、眩晕分级与单人饮酒一致；已达封顶者改走表演分支（举杯 4 s）。
8. 散局条件逐项验：离座 >4 m、任一段 3 s 超时、断线——均干净散局无残留状态；重连不恢复旧局。
9. 单人对 NPC：坐客必应战、小二忙时延后、罗大江只接吧台局，三态文案正确。
10. 观战：同桌第三人能看见桌面骰子翻滚与开盅点数；2.5 m 外无结果横幅。

**空间**

11. 暖棚：侧门出入判定正确、火塘暖源生效（寒意衰减按暖源口径验）、雪不穿棚顶。
12. 加密兜底件全部可登记就座 / 站位，碰撞不挡门、不挡小二巡堂路线。
13. 成本复测：酒馆室内标准视角 calls / tris 实测入账，与 §5.1 预算对表。
