# P4 性能基线测量 — 现图 @ ea3548b（扩图重构前对照）

测量：2026-11-17 晚，Muse（P4 验收方）。对象：`town-blockout-integration` @ `ea3548b` 的生产构建（`~/workspace/unwritten-ea3548b/voxel-tavern/dist`，townBlockout JS 416.14 KB）。
目的：给任务书 P4（性能优化）与 P1/P2（扩图重构）留一份**改前对照数**——扩图后同机位重测，差距即优化/劣化量。

## 方法与口径（重要）

- 无头 Chrome（SwiftShader 软件渲染，512×320，共享 1.5 核 VM）。**FPS 只记录、不可比**：软件渲染 + 弱 CPU 下的帧率与真机（GPU）没有换算关系；本报告的核心交付是**场景统计**（draw calls / 三角形 / GL 对象），这类计数与渲染后端无关，可跨设备对照。
- `renderer` 是 viewer.ts 的模块内变量，页面外不可达，故不用 `renderer.info` 本体，改用等价的黑盒计量：页面脚本运行前注入钩子，包裹 WebGL 的 `drawElements / drawArrays / drawElementsInstanced / drawArraysInstanced`（按图元模式与实例数折算三角形）与 `requestAnimationFrame`（计帧），每机位采样 4–5 帧取每帧均值。此口径与 `renderer.info.render.calls / triangles` 同源（three 的全部绘制都经这些调用），差异仅在钩子会计入 three 之外的零星 GL 调用（本页几乎没有）。
- `geometries / textures` 给的是 GL 层等价量：存活纹理对象数（createTexture − deleteTexture）≈ `renderer.info.memory.textures`；每帧不同 VAO 数 ≈ 当帧实际绘制的不同几何体数；存活 GL buffer 数单列（`memory.geometries` 本体不可达，按每几何约 3–4 个 buffer 粗估为 ~650–850 个几何，**此数为估算**）。
- 机位到达方式：`#jump` 传送（落点与朝向由 viewer.ts 的 `jump()` 公式决定，确定性朝向）+ 冰湖机位用合成 tap-to-look 转向、酒馆机位步行进入。四张机位截图已逐一目视核对朝向（广场见钟楼方向、纪念馆见正门立面、冰湖见东岸暖房/灯塔一带、酒馆为室内朝北）。

## 源码静态计数（`town-blockout/*.ts`，grep 构造点）

- `new Mesh` 出现 **127** 处、`new InstancedMesh` **17** 处——源码构造点不等于运行时数量（大量在循环/辅助函数内），运行时以每帧 VAO 为准（52–205）。
- 光源构造点：PointLight 8、DirectionalLight 5、AmbientLight 2、HemisphereLight 1，共 16 处（此前"22"为含导入/引用的行数口径）。其中点光+平行光 13 个是逐片元成本的主要来源（Lambert 材质、无阴影贴图）。

## 哪类对象最吃量（推断，已标注）

以下为按场景构成与四机位数据形态的**推断**，未做逐对象归因（黑盒计量到不了对象级）：

1. **三角形的大头是"少数几个重几何在所有户外机位反复出现"**（推断）：冰湖机位只有 59 calls / 52 个几何，却仍有 108 万三角形——平均每几何约 2 万三角形。候选：① 全图地形高程网格（单 Mesh、永远在视锥内，viewer.ts:121）；② 森林实例化（1,311 株树，forest-density 以 InstancedMesh 绘制，实例化按整网格剔除——只要视锥扫到林缘就整片计入，单株若为数百三角形，总量即数十万级）；③ 酒馆内嵌的体素几何（tavern-voxel-source）。三者都是"一两个 draw call 扛几十万三角形"的形态，与数据形态吻合。
2. **Draw calls 的大头是地标与街区的逐构件小网格**（推断）：calls 与每帧 VAO 几乎 1:1（差额为降雪 Points 等非几何绘制），说明 calls ≈ 可见几何个数。纪念馆机位最高（234），与纪念馆一带的文件构成一致（museum-* 近 20 个文件做壳体+细节+展陈，逐件成网）；广场次之（钟楼逐级踏步盒、周边地标同框）。
3. **没有遮挡剔除、没有 LOD**（由数据形态推断）：酒馆室内朝北仍发出 118 万三角形——墙后、屋外在视锥锥体内的对象照常绘制（three 只有视锥剔除）。室内机位 calls 低（72）但三角形不低，正是"大几何穿墙计入"的表现。
4. 降雪为单个 Points（1,580 粒子、1 call、0 三角形），成本可忽略，不是嫌疑。

## 对后续工作的含义（给 P4 / P1 / P2）

- A3 手段按本基线排收益：**先压三角形**——森林与地形的 LOD/分块剔除（按街区设可见距离）收益最大；其次地标几何按材质合并（压 calls，为扩图腾余量）；实例化推广到灯具/栏杆/摊位等重复件；动态光源（13 个点光/平行光）按档位收敛仍值得做，但它压的是片元成本、不压本次超线的三角形。
- 扩图后（P1）必须在**同四机位**重测一轮对照本表；新机位（火车站、温泉、冰雪城堡、过山车站）建成后另加。
- 真机帧率验收仍按任务书 A5 执行（三台真机定点表）；本报告的 FPS 数字**不得**引用为真机表现。真机卡顿的现有证据是 Thomas 本人 PC 实测（2026-11-17 17:50）。
