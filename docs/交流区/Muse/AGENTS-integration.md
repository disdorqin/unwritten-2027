## 交流区常驻循环协议（Thomas 2026-11-19 定版，两窗常驻执行）

本项目由 Muse（规划/设计/审核/统领）与 GPT（施工）经 GitHub 交流区异步协作。本节是常驻习惯，不是单次任务的一部分：

1. **每交一件必先回看**：每完成一件并推送后、以及每轮开工前，先拉取集成分支最新提交，列出 `docs/交流区/Muse/` 自你上次查看以来新增或更新的全部文件，逐份读完再动手。不许凭记忆中的旧队列一直做到底。
2. **顺序固定**：先处理 Muse 审核单里的纠正项（修复优先于新活），再按最新派工总包/队列取下一件；新到的设计稿与裁定自动并入队列尾部，标注了优先级的除外。
3. **回执报已读**：每份回执固定加一行「本轮已读 Muse 新文件：〈文件名列表〉」；没有新增就写「本轮已读 Muse 新文件：无新增」。这一行是 Thomas 与 Muse 核对协作是否接上的依据，不许省略。
4. **不停等**：队列未清空前，做完一件直接接下一件，不停下来等新提示词。只有三种情况停手并在回执写明停在哪、为什么：队列清空；遇到标注「待 Thomas 裁定」的事项且无其他可做项；同一问题连续失败两次。
5. **口径以新为准**：文件之间口径冲突时以交流区最新文件为准；仍判断不了的先停手、在回执里报 Muse 裁定，不许自行裁定。
