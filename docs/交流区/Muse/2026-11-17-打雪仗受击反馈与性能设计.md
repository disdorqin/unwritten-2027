# 打雪仗受击反馈：雪糊屏 + 视角晃动（Thomas 追加，性能设计由 Muse 定）

日期：2026-11-17。并入《打雪仗完整设计 v1》第三节（打击反馈）。Thomas 的要求：被砸中时，本人屏幕上要有雪花糊住视线零点几秒（带视线模糊感）+ 轻微视角晃动；前提是性能占用压到最低，几十人同时在线也不卡。

## 一、效果规格
- **雪糊屏**：被命中瞬间，本人屏幕出现雪团糊住的效果（雪花团 + 边缘结霜），持续约 0.4–0.6 s 后淡出；砸中头部时效果更强一档（呼应"头顶积雪"），躯干命中弱一档。
- **视角晃动**：命中瞬间起 0.25–0.4 s 的轻微晃动（旋转噪声约 0.3–0.8°、指数衰减），只够感到"被砸了一下"，不晕不偏离瞄准太多。
- **公平性护栏**：糊屏纹理的雪团集中在屏幕边缘与下部，**中心视野保持基本通透**；连续被砸只刷新计时、透明度封顶，不叠加到看不见路。

## 二、性能设计（为什么这套不卡，三条纪律）
1. **禁止实时模糊**：不做后期处理管线（额外的渲染目标 + 模糊着色器是移动端最贵的一类开销）。"模糊感"靠**预烘焙**——雪糊纹理在制作时就是柔边的软雪团，自带模糊观感，运行时零计算。
2. **覆盖层走 DOM、不走 WebGL**：游戏是网页——雪糊屏用一个页面覆盖元素（一张预烘焙雪糊 PNG + CSS 透明度过渡）实现，**零 WebGL 绘制调用**，由浏览器合成器处理，不占游戏渲染线程。若实现上必须走画布内，也只允许一张贴图的单次绘制且雪团像素集中边缘，禁止全屏逐像素着色器。
3. **晃动是纯数学**：视角晃动只是每帧给相机旋转加一个衰减噪声偏移，几行算术，无渲染成本。
- **多人不放大**：这套反馈 100% 只发生在被砸者自己的客户端上，与在线人数无关——50 人同场，每人屏幕上的效果成本都是同一份 O(1)；网络侧只有设计 v1 已定的命中事件（一条小消息）。真正随人数涨的是他人化身与雪球渲染，已有对象池（≤64）与 NPC/化身预算管着，不在本项。

## 三、预算与验收（并入设计 v1 第八节）
- 预算：效果激活窗口内，受击者客户端帧时间增量 **Δ ≤0.2 ms**（不含既有迸溅粒子，后者按附录另计）；覆盖层纹理 ≤1 张（建议 1024² 以内、边缘集中构图）。
- A4 验收：广场机位下开/关受击反馈各测一轮帧时间对照（无头只看相对量）；连砸 5 发验证计时刷新与透明度封顶；头部/躯干两档强度可辨；中心视野通透性人工抽查。

参考口径：MC 等游戏的受击反馈同理——屏幕覆盖 + 相机晃动，从来不是靠后期模糊实现的，这也是它们不卡的原因。
