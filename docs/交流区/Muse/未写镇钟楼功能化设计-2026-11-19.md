# 未写镇钟楼功能化设计 · 2026-11-19（Muse 设计，GPT 施工）

Thomas 点名（实测反馈第 12 条）：钟楼纯纯摆设；高是高但比较小；只有中间可以进去、两边进不去。本稿逐项查过 landmark-tower.ts 与 viewer.ts 现行接线后写规格：**钟楼的内脏其实大半已建好，病在全部功能只绑跨年夜仪式时间线、日常一次都不触发，且两翼是实心假楼。** 数字出处逐项标注；「估算」为设计推算，「待实测」为施工前必量项。

## 一、现状与病灶

地块（layout.json）：clocktower origin [226, 223, 12]、footprint 34×14（x 209–243、z 216–230），门 [226, 216] 朝南开向广场，connect [226, 212] 贴广场北沿。

1. **高而显小（体量比失调）**：塔身外宽仅约 11.5 m（大厅地面层 13×13、墙体在 ±5.75 一线，landmark-tower.ts）；总高按 `clocktowerHeight()` 拉伸公式（钟面带以上按 5/16 补偿）推算 ≈**110 m（估算）**，高宽比 ≈**9.6 : 1（估算）**——是一根针，不是一座楼。34 m 宽的地块里，真正有体量的只有中间 11.5 m。
2. **两边进不去（翼楼实心）**：两侧翼楼自 |x| 5.4 伸至 16.25（每翼宽约 10.85 m、进深 ±6.55 m、高约 8.6 m 加坡顶至约 11.2 m），外观有发光窗洞，内部却是一整块实心碰撞体（每翼一个 solid，0.25–8.45 m 全堵），无楼层、无门、无任何内部几何。玩家能进的只有中塔一孔。
3. **纯摆设（功能全绑仪式夜）**：
   - 钟面是**静止图画**：南面表盘指针由固定笔画写死（stroke 角度 −π/15 与 −π/3，landmark-tower.ts），不走字；
   - 敲钟机制其实齐全：大钟带 `strike()` 摆动（周期 1.02 s、衰减 4 s、最大摆幅 π/30），viewer 已接整点钟声 cue（`hourly-chime`，每次 3 击、间隔 2020 ms）、倒计时滴答（strike 0.28）、零点大击（grand-strike），还有玩家拉绳敲钟点与「查看钟楼表盘」点——但 cue 只由 town-ceremony.ts 在**跨年夜仪式日程内**生成（其第 204 行），平日打开游戏，钟不敲、绳拉了也只在仪式保留期外才响（climax 及距零点 ≤300 s 时拉绳被锁）；
   - 内部其实可登：32 段环梯（每段 12 级 × 0.21875 m）直达表盘层（第 24 停）、钟层（第 27 停）与塔顶瞭望台（第 31 停以上），表盘层有齿轮组与书房、钟层有工具板，`userData.stops` 已暴露 dial/bell/lookout 三停——但日常玩家没有任何理由上去，塔顶生肖龙点位（viewer 接线）之外无第二个锚点。

## 二、设计规格

### 2.1 塔钟走真实时间 + 倒计时牌（方案①）

- **指针动态化**：表盘指针（南北两面，内面既有刻度环与指针同驱）改为动态批次，做法复用大钟 `attachBell` 的「可动 InstancedMesh 批次」现行模式，不动表盘盘面、120 刻度环与齿轮组（已验美术零改动）。
- **驱动口径**：取 Asia/Shanghai 本地时间；时针角 = (时%12 + 分/60) × 2π/12，分针角 = (分 + 秒/60) × 2π/60，1 Hz 跳步更新（与既有 countdown-tick 的秒级节奏同口径）。角度正负号与 stroke() 既有约定（现行静止笔画约对应 10:08 构图）的对应关系**待实测**：施工第一步先以静止笔画反推约定，再接驱动，验收含整点位图对照。
- **倒计时牌**：南面塔身、钟面带以下居中设像素字牌（估算位置：原始 y 44–50 m 段、宽约 7 m、高约 3 m，估算），做法复用表盘的 box 像素字口径（dark 底、gold 字），6 位 HH:MM:SS + 两位分隔点。数据源：平日显示北京时间 HH:MM:SS（与指针同源）；仪式 converge 起改读 `ceremonyState.secondsToMidnight`（town-ceremony.ts 既有字段）显示距零点倒计时，climax 归零时刻与 grand-strike cue 同步。更新 1 Hz；像素字字形表由施工自备，风格与表盘刻度同族，字形表随回执附图报备。

### 2.2 日常整点敲钟 + 零点衔接（方案②）

- **日常钟点**：新增一个「日常时钟」cue 源，按 Asia/Shanghai 整点发出与现行同形状的 `hourly-chime` cue，走 viewer 既有 handler（`festival.playCeremonyBell('hourly', 距离)` + `bellMotion.strike(0.65)`，**3 击、间隔 2020 ms——全部沿用现行已验数值，不许改**）。发声时段 07:00–23:00（估算，设计取舍）；23:00–07:00 只摆钟不发声（摆动为纯视觉，音频本就按距离衰减）。
- **与仪式日程互斥**：跨年夜仪式日程激活期间，日常 cue 源停发，敲钟完全由 town-ceremony.ts 既有日程接管（hourly-chime / countdown-tick / grand-strike 一字不改），杜绝双发。
- **零点衔接 C2**：零点大击沿用既有 grand-strike cue；本稿只新增两点：①倒计时牌在 climax 归零（与 grand-strike 同帧口径，验收对表）；②钟声为仪式第一波烟花的**并行声画**，不改 C2 §3.4 段序、时刻与任何已验数值文案。拉绳敲钟的仪式保留锁（climax / 距零点 ≤300 s）口径不变。

### 2.3 扩体：基座打通 + 中塔加宽 + 翼楼赋用（方案③）

- **门廊台地**：入口三级台阶由现行 6.7 m 宽扩至约 13 m（估算），两侧加缓坡；广场北沿至塔门（z 212–216、x 209–243）的门前带铺装为钟楼前场（《广场二期扩容设计》已把此带留给本稿，两稿不重叠）。
- **基座三开间**：地面层（原始 0–10.25 m）在塔身东西两侧墙（±5.75 一线、z=0 处）各开一拱门洞，宽 1.75 m × 高 2.25 m（复用塔内既有 `addTownWindow` 的 1.75×2.25 尺度口径），大厅与两翼贯通成 34 m 通宽的基座大厅；门洞只开地面层，10.25 m 以上塔身墙体一字不动（环梯核心与 shaftWalls 口径零改动）。
- **中塔加宽（只加皮不动骨）**：钟面带以下（原始 10.25–53.5 m）四角加贴壁扶柱，外凸 0.75 m、柱宽 1.25 m（估算），塔身视觉宽度由约 11.5 m 增至约 13 m（估算），高宽比降至约 8.5 : 1（估算）；扶柱只贴外皮，不进楼梯井、不改任何 stops 坐标。
- **翼楼打通（每翼：两层，层高估算）**：拆除每翼整块实心碰撞，改为墙壳 + 两层楼面：地面层与大厅同标高（原始 0.3125 m），夹层原始约 4.9 m（估算；翼内净高约 8.2 m，两层约 4.6 + 3.6 m，估算）；南立面既有三扇发光窗洞（u = 6.85 / 10.45 / 14.05）改为真实窗洞，复用 `addTownWindow`（塔内已有 'tavern' 风格先例）；翼内几何并入既有内饰分层批次口径（landmark-tower.ts 现行按高度带切分的 detailInterior 层，cutoffs 既有数组），不新增渲染路径。
- **西翼 = 钟机 / 展陈**：陈设全部复用塔内既有母题与函数：齿轮墙（gear() 既有三档尺寸 0.90625/28 齿、0.625/22 齿、0.46875/16 齿）、表盘剖面与拓片墙（表盘层既有 rubbing 母题）、退役钟舌与绳具展架、工具板（钟层既有 toolBoard 母题）。纯陈设 + 既有 localSpot「查看」式播报，不新设交互系统；新增播报文案随回执报备。
- **东翼 = 环梯 + 观景连廊**：翼内设环梯（复用 stairs() 助手，梯宽 1.125 m——塔内 branchWidth 既有先例）自大厅层升至翼顶平台（原始约 11.2 m，估算）；平台沿南立面设观景连廊，栏杆复用 guard()；连廊西端在塔身南墙开门洞接入环梯井：落点为最接近原始 11.2 m 的楼梯平台（约第 4–5 停一带，估算），**具体落点待实测**（碰撞与梯段净空实测后定，实测不通则连廊只连东翼平台、独立成观景廊，此降级口径预先批准，不许为打通而改环梯走向）。
- **塔顶观景台（正式化既有瞭望台）**：瞭望台几何与护栏已在，只做三件：①登记合影机位（复用 plaza-group-photo / theater-photo-camera 的机位口径）；②加黄铜望远镜陈设一具（估算，纯陈设无系统）；③塔顶生肖龙点位（userData.stops.lookout 既有接线）位置与触发一字不动。

### 2.4 整点小事件锚点（方案④）

以 2.2 的日常整点 cue 为全镇统一钟点，挂三个环境事件（全部环境触发、玩家零操作要求、单人成立）：

- **集市开摊**：整点 cue 触发集市摊位开摊状态刷新（复用集市现行活动状态机，不新设时段表）；
- **NPC 聚集**：整点 cue 后，驻守 NPC 按既有驻守锚点系统向广场锚点轮换聚集一轮（复用 town-npc 驻守/锚点口径，不新增 NPC 行为系统）；
- **灯市点灯**：逢傍晚整点（17:00 / 18:00 两档，估算）cue 兼作灯市与广场灯饰点灯触发（复用 townLights 既有灯带口径）。

三项均为客户端环境表现，复用既有通道与状态，不新增协议号；联机各端以各自 Asia/Shanghai 时钟对齐，环境事件允许秒级漂移（仪式 cue 的严格同步口径不受影响，仍走既有日程）。

## 三、与既有系统的衔接点

- **buildTowerLandmark 合同不变**：函数签名与 `userData` 合同（colliders / floors / ramps / stops / dialFocus / bellMotion / detailInterior）全部保留；stops 三停坐标不许动（生肖龙、拉绳点、表盘点、百门通相关接线都挂在上面）。塔体几何同时供 Voxelize 快照（buildGrandClocktower 既有管线），改动后须过快照回归。
- **town-ceremony.ts**：阶段、时刻表、cue 表一字不改；本稿只新增「日常时钟」旁路 cue 源与倒计时牌读数两个消费方。
- **festival.ts**：`playCeremonyBell` 与 `ringBell` 沿用，音频资产不新增（钟声音色三档 tick/hourly/grand 既有）。
- **C2 烟花**：§3.4 定稿段序与时刻零改动；钟声只做并行声画与倒计时牌归零对表。
- **广场二期**：门前带（z 212–216）归本稿、bounds 北沿归广场稿，两稿已对齐不重叠；钟楼前场铺装与广场铺装同口径。
- **百门通（B13）**：塔内 stops 若被门网引用，坐标不变即不影响；本稿不新增门点。

## 四、验收线（逐条核）

1. 钟面走字：任意整点与半点各截一图，指针位置与 Asia/Shanghai 实际时间一致（误差 ≤1 分钟）；南北两面一致。
2. 倒计时牌：平日显示北京时间到秒；仪式彩排口径下（TOWN_REHEARSAL 既有通道）切入 converge 后改显距零点倒计时，归零帧与 grand-strike 同帧（录屏逐帧核）。
3. 日常敲钟：07:00–23:00 任一整点，广场任意点位可闻 3 击（间隔 2020 ms）、可见钟摆；仪式日程激活时无双发（彩排全程计数核对）。
4. 扩体实走：自塔门进入后可不回头直达西翼展陈末端与东翼环梯顶平台；两翼窗洞可真实向外看（非发光贴图）；连廊落点按实测结论验收（打通或降级口径，二选一在回执中点名）。
5. 体量对照：同机位（广场心区向北）新旧对照图各一，高宽比按完工实测标注；扶柱不入楼梯井（塔内任一段环梯净宽与改前一致，抽测 3 段）。
6. 合同回归：userData.stops / dialFocus / bellMotion 与改前逐项一致；拉绳敲钟、查看表盘、塔顶生肖龙三点位实测可触发；Voxelize 快照回归通过。
7. 既有套件全绿（根套件 + 服务端 + tsc）；性能读数：广场心区同机位 draws / tris 与改前对照，在 PC 参考线（450 / 2.2M）内或超线逐项说明（翼内几何走既有分层剔除，塔外视角不得全量加载翼内批次——以分层可见性实测自证）。

## 五、边界（不做什么）

- 不改环梯走向、stops 坐标、钟面盘面与刻度、齿轮组造型（已验美术与动线零改动，只加皮、开洞、赋用）；
- 不改仪式日程、C2 烟花段序与任何已验数值（3 击 / 2020 ms / strike 强度 / 摆幅周期）与文案；
- 不新增协议号、不新增 NPC 行为系统、不做需要第二名玩家的钟楼玩法；
- 不在塔身 10.25 m 以上开任何新洞（连廊门洞只许开在南墙且以实测落点为准，不通即降级）；
- BGM 仪式版切换不在本稿范围（另有小单）。
