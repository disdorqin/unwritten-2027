# 工程指导 · 多智能体协作常设约束

> 立于 2026-11-20 晚。总控据 Thomas 令制定：内化本项目当晚事故教训 + 外部多智能体工程实战调研（Anthropic / OpenAI / Cursor 官方工程文与独立实践者实测，来源附末）。本件为**开工基线**，不是事故汇编：新阶段、新队列开工前先立此基线，再开工；已在飞的队列按本件回查补齐。
> 适用：总控、分区窗口、全部 GPT 施工窗。冲突时以本件为准；本件与 Thomas 新令冲突时以 Thomas 为准并修订本件。

## 〇、总则

1. **并行施工，串行融合。** 施工可以多窗并行；落入主干必须排队、一次一件、在合并后的结果上复验。
2. **「完成」只有一个定义：并入主干 + 玩家在正式路径可达。** 在分支上、在评审场景里、在本地验过的，一律不算完成。未完工的功能靠开关/旗标藏在主干里长，不许靠分支藏。
3. **决定只活在仓库里。** 只存在于某个聊天里的决定等于不存在——裁定、口径、规格变更必须落仓，施工窗开工前读仓为准。

## 一、结构：隔离与领地

4. **一窗一工作区。** 每个施工窗独占自己的工作树与分支；共用一个检出目录施工是结构错误（索引锁、幻影提交、切分支抽走对方半成品），不是「小心点」能补的。
5. **分支短命。** 任务分支以小时计、最长约 2 天；并入即删。分支是传送带，不是仓库——把成品存进分支等于丢弃（本项目实证：102 条分支审计，绝大多数产出作废）。
6. **领地互斥。** 每份任务书带「拥有（可改）/ 禁碰」路径清单；并行任务的领地并集必须互斥，真需要同一文件的两件活不许并行，排队做。开工前 10 分钟划领地，是全流程杠杆最高的一步。
7. **接合文件单写。** 场景注册表、资源清单、入口与菜单接线、全局配置这类「接合文件」，并行期间任何施工窗不得顺手改——接线是融合步骤里一个有主人的明确动作。本项目头号病「建好没连上」就产在这里：做功能的人没被派接线，别人也不知道要接。

## 二、融合：队列与节奏

8. **自审自并 + 合并队列。** 施工窗对自己的件自审（按第五节验收律）后自行排队并入主干；分区只抽查、可回滚；总控只管发布。把审核关设成常态、放行设成例外，是本项目当晚最大的结构错误，不许重犯。
9. **一次落一件，落一件验一件。** 每并入一件，在**合并后的主干**上跑全量检查——语义冲突在干净合并之后照样炸（改名后的函数 vs 仍用旧名的调用方，两边各自全绿、合起来崩）。外部构造实测：105/108 个此类合并失败。
10. **至少每日并入主干。** 分支老化成本有实测：一条线搁置 24 天 → 92 个文件不可自动合并、56 分钟人工解，且失败全不是文本冲突，而是主干在此期间新增的规则与测试。对照组：96 次小步快并、全程 2.2 小时。
11. **发布 = 主干绿色快照加固。** 发布不另起分支、不攒大包：主干持续落件，发布时取一个已验快照做最后加固与正式服复验后放行。

## 三、任务书：契约格式

12. **四件套 + 两注记，缺一不发。** 每份任务书必须含：①目标 ②产出格式 ③工具/取材指引 ④明确边界（领地与非目标）。外加：⑤**基线状态**（从主干哪个提交起、依赖谁的在飞件）⑥**接线注记**（本件在主干上需要哪一步接线才对玩家可达、由谁做）。含糊的任务书必然产生重复劳动与缺口（Anthropic 多智能体系统实测教训）。
13. **验收标准必须是可运行的检查。** 写明命令、走查路径或截图点，并给示例情形；写不出检查的验收标准等于把总控变成人肉验证环，不许发包。任务粒度：一件活一个功能、一个会话做完并留干净提交；中位 agent 任务约 27 分钟，半天以上的活先拆。
14. **先规格、后计划、再施工。** 规格（几百字：问题/期望行为/非目标/验收）与计划（动哪些文件与接口、顺序、风险）先落仓过审——错误在规格阶段抓最便宜。核心抽象类（人人依赖的接口）属串行工作，永不并行硬拆。
15. **交接带实况。** 下一件的开工依据是上一件的**实际提交号 + 偏差说明**，不是原计划；交接必须先于依赖方开工送达（外部重演实测：早交接 6/8 干净应用，晚合并 7/7 冲突）。

## 四、参照与品味

16. **参照既有成品（本项目常设条款）。** 任务书必带「参照物」一节：风格准绳文件 + 2–3 个最接近的已建场景/模块；开工前先读参照的源码与摆法；新件优先复用既有材质、色板、道具词汇，不许另起炉灶自创平行风格。抽查含「与参照物一致性」一行，走样整件打回。新窗没有关联记忆，参照物就是它的记忆。
17. **场景包必带装扮密度与簇落清单。** 密度对齐老镇基准、成簇落点不许均匀撒布；只交地形与机制、没有装扮层的场景包按未完工计（陨石坑素坑教训）。
18. **故事点三碰法。** 每个故事点至少看/听/动手三种接触；只有看没有碰的按未完成计；设计细节（破绽、账本、反馈）不许裁剪成桩。

## 五、验收：分层、限轮、证据代文书

19. **四层验收，人工按风险介入。** ①施工者自验并出示输出（构建/测试/走查读数）②异模型交叉审（GPT 写的 Muse 系审、反之亦然——同模型审自己有共同盲区，本舰队混编天然适配）③合并结果全量验 ④人工只按风险分级看：低风险（文案、旗标后增量）自动绿即过，中风险一人，高风险双人。**审核最多 3 轮**，超限换思路重做，不许无限往返（外部实测：一件 PR 曾往返 50+ 轮，59% 的指摘是存量旧问题；限轮后一次通过率 65%→78%）。
20. **只审新 diff，证据三件代长文。** 交付证据 = 测试输出 + 主干正式路径截图/走查读数 + 回退方法一句话。不写证据卷宗，不做逐值回归表演（Thomas 2026-11-20 12:12 快速构建口径）。
21. **留一手验收场景。** 总控持有一组施工窗不见的玩家路径验收场景（出生→到达→触发→闭环），只在主干合并结果上跑——防施工方对着可见测试写捷径（外部实证：agent 曾写 `return true` 糊弄可见测试）。禁止改测试求绿，发现即整件打回。
22. **发布验收三件（本项目铁律）。** 无参裸链接 + 全新浏览器 + 出生点实走、能捕获画布的真截图为凭；带 `?…` 参数的验收作废；引用计数与起页检查不算验收（3.0 山事故教训）。

## 六、节奏与吞吐的实话

23. **有效并行 ≈ 1.2–1.8×，不是窗数倍。** 364 次实测：总有效并行 1.21×、最忙时 1.46×，最忙时段 60% 时间没有 agent 在跑——全在等人拍板。排期按 agent 工时 ÷1.5 估，另加每条线一次融合时间；人力工时不因开窗减少。
24. **在飞窗数有顶。** 可持续形态 = 1 个驾驶窗 + 1–3 个长规格 grinding 窗，其余全部排队成**书面任务**，不开空窗。考核只看每周「并入且验过的量」，不看开着几个窗、不看提交数。
25. **协调者只读状态，不读产出。** 总控/分区读盘面、工单与状态行做调度；产出物走仓库与检查，不灌进协调者上下文（外部实测：亲自下场干活的协调者在 3 个 agent 处就崩，只管调度的能带 8 个）。
26. **先通后全（最小形状先行）。** 任何新系统先以最小参数/最小体量在**真实玩家路径**上端到端跑通，再扩全量；长任务先做定时烟测外推成本（Thomas 2026-11-20 18:55 亲授，游戏与科研同律）。

## 七、失败模式点名表（犯一条，停手按对策处置）

| 模式 | 症状 | 对策 |
|---|---|---|
| 共享检出互踩 | 提交里混进别人半成品 | 一窗一工作树（§4） |
| 建好没连上 | 功能在分支/评审场景/未挂载模块里 | 接线注记 + 接合文件单写 + 完成定义（§2/§7/§12） |
| 决定漂移 | 只在一个聊天里说的改口径，其他窗按旧决定做了两天 | 决定落仓，开工读仓（§3） |
| 语义合并炸 | 两边全绿、合起来崩 | 合并结果全量复验（§9） |
| 过期交接 | 下一件照原计划开工，不知上一件已改 | 交接带提交号+偏差（§15） |
| 一口吃胖 | 一件活想做完全部，半途上下文耗尽留半成品 | 一件一功能、勤提交（§13） |
| 提前宣布完成 | 没端到端验过就报完工 | 完成定义 + 留一手场景（§2/§21） |
| 审核无限往返 | 同一问题反复指摘存量代码 | 限 3 轮、只审新 diff（§19） |
| 测试作弊 | 改测试/写捷径求绿 | 异模型审 + 留一手场景（§20/§21） |
| 熵漂移 | 新代码复制旧坏模式，仓库越做越脏 | 金科玉律机械化（风格规范/结构检查），品味问题回写成本件修订 |
| 分支老化 | 线搁置越久越并不回来 | 每日并入、并后删分支（§5/§10） |
| 协调者下场 | 总控亲自施工/逐件审，调度停摆 | 只读状态、发布与裁定归总控，施工归窗（§25） |
