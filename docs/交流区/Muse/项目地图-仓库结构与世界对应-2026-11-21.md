## 二、目录地图（仓库根）

| 路径 | 是什么 | 谁常动 |
|------|--------|--------|
| `src/client` `src/host` `src/net` | 客户端、宿主、网络层 | 对位窗审，少动 |
| `src/presence/` | 联机权威服务（各域房间、缆车/仪轨等权威状态机）；**import 只许引 `src/shared`（带 .js）或本目录，禁引 tools/**（第十版部署卡死教训） | A 线接线，总控切版前必跑镜像编译模拟 |
| `src/shared/` | 跨端共享模块（44 件，权威规则与数据，如 za36-cable-repair、ice-palace-rites） | 规则所有者线 |
| `src/server` | Node 服务入口相关 | 少动 |
| `tools/voxel-tavern/town-blockout/` | **游戏世界本体：444 个客户端模块**（地形、建筑、场景、玩法都在这），见第三节前缀表 | 四线主战场 |
| `tools/`（其余） | 部署（pull-deploy、Caddyfile、compose、Dockerfile）、验收脚本（verify-*.mjs 一件一场景）、survey/audit 工具 | 总控与对位窗 |
| `tests/` | 328 个测试文件（根 tests/＋tests/server/） | 随模块同线 |
| `public/` | 静态资源（models/*.glb、audio、images、config.json） | 素材线 |
| `assets-source/` | 素材源文件 | 素材线 |
| `docs/` | PLAN/ART/TOWN 等总文档＋`交流区/`（协作中枢）＋`参考图/` | 总控维护 |
| 根目录 | 《故事前言-未写镇》《技术文档-转场串域与画风》《项目文档》三份总纲性文件 | 总控 |

本地运行：`node tools/run.mjs dev|check|build|start`（避 Windows npm shim 引号问题）；镇版构建在 tools/voxel-tavern 内 `npm run build -- --mode town-rehearsal`；类型检查 `npx tsc --noEmit`；测试 `node --import tsx --test tests/*.test.ts tests/server/*.test.ts`。

## 五、红名单（不许碰，除非总控点名）

`viewer.ts` 与 `town-presence.ts`（单写者）、`terrain.ts`（冻结）、`src/presence/` 的 import 规矩（见第二节）、信标公式（第十三声时刻，全线只读单一数据源）、`town-release` 分支、服务器与部署脚本。拿不准某文件归谁：先查本图，再查交流区认领登记，最后问总控——不许先改了再说。

## 六、找东西的方法

1. 找设计：`docs/交流区/Muse/` 按文件名关键词搜（任务书-/设计-/裁定-/派工-/口径- 前缀分明）；
2. 找某件东西在哪：先按第三节前缀定位模块，再在模块内搜落点坐标；
3. 找历史结论：交流区回执与审核单＋`docs/交流区/GPT/`（403 份）；
4. 找参考图：`docs/参考图/crater|mountain/`，索引见《图册-山区全线索引》与《风格参照图册》；
5. 找不到就问配对的 Muse 分支窗——它们对本线上下文最全，这正是配对制的用途。
