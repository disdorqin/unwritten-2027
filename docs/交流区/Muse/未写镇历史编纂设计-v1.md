# 未写镇历史编纂设计 v1 ·《未写镇志》

提出：Thomas，2026-11-18 14:32（"给咱们未写镇搞一个历史编纂"）。设计：Muse。
定位：给小镇修一部**活着的镇史**——官修底本（建镇来历、编年、人物、风物）先行立起，玩家史（镇民录）随游玩自动生长，跨年夜添新篇成为仪式的固定环节。镇名「未写」本就是史观：**这镇子的历史不预先写死，是住进来的人一天天写出来的**；羊年地支又是「未」——未写、未年、未羊，三未同字，镇志的卷首语就从这里起。

**事实纪律（全稿红线）**：涉及镇长张乐天本人，只许用《NPC事实库-张乐天-v1》安全集口径——姓名张乐天、AI 工程师、做电力/时间序列预测研究、正为保研发论文、新加坡华人、过日子省（只用免费资源）、这座镇子是他张罗了请朋友跨年的（F15/F16/F19 拼句口径）。镇志里他的身份只作**镇内叙事**（镇长/建镇人）呈现，**不写真实生平、不写联系方式、不推断性格与私事**；NPC 小传全部来自既有人设文件，不新编往事；开发侧事实入史必须经 §4 的转译口径，不把 SHA、部署、服务器这类词原样写进镇内正文（转译对照只留在编纂工作注里）。

## 1. 编纂体例：《未写镇志》五卷

### 1.1 纪年法

镇内纪年不用公元干支硬套，用**两段纪**：

| 段 | 起讫 | 含义 |
| --- | --- | --- |
| **建镇纪** | 2026-11-16 立镇之议起，至 2026-12-30 | 从无到有的筹建与测试期；镇内叙事称这一段为「试灯的日子」 |
| **开镇纪** | 2026-12-31 20:00 开镇起 | 正式开镇后的日子，按年续编：开镇纪元年（2027）、二年…… |

编年条目双标日期：`开镇纪元年 · 2027-01-01` 式——镇内纪年在前、真实日期在后，两边都查得到。建镇纪条目同理（`建镇纪 · 2026-11-18`）。

### 1.2 卷目结构与撰写责任

| 卷 | 内容 | 来源与责任 |
| --- | --- | --- |
| **卷一 · 建镇记** | 从无到有的来历，镇内叙事化散文：镇长为何建镇、镇名「未写」的由来、雪原上先有了路还是先有了灯、六站通车与集市开张的先后（按编年事实序写成故事） | **Muse 供稿**（内容线撰写，事实只取已确证里程碑与安全集）；一次成稿，后续大修才动 |
| **卷二 · 编年** | 大事记，逐条：立镇、镇基落成、试灯、联机三轮、通车、开市、宫殿落成、温泉扩建、首个跨年夜、迎未（除夕）……每条 = 日期 + 题名 + 正文 2–5 句 + 来源标（官记/自动登记/镇民投稿） | **Muse 供稿打底**（首批见 §4）+ **系统自动登记**新条目（§3）+ 镇民投稿经审入录；三路同卷、来源必标 |
| **卷三 · 人物志** | NPC 逐人小传（15 人 + 预留 2 人）：罗大江（酒馆老板）、苏小满（邮局邮差）、顾长明（灯塔看守）、乔麦（灯坊匠人）、柳三弦（舞台班主）、钟铁生（火车站站长）、钱满仓（集市东家）、丁小豆（跑堂小二）、陶二娘（糖葫芦摊主）、贾明灯（灯笼摊主）、文墨生（春联年画摊主）、胡六环（套圈摊主）、纪守信（信箱管理员兼编纂官）、翁寒江（冰钓老手）、樊樵（守林人）；预留：汤守（温泉，人设待温泉专稿）、宫殿礼仪官。外加**镇长篇**（安全集拼句，见红线）与**小未篇**（吉祥物：来历只写镇内叙事——羊年将至，镇口来了一只挂金铃铛的小羊） | **Muse 供稿**，逐人从既有人设/台词文件提炼（驻地、职能、口头禅、与镇子的关系），不新编往事；预留二人待人设落定后补传 |
| **卷四 · 风物志** | 各区风物：中心广场、集市、冰湖、森林木屋区、冰雪城堡、温泉、火车站与六站、灯塔、酒馆、邮局、纪念馆新区、屋舍（相遇之屋）——每区一篇：方位、看点、玩法、掌故（掌故只许引用编年已录之事） | **Muse 供稿**（素材取各区既有设计稿与实装）；新区落成后补篇 |
| **卷五 · 镇民录** | **玩家史，活史主场**：首批镇民名册（测试期进过镇的人，按首次进镇序）、历任冰雪之主（登临/退位逐任登记）、历任领头羊（集齐生肖结算序）、测试期大事（首次满员烟花之夜、首场雪仗混战的胜者……）、跨年夜在场名册（2026-12-31 当晚在镇者） | **系统自动生成为主**（§3 事件钩子）；镇民可为自己补一句「镇民自述」（经审入录，见 §3.3）；Muse 只定体例不代笔 |

体例要点：卷一至卷四是「官修底本」，随版本发布更新（静态数据，跟版走）；卷五与卷二的新条目是「活史」，靠 §3 的机制在运行时生长——**底本保证镇子一开张就有史可读，活史保证这部史不会停在开张那天**。

## 2. 载体与呈现：一份数据，三种呈现

### 2.1 数据同源（先定数据，后定皮）

全镇史共用一份结构化数据 `townChronicle`，三种呈现（展陈/书册/碑）都只是它的视图，**不许各维护一份文案**。条目记录结构（与《时光信箱细化-v1》§4 共用文本存储层同形，多人迁移路径一致：本地 localStorage → 服务端记录、actor 换真实玩家 id）：

```jsonc
{
  "id": "chr-0007",              // 全局序号，入录即定，不复用
  "vol": 2,                      // 卷：1 建镇记 2 编年 3 人物 4 风物 5 镇民录
  "era": "建镇纪",               // 建镇纪 | 开镇纪元年 | 开镇纪二年 …
  "date": "2026-11-18",          // 真实日期（编年检索用）；人物/风物条目可为 null
  "title": "雪仗开场 · 烟花备好",
  "body": "……",                 // 正文；编年 2–5 句，人物/风物为整篇
  "source": "auto",              // official 官记 | auto 自动登记 | player 镇民投稿
  "actor": null,                 // 关联玩家/NPC id（镇民录与自动条目用）
  "status": "published",         // draft 草稿（待审） | published 已入录
  "pinned": false                // 碑面精选标（编纂官选，见 §2.4）
}
```

存储分工（诚实分期，见 §5）：底本数据（卷一–四 + 卷二首批）= 客户端内置 JSON，随版本发布；活史数据（卷五 + 卷二新条目）v1 先落本地（个人视角的镇民录：自己的里程碑全准、全镇名册以本机所见为准并标注），**全镇一致的活史要等服务端加一个 append-only 编年存储**（presence 服务端现为无状态中继，这是本设计唯一真实的服务端依赖，列入 §5 活史批，不假装现成）。

### 2.2 呈现一：博物馆/纪念馆镇史展陈（实景）

- **落位**：博物馆（纪念馆）**1F 大厅设「镇史廊」**——沿墙展板组（建镇记缩编 + 编年精选滚动页）+ 大厅中央展柜放《镇志》实体书模型（与书册界面同封面，点击即开 §2.3 书册）。纪念馆新区展示柜区补一格「镇民录荣誉柜」：与生肖集齐结算柜（领头羊名牌）同排，陈列历任冰雪之主/领头羊名牌——荣誉的实物落点就在纪守信当值的纪念馆。
- **与 T1 精修的合并施工口径**：博物馆在 T1 序列里是**批二**，且 2F 是全镇唯一双超标（309 calls / 153.9 万 tris）、增量空间为负——故镇史展陈**只进 1F**（1F 基线 134 calls / 98.2 万，有余量），且必须等博物馆 T1 的**标签图集化还账**同批施工：展板一律走既定标签图集机制（展签图集化 −40~−70 calls 的同一套活），**禁止逐板独立 Mesh、禁止一物一纹理**，并入 1F 既有材质批次；展柜书模并入展柜批次。增量申报口径沿 T1 §预算表：还账达标后解锁的额度内列支（预估 +2~3 calls / +0.5 万 tris 级，以施工实测对账为准）。**不许抢占还账额度先行摆件**——顺序写死：先图集化、后镇史廊。
- 展板内容 = 数据的 `pinned` 精选 + 卷一缩编，换展 = 改数据标，不动几何。

### 2.3 呈现二：《镇志》书册界面（随身，DOM）

- **入口三处**：展柜书模（馆内）、护照界面加一个「镇志」页签（护照是个人册、镇志是全镇册，同为册子形态，入口并列不合并数据）、纪守信对话选项「看看镇志」。
- **形态**：DOM 全屏册页——左目录（五卷卷目 + 卷二按纪年分段）、右正文；支持**翻页**（卷内条目序）、**卷目跳转**、**检索**（按题名/正文关键词 + 按日期查编年，纯前端过滤内置+本地数据，零后端）。镇民录卷打开时顶部一行小字注明数据口径（本机所见 / 全镇同步，随 §5 分期切换文案）。
- **成本**：纯 DOM + 文本，零 GL、零新增绘制；数据体积全本预估 <200 KB 文本，懒加载分卷。
- 与护照的关系：护照记「我」（印章、称号、收集），镇志记「镇」；卷五镇民录里查到自己时，可一键跳护照对应称号页——互引不互吞。

### 2.4 呈现三：大事记碑（精简版）

- **主碑**：纪念馆前庭立「未写镇大事记碑」（纪守信驻地旁）——碑面只刻 `pinned` 精选 + **最新 3 条**编年（题名 + 日期一行式），点击开书册直达该条。碑体几何并入纪念馆新区既有批次（石碑 + 碑座 + 顶部小灯，个位数盒量级）。
- **镜像碑**：火车站站厅（未写镇站）站牌区立精简镜像——只显示最新 3 条。叙事理由：**乘火车进镇的人，下车第一眼先看见这镇子最新的一页史**，再抬头看时刻牌去赶车。内容与主碑同源同标（`pinned`/最新），不另编辑。
- 碑面更新 = 数据更新，碑体不动；仪式夜碑顶小灯并入仪式灯光口径，不新开光源。

## 3. 活史机制：新条目如何产生

### 3.1 里程碑自动登记（系统事件 → 条目草稿）

下列事件已有或将有系统钩子，触发即生成条目（事实型直接入录，叙事型落草稿待确认，见 §3.4）：

| 事件 | 钩子来源 | 入卷 | 形态 |
| --- | --- | --- | --- |
| 冰雪之主登临 / 退位 | 宫殿王座 announce 通道（已有广播） | 卷五·历任冰雪之主 + 卷二各一条 | 事实型，自动入录 |
| 集齐生肖 ·「领头羊」诞生 | 纪念馆展示柜结算点 | 卷五·历任领头羊 + 卷二 | 事实型，自动入录 |
| 测试服烟花首次触发（≥5 人在线满 15 分钟） | 测试服烟花触发器（已上线） | 卷二 + 卷五·测试期大事 | 事实型，自动入录，条目注明在场人数 |
| 在线人数新高 | presence 服务端计数 | 卷二（仅破纪录时） | 事实型，自动入录 |
| 首位镇民进镇 / 每位镇民首次进镇 | presence join | 卷五·镇民名册 | 事实型，自动入录（名册追加） |
| 跨年夜仪式完成（cue 表跑至 T+30 s） | 仪式编排模块（onCue 单一出口） | 卷二·「首个跨年夜」整篇 | **叙事型，生成草稿**，走 §3.5 添新篇 |
| 时光信箱开箱（2026-12-31 20:00） | 信箱 UNLOCK_AT | 卷二 | 事实型，自动入录（封存总数入史，不记内容） |
| 火车新站开通 / 集市新摊开张 / 新区落成 | 建设批次上线事件（无现成钩子者由编纂官手动登记，见 §3.2） | 卷二 + 卷四补篇 | 手动登记 |

原则：**自动登记只记系统确知的事**（谁、何时、做了什么，全是事件自带字段），不生成评价、不替玩家抒情；抒情的部分留给人写（官记与投稿）。

### 3.2 编纂官登记（人工补录）

建设里程碑、镇内趣事等无钩子事件，由编纂官在编纂面板（§3.4）手动成条：题名 + 正文 + 日期，来源标 `official`。这是把「通车、开市、宫殿落成」这类开发批次转译入史的正式通道——**每批大建设上线，编纂官补一条编年，是交付清单的一项**（写进各建设批次的验收口径）。

### 3.3 镇民共创（投稿入录）

- **投稿口**：邮局（苏小满处）与新区信箱（纪守信处）各设「镇志投稿」——复用时光信箱的文本存储与校验形态（长度上限、控制符剥离，沿 P2b 聊天同口径；朋友服不设词表过滤，沿既定裁定）。可投：镇民自述（入卷五本人名下）、见闻投稿（入卷二候选）、风物补充（入卷四候选）。
- **审核**：投稿一律 `draft`，经**编纂官初审 + 镇长终审**（v1 本地期：投稿先存本地、随镇长巡查时审；服务端期：进审核队列，镇长面板一键过/驳，驳回不通知理由外的内容、原文仅投稿者与审核者可见）。**未经审的投稿不出现在任何呈现端**——碑、展、书三端只读 `published`。
- **防滥用**：投稿频率沿聊天限速口径；一人同时待审 ≤3 条；条目一经入录不可被其他镇民编辑（本人可申请更正，走新投稿）；名册类自动条目不接受投稿改写（防冒名顶替——名字以 presence join 记录为准）。

### 3.4 编纂官裁定：纪守信兼任

**裁定：编纂官由纪守信兼任，不新设 NPC。** 理由四条：①**人设现成**——他本就是「一板一眼，凡事讲登记、讲次序」的登记员，台词里天天经手「一封一封登记在册」，编纂就是把登记的对象从信换成事；②**驻地现成**——他当值纪念馆新区，紧邻博物馆镇史廊与荣誉柜，展陈、名册、编纂三件事在同一片区闭环；③**职能同源**——信箱管理员管「写给未来的信」，编纂官管「写给后来的史」，在他的人设里是一件事的两面（他讲解时光信箱的台词口径可直接延伸）；④**省一条内容债**——新设编纂官要新写人设+台词+驻位，已有 15 人名册里正好有最合适的人，不另起炉灶。分工：纪守信**主编**（讲解、初审、手动登记、碑面精选），苏小满**协办收件**（邮局投稿口），镇长**终审**（服主权限面板加「镇志终审」一项，与吉祥物稿 M2 权限同批，接口在此预留）。纪守信新增台词（编纂讲解/投稿引导/添新篇主持词）由 Muse 内容线补一小包（约 15 句级），列入内容债清单，不阻塞本设计施工。

### 3.5 跨年夜添新篇（仪式固定环节）

- **位置**：仪式 cue 表 T+30 s 正式段落结束、转入余韵（篝火庆典/舞台安可）后，在**广场篝火主锚点**举行一个短环节「镇志添篇」：纪守信到场（NPC 仪式调度，与苏小满 20:00 开箱主持同机制），宣读今夜自动成稿的「首个跨年夜」条目题名，镇长（或在场镇民共同见证）确认，条目由 `draft` 转 `published`，书册卷二新增一页并在目录亮起新篇标；广场公告板「今晚」格同刻换成「镇志已添新篇 · 首个跨年夜」一行（公告板既有数据格，文案切换即可）。
- **与 cue 表的接口**：不改既有 cue 序，只在余韵段**新增一条建议 cue**：`T+300 s · 镇志添篇`（篝火点 cue：篝火光强微扬 + 编纂官到场 + 添篇广播走 announce 通道）——编排层经既有 `onCue` 单一出口发 `ceremony:chapter-sealed` 事件，镇志模块订阅处理（成条、转正、刷新三端）。单人版等价：同一 cue、本地时钟源（与仪式稿 CeremonyClock 口径一致）。彩排可由服主 `owner/ceremony` 手动触发（吉祥物稿 §3.3 g 既有通道，加 `chapter` 动作即可）。
- **此后每逢大节复用**：迎未（除夕）、元宵等后续节日夜，添新篇照此例行——仪式给镇史一个固定的落笔时刻，镇史给仪式一个跨年的回声。

## 4. 首批入史清单（已发生事实，只许确证）

首批 = **实录 6 条 + 预置 2 条**。开发侧事实转镇内叙事的转译口径先立规矩，再给示范：

**转译三则**：①器物转译——服务器→「镇基」，域名/DNS→「门牌」，端口/HTTPS→「港灯/镇门」，上线→「点灯/开镇」，测试→「试灯」；②人名口径——镇内正文只称「镇长」，叙事需要点名时用「镇长张乐天」（安全集内），不写账号、域名注册人等开发信息；③数字口径——人数、间数、站数等可公开的镇内数字照写（52 栋老屋、六站、88 扇门通一屋——均为镇内可见事实），SHA、IP、部署细节一律不入正文，只留编纂工作注。

## 5. 成本与施工拆分

### 5.1 成本账

| 项 | 成本 | 口径 |
| --- | --- | --- |
| 底本数据（五卷首批文本） | Muse 撰稿工时，无运行时成本 | 内置 JSON <200 KB，分卷懒加载 |
| 书册界面 | DOM 一套（目录/翻页/检索），零 GL | 复用护照/面板 DOM 形态，不新开渲染路径 |
| 镇史廊展板 + 展柜书模 | 预估 +2~3 calls / +0.5 万 tris（实测对账） | 只进博物馆 1F；走标签图集 + 既有批次；**等图集化还账同批**，不抢额度 |
| 大事记碑 ×2（前庭主碑 + 站厅镜像） | 个位数盒，并入所在区既有批次，+0 calls | 碑顶小灯并入既有灯光口径，不新增光源 |
| 活史 v1（本地） | 客户端事件订阅 + 本地存储一份 | 复用时光信箱共用文本层，不新起存储 |
| 活史 v2（全镇一致） | **服务端唯一真实增量**：presence 加 append-only 编年存储（小 JSON 落盘 + 事件钩子写入 + 审核队列字段） | 独立小批，排在 P2b 事件层稳定后；不动机位同步与状态记录 |

### 5.2 施工拆分（四批）

1. **内容批（Muse，先行）**：卷一建镇记成稿、卷三 15 人小传、卷四各区风物、卷二首批 6 条正文（§4 已给 4 条示范，其余照例补齐）、纪守信编纂台词小包。交付 = 底本 JSON 数据文件 + 文案稿，GPT 只装配不撰写。
2. **呈现批（GPT，可与内容批并行）**：书册界面（目录/翻页/检索）+ 大事记碑两处 + 护照页签入口——用占位数据先行，内容批数据到后直接灌入（同源结构已在 §2.1 定死）。
3. **展陈批（GPT，随博物馆 T1 批二合并）**：镇史廊（图集化还账之后）+ 荣誉柜格。**不单独开批**，并入博物馆 T1 施工单，验收随 T1 一栋一验走。
4. **活史批（分两步）**：v1 本地钩子（冰雪之主/领头羊/人数新高/名册在本机的登记 + 添新篇 cue 接口）随宫殿与仪式批次搭车；v2 服务端编年存储 + 投稿审核队列 + 镇长终审面板，单独立项，排在吉祥物 M2 权限批之后（共用服主验证通道，不重复造轮子）。

### 5.3 验收口径

- **条目可查**：书册检索以「烟花」「纪守信」「2026-11-18」三词实测，各命中应命中的条目；碑面最新 3 条与数据最新 3 条一致（改一条数据，碑、展、书三端同变——同源实测）。
- **书册可翻**：五卷目录跳转、卷内翻页到底有界、人物志点名直达小传、镇民录查到自己并可跳护照称号页。
- **自动登记实测**：测试环境触发一次冰雪之主登临 → 卷五与卷二各生成一条且字段正确（人名/时间取事件本身）；触发一次测试服烟花 → 卷二条目注明在场人数；未审投稿在三端均不可见（防滥用实测）。
- **添新篇彩排**：服主手动触发 `chapter` 彩排 → cue 到点、纪守信到场、草稿转正、公告板文案切换，四项全中方算通过；正式夜走真序时同项复核。
- **事实纪律抽查**：镇长篇与建镇记逐句比对事实库安全集，出现库外生平/联系方式/推断性格即整批退回内容线重写。
