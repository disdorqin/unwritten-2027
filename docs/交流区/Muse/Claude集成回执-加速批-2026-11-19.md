# Claude集成回执 · 加速批（画质三档 / 雪橇×雪墙 / 连接日志）（2026-11-19）

基线：集成 `c8f28ca` / 线上 `37e26ee`。三条车道在独立副本施工，Muse 逐线集成进主树（server.ts、viewer.ts、town-snowfight.ts 三方合并均无冲突），集成后全套复验见文末。

## 一、M5 画质三档 + M2/M4（车道 A）

- 新模块 `town-quality.ts`：流畅（分辨率上限 1.0 / 粒子 0.5）、**均衡（默认，1.5 / 1.0，与改前逐项等值、单测锁定）**、精美（2.0 / 1.25）；存储键 `unwritten.quality.tier.v1`；设置面板灵敏度滑杆后加画质选择，切档即时生效。
- 粒子缩放落点：降雪、落雪环、雪仗雪雾团、雪橇雪雾；**烟花不缩放**（种子确定谱面属内容、非环境粒子）。
- M2：触屏顶部面板 6 秒无操作淡化至 0.45，触摸/聚焦恢复；次要文本在 coarse 下隐藏。桌面零变化。
- M4：竖屏 + coarse 布局段——面板/聊天让出右侧按钮列，摇杆与按钮簇不重叠，纯布局无新美术。

## 二、雪橇×雪墙 + 触屏雪橇跳（车道 B）

- 协议新增 kind 7 `SLED_SMASH`（8 B 帧，避开 12 B；codec 测断言 12 B 伪帧被拒）。服务端四闸裁定：报告速度 ∈(6,20]、列高恰为 1、报告者距格心 ≤6 m、通过后 damage×3 销毁并复用 `WALL_CLEAR` 广播（双端一次收敛，本地不预毁）。客户端仅对「一层墙 + 速度 >6 + 橇体低于墙顶」放行，厚墙/低速走既有撞毁规则。
- 触屏：`requestJumpAction()` 乘橇时与键盘 Space 走同一条 `sledRide.jump(3.2)` 路径；disabled 态乘橇时以 `airborne()` 为准。
- **顺带修复既有缺口（补记 D1 条目）**：poll 通道此前不分 kind 全送雪球解码，snowfight 的 place/wall-hit 在备用通道上不可用——现已与 WS 同口径分发。
- 信任模型明示：撞穿速度为骑乘端自述，与 WALL_HIT 同级；拆墙不得分，风险接受。

## 三、S2 服务端连接日志（车道 C）

- `server.ts` 新增可注入 `connectionLog` 出口（默认 console.log，日志异常不伤服务）。每条一行 JSON，字段白名单恰 5 个：ts / transport（ws|poll）/ peer / step（attempt/session/join/drop）/ result，与客户端故障码 PG-1/WS-2/FR-3/HB-4 对位。
- **不记昵称、聊天文本、IP、会话令牌**——测试逐行断言键集合与哨兵字符串不落日志。drop 原因码经 `Peer.dropReason` 区分（leave/protocol-error/heartbeat-timeout/poll-timeout 等）。

## 四、集成复验

- 根测试 289/289（282 基线 + 画质 6 + 撞穿 codec 1）、服务端 54/54（48 + 连接日志 5 + 撞穿双端 1）、tsc 通过、build 成功。三方合并文件：server.ts（S2 日志 × 撞穿裁定）、viewer.ts（画质接线 × 撞穿/雪橇跳）、town-snowfight.ts（粒子密度 × wallColumnAt），均一次合入无冲突。
